# Partura 的工作方式:每条表达式都是一次新的研究

写在最前面,因为这是最容易做错的一件事:

> **不要把上一条因子的配置改个表达式就跑。**
> 实验计划是**从这棵树推出来的**,不是模板。探针集合也是。
> 唯一跨研究复用的东西是**结论**(`lab/findings.yaml`),而且它是先验,不是证据。

---

## 1. 为什么计划不能复用

F001 是「日内折叠 → 日轴极值 → 逐元素乘 → 日轴极值」。它需要的问题是:
这个量带不带尺度?取极值是在记事件还是在取幅度?乘法是门控还是两个信号?

F002 是「日内折叠 ×2 → **跨日成对协方差** → 日轴顺序统计量」。这棵树里
没有逐元素乘法,所以"门控"这个问题根本不存在;但它多了一个**成对**算子,
于是冒出两个 F001 从来不需要问的问题:

- 两个操作数是**对称**的吗?(如果是,"High 解释波动"这种读法就不被表达式支持)
- 它配的是**同期**还是**跨期**?

第二个问题在内置探针里没有答案,只能为这次研究写一个。写出来之后测到的东西是:

| | 操作数对称 | 脉冲交互随滞后 L 的衰减(相对 L=0) |
|---|---|---|
| `cross_cov(x, y, 15)` | 是 | L≠0 一律 **0.0714 = 1/(15−1)** |
| `cross_corr(x, y, 15)` | 是 | L≠0 是 **0.41~0.64** |

`cross_cov` 在 L≠0 上的那点响应**不是跨期配对**,而是窗口均值被脉冲推动造成的泄漏,
大小恰好等于 1/(d−1) —— 解析上可以核对。而 `cross_corr` 因为要除以两个方差,
窗口里任何一天的极端值都会重塑整个统计量,**离期污染大了 6~9 倍**。
"把 cov 换成 corr 来去尺度"这个在 F001 里天经地义的动作,在这棵树上是有代价的,
而这件事只有靠一个为这棵树写的探针才看得见。

**这就是不能复用的原因**:同一个动作在不同的树上含义不同。

## 2. 一次研究的流程

```
partura decompose <expr> [--probes studies/<fid>/probes.py]
        → 算子档案(声明 + 源码 + 探针实测)、SSA 分解、实验室里的既往先验
        ↓  人(agent)读这棵树,决定还要问什么
        ↓  需要新问题 → 写 studies/<fid>/probes.py,重跑 decompose
partura propose <expr> --factor-id <fid> --out configs/<fid>.draft.yaml
        → 从树结构 + 探针签名生成**候选**实验(isolate/ablate/substitute/window/field/…)
        ↓  人删掉没信息量的、补上只有读了这棵树才想得到的、把每条 why 写成可证伪的话
        ↓  控制变量、门控变量、诊断项也在这一步按这棵树的嫌疑来挑
partura run <config> --stages ...        # 训练段 + 验证段,一个阶段回答一个问题
        ↓  读结果 → 更新假设 → 只在需要时加下一个阶段
partura run <config> --stages S_final --holdout    # 留出段只读一次
partura report <config>                  # 生成段(表) + 手写段(notes/)
        ↓  把可迁移的结论写回 lab/findings.yaml
```

### `propose` 在做什么(以及它不做什么)

它从树结构和**实测的探针签名**派生候选:

- `isolate` / `ablate` —— 每个节点单独跑 / 删掉。
- `substitute` —— 从注册表里挑**与当前算子只差一条实测性质**的兄弟。
  `cross_max → cross_med`(只差 `monotone_in_window`)、
  `cross_cov → cross_corr`(只差 `homogeneity_degree`)。
  这一步不可能预先写死:候选是**当场探针跑出来的**,换一棵树就换一批。
- `window` —— 每个滚动节点的邻域窗口(取自注册表自己的窗口池)。
- `field` —— 同类字段互换。
- `magnitude` / `interaction` —— **只在探针说相关时才出现**:操作数带符号且父节点是极值
  才提 `abs_` 检验;有逐元素二元节点才提"只留左支/只留右支/换成加法/先排名再相乘"。

它**不决定**什么重要。输出是一份草稿,`question` 和 `why` 都是空壳,等人填。
一份没被删改过的 `propose` 输出直接拿去跑,就是又一次盲搜。

## 3. 探针的写法

探针回答**一个**问题,声明自己对哪些算子适用,不适用就明说,跑不动就报错 —— 不猜。

```python
@probe("effective_quantile",
       question="喂一段已知斜坡,输出落在第几分位?",
       applies=lambda s: s.requires_window and s.arity == 1 and s.compute_axis == "D")
def _q(ctx):
    ...
```

`ctx` 给的是内核本身、统一的调用方式(`ctx.call`)、统一的随机样本(`ctx.sample`)
和统一的比较口径(`ctx.close` 数值、`ctx.spearman` 序)。
内置探针只覆盖最普遍的问题(因果性、分钟顺序、平移、齐次度、保序、缺失、取负、窗口单调、脉冲记忆);
**本研究特有的问题写在 `studies/<factor_id>/probes.py`**,报告里会单独标成"本研究新增的探针"。

自检是好探针的标志:`effective_quantile` 在 `ts_quantile_q75` 上应该读出 0.75、
在 `cross_max` 上读出 1.0 —— 两个都对上了,这个探针才可以用来读别的算子。

探针写错了就改:`cross_lag_response` 第一版返回"这些滞后上都有响应",
看上去像跨期配对,其实是均值泄漏;第二版改成报**衰减剖面**,才看得出 1/(d−1) 这个结构。
改探针和改实验一样,是研究的一部分,不是返工。

## 4. 什么才可以跨研究复用

只有 `lab/findings.yaml`:每条结论带**证据**、**出处研究**、**置信**,以及
**什么情况下会失效**。`partura lab <expr>` 会把与这棵树相关的先验拉出来,
报告第 2 节末尾也会印一遍,并写明:

> 这些是既往研究的先验,不是本研究的结论。本报告如果依赖其中任何一条,必须在本研究里重新测一次。

反例就在 F001 的记录里:`day_durbin_watson` 作用在**价格水平**上 ≈ 日内已实现方差,
但喂给它**收益序列**时是分钟收益一阶自相关 —— 方向都反。
同一个算子,操作数一换,先验就失效。所以每条 finding 都必须写清楚它的适用条件。

## 5. 硬规矩(与 F001 相同,不随表达式变)

- 方向只在训练段定一次,原样用到验证段与留出段。
- 所有和钱有关的数字都扣成本(15 bp 单边),同时给日换手。
- 留出段有台账;反复用它挑变体,它就变成了第二个验证集。
- 每个变体都要有 `why`,说明它想证伪哪个假设;不做"再试 100 个相近公式"。
- 原始结果不覆盖,面板按表达式内容寻址缓存。
