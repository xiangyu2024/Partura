# C05:主 AlphaCube 一直跑、不受打扰;Partura 从它的产出里定位好结构,派小 AlphaCube 去深挖、去烂部件、试新想法(事先约定)

## 1. 来由

C01、C02 判定「Partura 更差」,C03、C04 判定「分不出」。从这四次里能确定的:

1. Partura 凭先验写的机制几乎都不成立:C03、C04 的直接检验都是 0 过线(C04:64 个变体 0 个)。
2. Partura 的先验会伤到搜索:C04 里它的禁令(C4P1)禁掉的正是 A 组留到测试段的那一族;B 组的发现数 53 对 A 组 173。
   在同一个预算里「agent 指挥 GP」,agent 的错误直接挤掉了探索。
3. Partura 唯一留下的贡献是一个**特征构造**(C04 的 C2a:日收益按涨跌停幅度缩放),方向却是 GP 从数据里定的(和它写的相反)。
4. 主指标的融合允许「方向相反的孪生 head」(ρ ≈ −0.6)同时入选,融合时互相抵消(C04 RESULT §3)。

所以 C05 换一种分工:**主 AlphaCube(M)不受 agent 任何影响,一直跑,只按自己的历史做结构禁令和相关度禁令**,像一个随机 idea 生成器;
**Partura 从 M 的产出出发**(先定位哪些结构是 alpha 的来源,再查文献、再想),派**小 AlphaCube 任务**去实践:
- **E 深挖**:把一个好结构(核心)固定住,只在它外面长,并且要求外面的处理和以前见过的都不一样;
- **R 去烂部件**:把好因子里没用或有害的部件去掉或替换,看会不会更好;
- **N 新想法**:受这一批或文献启发的新 idea。

Partura 不给 M 下任何禁令,只能**加**东西;最坏的情况是浪费它那份算力。

**C05 的问题:同样的额外算力,交给 Partura 去定位—深挖(B 组),比交给更多的无 agent 搜索(A 组),能不能让最终因子库的样本外表现更好?**
另设 B0 组:同样的定位工具和任务类型,但由事先写死的规则代替 LLM 做选择、不查文献 —— 用来把「LLM 的判断」和「定位—深挖这套架构」分开(次比较)。

## 2. 设计

与 C04 相同的环境:数据与时段(train 2018-01-02 ~ 2021-12-31,valid ~ 2023-08-07,测试 2023-08-08 ~ 2025-12-31,前推 2026 只报);
奖励 `long_neutral`(控制:流动性、波动、20 日反转、已知族、`LogFloatCap`);与已知族 |ρ| ≥ 0.5 拒绝;禁 `ts_spearman` 与 `nt_*`;
6 个日频字段叶子(概率 0.2);发现门槛 score ≥ 0.5;单次运行内的 heads 规则不变(与已知族、池 |ρ| < 0.5,互相 |ρ| < 0.7)。

### 2.1 主 AlphaCube M(三组共用同一份)

- 种子 **801–808**(原服务器 801–804,新服务器 805–808)。每个种子 4 批(e = 1..4),每批是一次普通 GP:
  `I0_open_search`、control 臂、GP 随机数种子 10·s + e、预算 192、种群 48。
- 第 e 批的**自身历史禁令**(只看本种子 M 的第 1..e−1 批 heads,不看任何 Partura 产出):
  (i) 相关度禁令:与其中任一 head 的日度秩相关 |ρ| ≥ 0.7 的候选拒绝(AlphaCube 自己的 `RankSimilarityBan`,`ban_rank_corr = 0.7`);
  (ii) 结构禁令:算子树骨架(字段、常数、窗口都抽象掉;AlphaCube 的 `skeleton_key` 去掉窗口)与其中任一 head 相同的候选拒绝。
- M 的每一批都不读 Partura,所以 M 在三组里完全相同,只跑一次。

### 2.2 轮次与信息时间表

每个种子 3 轮(k = 1, 2, 3)。第 k 轮的快照 = **M 的第 1..k 批** + 本组前几轮任务的全部结果。第 k+1 轮在本组第 k 轮的任务全部跑完之后开始。
(真实部署里两边完全异步;实验里把「Partura 每轮看到 M 的几批」写死成 k,让三组看到的信息相同、结果可复现,不依赖哪边跑得快。)
M 的第 4 批只进最终因子库,不进任何一轮的快照。

### 2.3 每轮每组的额外算力:256 次候选评估

| 组 | 第 k 轮花在哪里 |
|---|---|
| **A** | 2 次普通 GP(control 臂、种群 32、各 128),GP 种子 1000·s + 10·k + j |
| **B0 / B** | 定位的消融 ≤ 48 次 + R 直接评估 ≤ 16 次 + 2 个 GP 任务位,各 96(种群 32);用不完的不挪用 |

三组的 GP 都带同一种**库禁令**:库 = 快照里 M 的 heads + 本组之前各轮额外产出的 heads(相关度 ≥ 0.7 拒绝 + 骨架相同拒绝,同 2.1)。

### 2.4 定位工具(B0、B 都用;确定性,只读 train + valid)

对本组快照:
- **heads 表**:全部 heads(来源、score、train / valid 夏普、半衰期、方向)。
- **共性**:快照里所有已评分候选(各次运行的存档)的子树(日频形状、≥ 2 个节点、不是整棵树),出现在 ≥ 4 个候选里、且不超过 70% 的,
  比较含它与不含它的候选的 score 均值差,附单侧 Mann–Whitney p。
- **拆解**:每轮取尚未拆过的 score 最高的 ≤ 4 个 head,每个 ≤ 12 个变体:子树单独当因子(充分性)、跳过一个算子(必要性)、
  字段换成同类(Close↔Vwap↔Open、High↔Low、Volume↔Amt)、窗口 ×½ / ×2(敏感性)。全部评 score、train / valid 夏普。
- **机械核心卡**:(1) 拆解里自身 score ≥ 0.5 且 ≥ 所在 head 的 60% 的子树,按自身 score 排;(2) 共性里均值差 > 0 且 p < 0.1 的子树,按均值差排。

### 2.5 任务

- **E 深挖**(一个 GP 位):给一个核心(必须是快照里某个 head 或存档候选的子树,能单独求值)。
  - 每个候选必须**原样包含**核心;核心之外的算子集合不得与快照里、本组之前任务里任何含该核心的候选相同。
  - 初代 32 个个体全是含核心的种子:B 是 Partura 写的 ≤ 16 个 + 机械嫁接补满;B0 全是机械嫁接。
    机械嫁接:AlphaCube 生成器出一棵随机树,把其中一个日频形状的非根子树换成核心。
  - 奖励在控制里**再加核心的家族**(快照里含该核心的 heads,按 score 取前 ≤ 6 个),只奖励新信息。
- **N 新想法**(一个 GP 位):B 是 Partura 写的 idea 与 ≤ 16 个种子(占初代至多一半),steer 臂只用种子;B0 是一次普通 GP(和 A 的一样)。
- **R 去烂部件**(≤ 16 次直接评估):对快照里的某个 head 给出去掉或替换部件的变体。
  变体 score ≥ 原 head + 0.1、与原 head 的交易信号 ρ ≥ 0.5、与已知族 |ρ| < 0.5 时,**在本组的库里替换原 head**。
  B0 的 R:拆解里比原 head 好的变体按改进量排,数量同 B。
- **约束**(B 必须遵守,B0 的规则自动满足):每个核心整个实验至多 2 个 E 位;3 轮里至少 1 个 N 位。
- **B0 跟随 B**:B0 第 k 轮的 E 位数、N 位数、R 数与 B 第 k 轮相同;选哪个核心按机械核心卡的顺序(跳过已用满的)。

分级团队:**结构解剖员**(Opus 5:读定位工具的输出,判断哪些子树是 alpha 的来源、哪些部件是烂的,给出文献检索题目)→

1. **实现细节(2026-10-28 20:40 美东;M 的第 1 批已开跑,还没有任何结果被读过)。** 都是 §2 没写到的地方,不改任何比较:
