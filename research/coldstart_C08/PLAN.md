# C08:新尺子下让 Partura 出点子;宽松审计员把关,严格审计员旁听打分(事先约定)

写于 2026-10-31,在 C08 的任何运行之前。提交之后不改;要改另写「修订」。

## 1. 来由

C01–C06 都让 Partura 出点子,但用的都是有漏洞的旧尺子:
- 先平滑原始值;
- 只做线性中性化。

它的点子里有一部分是靠漏洞拿分的。C07 修好了尺子,但只让 LLM 做验证,没让它出点子。所以 Partura 从来没有在修好的尺子下出过点子。

审计规则采用研究负责人定的原则:**只挡数学问题,以及明显度量同一个东西的;其余放行,并写出最可能的 alpha 来源。**
C06 那种严格标准(创新度、合理度 ≥ 3,要求说得清机制)只旁听打分,事后比较它会不会更好。

**C08 的问题:在修好的尺子下,同样的额外算力交给 Partura 派任务(P),因子库的样本外表现是否好过多跑普通 GP(A)?**

## 2. 设计

- **尺子**:与 C07 相同(`PARTURA_RANK_FIRST=1`、`PARTURA_NEUTRAL_POWERS=1,2,3`)。
- **复用 C07**:M 与 A 原样复用 C07 的运行;种子 801–808、尺子都相同。快照与信息时间表同 C05 / C06:第 k 轮看 M 的第 1..k 批。
- **P 组**:C06 的派任务设计(C06 PLAN §2.2–§2.5),只有以下三处不同。
  1. **尺子**:E 任务、R 评估、定位工具的交易信号都用新尺子。
  2. **第 1 轮不复用任何东西**:定位、解剖、文献都在新尺子下现算。
  3. **审计员按宽松原则**(`rules.md` §3–§4):
     - 创新度 1 = 与某个 head 或控制度量同一个东西,合理度 1 = 有数学问题,其余一律 ≥ 3;
     - 自动划掉的种子:与 head |ρ| ≥ 0.7,或与控制 |ρ| ≥ 0.8;
     - 通过条件、至多审 3 次、不过改普通 GP,都同 C06。
  - 其余与 C06 相同:
    - 每轮 2 个 GP 任务位,各 96 次评估;R ≤ 16 次直接评估;定位拆解 ≤ 48 次;
    - E / N / R 三类任务;三处修正(E 不加家族控制、R 收录、R 链走到末端);
    - 角色与模型:解剖员 Opus 5、文献员 Sonnet 5、PI Opus 5.5、审计员 Opus 5.5、检查 Haiku 5.5;
    - 隔离规则见 `rules.md` §5。
- **旁听的严格审计员**(Opus 5.5,`rules_strict.md`):每个种子每轮在计划定稿后打一次分(共 24 次),写 `shadow.yaml`。它不拦截、不触发重写。

## 3. 判读

- **库**:
  - M = C07 的 M heads;
  - A = M + C07 的 A heads;
  - P = M heads(按 P 的 R 替换,链走到末端)+ P 的额外 heads 与 R 收录的 head。
  - 去重同 C05 §3。
- **融合书**:等权 z-rank 融合后,**再对 16 列基做一次中性化**,与单个 head 的处理一致。
  - 这一条是在 C07 判读后的开发分析里发现的:很多 head 等权融合会带回控制暴露。
  - 它对所有组一视同仁。不中性化的版本作为次要结果同时报告(`--no-fuse-neutral`)。
- **主比较 P 对 A**:8 对同种子,单侧 Wilcoxon(α 0.05),「P 更好 / P 更差 / 分不出」。
- **测试段(2023-08-08 ~ 2025-12-31)是开发集**:它已被读过 7 次。C08 在它上面的结果只说明「开发期」。
  - **确认**只用 2026-09-16 之后的数据;数据更新后读一次,台账另记。前推段(2026-01-01 ~ 09-16)只报。
- **次要**(只报):
  - P 的额外 head 单个的表现;
  - 按旁听严格审计员的判断分两组(它会放行的任务位 / 会挡掉的任务位),比较各自产出的 head;
  - A 对 M,P 对 M;token 与 GPU。

## 4. 已知局限

- 测试段是开发集,不是干净的样本外;前推段也读过。干净的检验只有新数据。
- 新尺子下 GP 本身能找到的东西很少(C07:8 个种子共 68 个候选),P 与 A 的差可能被噪声淹没。8 对的功效低。
- 融合书再中性化是看过 C07 测试段之后加的(对所有组相同)。
