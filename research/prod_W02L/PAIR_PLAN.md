# 组合层合并：D 口径的 W02L 组合 + 挖掘冠军组合(事先写下)

写于 2026-11-13 14:25 EST,在算任何东西之前。用户 11-13 的要求，原话大意如下：

- 尺子 D 本来就是为了在已有冠军之外增加 alpha;
- 把 W02L 的 head 都按尺子 D 的口径处理后，一定有 alpha;
- 再和挖掘冠军组合，两个夏普合起来一定大于其中任何一个;
- 不先合成信号再建组合，而是先各自建组合，再合并。

## 两条腿(各自建组合)

1. **X 腿：挖掘冠军。** 用冠军信号本身(`runs/prod_W01/two_level/champions/signal_挖掘冠军_20260916.npy`),方向和半衰期在 train 上定(书的半衰期网格同 W02L)。
2. **W 腿:W02L 的 head,按尺子 D 处理。**
   - 每个 head 的处理和打尺子 D 分时完全相同：逐日 z 秩 → 用它的 D 半衰期做 EMA → 每天对尺子 D 的基做截面回归取残差 → 乘上它的 D 方向。
   - 尺子 D 的基 = 5 个控制项(含平方、立方)+ 手写库冠军 + 挖掘冠军 + 规模 / 流动性 / 价格的十分位哑变量。
   - 主版本 W79:去重后的 79 个 head(`library/W_dedup.json`),每个残差逐日标准化后**等权平均**,再按尺子 D 处理一次(秩 → 残差)。权重不拟合。
   - 描述版本：全部 244 个 head 的同样做法(W244);79 个 head 各自的 D 组合，逐日净超额等权平均(先组合后平均，W79b)。
3. **两条腿的书相同**:纯多头头部十分位等权，扣 15 bp,减全市场等权，得到逐日净超额。

## 合并(组合层，不合信号)

- 合并组合的逐日净超额 = a × X 腿 + (1 − a) × W 腿。
- a ∈ [0, 1],步长 0.01,在 train(2018-01-02 ~ 2023-08-07)上取夏普最大的那个，之后固定不动。
- 同报 a = 0.5,以及按 train 波动把合并组合缩放到和 X 同波动后的年化(只作描述)。
- 另外两个只作描述的合并：手写库冠军 + W79;挖掘冠军 + 手写库冠军(组合层)。

## 报什么

每段(train / valid 2023-08-08 ~ 2025-12-31)报：

- X、W、合并组合的年化净超额、夏普、回撤;
- 两腿逐日相关;
- W 对 X 的时间序列回归：alpha(年化)、beta、alpha 的 t、评估比率(alpha / 残差波动);
- 理论上最优合并的夏普 √(SR_X² + 评估比率²)。

## 核对(先做，不过就停)

用 `_signals` 加尺子 D 的基，重算 244 个 head 的 D train / valid 夏普，和 `d_scores.jsonl` 里记的比对。差不超过 0.02 的要占 95% 以上，否则口径没对上，不往下算。

## 怎么读

- 用 train 上定的 a,在 train 上合并夏普 ≥ 两条腿里较大的那个，这在数学上必然成立，只要两腿相关 ρ < SR_小 / SR_大，就严格大于。所以 train 上的数不说明问题。
- **valid 上的数也偏乐观**:W02L 的 head 是按 D 的 train 和 valid 两段较差的那个挑的，W 腿在 valid 上本来就过了线。冠军和 a 在 valid 上是样本外。
- 干净的检验只能在没用过的数据上做：
  - 2026-09-16 以后的新数据(≥ 60 个交易日);
  - 或者用户明确说「读第二次」时读 2026,并标成第二次读。
  - 主判据：合并组合(a 固定)和 X 腿的夏普，以及 W 对 X 的 alpha 的 t:t ≥ 2「W 在冠军之外有 alpha」;0 < t < 2「方向一致、证据不够」;t ≤ 0「没有」。
- 这次不读 2026:尺子 D 的基和所有信号只算到 2025-12-31。

## 补记(2026-11-13 15:10 EST,核对没过之后、任何合并结果算出来之前)

- 第一次运行停在核对：只有 90.2% 的 head 重算的 D 与记录相差 ≤ 0.02(要求 95%),最大差 0.18,重算的偏高。
- 查明原因：
  - 对不上的 24 个里 21 个含 `in_topk_masked`。其余 3 个只差 0.02 ~ 0.025。全部 head 的中位差是 0.0001。
  - 抽了一个含 `in_topk_masked` 的 head 对比:`runs/prod_W02L/two_level/_signals` 里的版本，和打尺子 D 时 PanelSet(CPU、共用缓存)给的面板逐日 z 秩相关 0.995,但 72% 的格子不同，每天都不同。
  - 这一类算子在两次计算里并列值处理不同(`_signals` 是在 GPU 上算的)。
- 改法：每个 head 的原始面板改从和尺子 D 打分时相同的 PanelSet 取(CPU、共用缓存),再按 D 的口径处理(`steer.signal_input` → EMA → 残差 → 方向)。核对标准不变，仍是 ≥ 95% 在 0.02 以内，否则停。
- 附带：建库(C_W / C_LXW / C_WK)用的是 `_signals` 版本，这 21 个 head 在那里和 D 打分时的面板略有不同。主判据结论不受影响，记在这里备查。
