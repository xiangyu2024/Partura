## 2. 对象与第 0 步

## 3. 尺子

- 产线奖励原样:先排序、EMA 0 / 5 / 20、按 train 定方向和半衰期、十分位纯多头扣 15 bp、score = min(train, valid)。
- 两把尺子都算,只用 B 跑轮次:
  - **A**:残差对 5 个控制(流动性、波动、20 日反转、已知成交额族、流通市值)的 1 / 2 / 3 次方取。
  - **B(主)**:A 的控制再加两个冠军信号(手写库冠军、挖掘冠军),按日期对齐。
    理由:要量的是「在这 5 千多条之上的提升」,冠军就是它们的两层合成。W01 叠加到冠军上只多 +2.3 个点,因为它的奖励没对准「冠军之外」。
- head = 闸门通过(覆盖 ≥ 90%、不同值 ≥ 50%)、score ≥ 0.5、与已知族 |ρ| < 0.5。
- 代码:`PARTURA_EXTRA_CONTROLS`,未设时逐位不变。

## 4. 批 → 流 → 轮(`scripts/w02l_lib.py`)

- **一批的 heads:** 该批在 B 下的发现,按分数取至多 8 个;含 `ts_spearman` 的不算(C01 修订 4)。
  这些写成和 M 批同格式的 evidence;富集表用全部成员及其 B 分数。
- **哪些批有轮次:** 至少有 1 个 head 的批。
  - 若这样的批少于 24 个(试点需要 8 条流 × 3 轮),没有 head 的批取 B 分数最高、且 > 0 的 3 个成员当「素材」补上。
  - 素材只给 PI 和定位工具当起点,本身不进 W02L 的库。
- **流:** 有轮次的批按主题聚在一起(head 多的主题优先),每 3 批一条流,编号从 2001 起;第 k 轮读本流第 1..k 批。服务器端原样用 `prod_conductor.sh`。
- **每轮:** 和 W01 修订 2 之后相同。
  - 总领跑 fetch → PI(Sonnet 5.5)→ 相关度表 → 审计(Haiku 5.5,1 次)→ 定稿推送;工作流 `workflows/w02l_round.js`。
  - 2 个 GP 任务位各 96 次评估,加不超过 16 个 R 变体。
- **整波库禁令**(W01 `NEXT_WAVE.md` §1 (a)):
  - 秩相关 |ρ| ≥ 0.7 的禁令对象:本流 heads、别的流已出的 heads、W01 的 heads(`PARTURA_WAVE_BAN=1`)。
  - 骨架禁令(`PARTURA_SKELETON_BAN_FILE`):两个库全部 5583 条的骨架。
  - 禁令样本的指纹缓存在磁盘(`PARTURA_EXEMPLAR_CACHE`)。
- **资源:** 新服务器 12 个运行位、2 路显卡、面板缓存 64 GB、整机匿名内存线 850 GB(`tmp/w02l_env.sh`)。

## 7. 判读(事先写下;test 只读这一次,记账 `ledger_prod.json`)

- **W02L 库:** 各流任务产出的新 head,加上 R 的替换与收录(B 下 score ≥ 0.5、与已知族 |ρ| < 0.5),彼此按 |ρ| ≥ 0.7 去重。
- **主判据:提升 = C(L ∪ X ∪ W02L) − C(L ∪ X)。**
  - 两个都用 AlphaCube 原样的两层合成建:打分 → 族 → 族内 ridge → 族间 lstsq。两边做法完全相同。
  - 选族、权重、半衰期都只用 2018-01-02 ~ 2025-12-31 拟合,也就是新切分下 test 之前的全部。
  - 比 test 段纯多头逐日净超额,同一天相减,看 t:

    | t / 年化差 | 判读 |
    |---|---|
    | t ≥ 2 | Partura 让这 5 千多条变好了 |
    | 差为正且 t ≥ 1 | 方向一致、证据不够 |
    | 差为负 | 没有增益 |
    | 其余 | 证据弱 |

  - 多空的成对差同样报,只作描述。
- **次要(描述):**
  - W02L 自己的两层合成单独看。
  - 叠加到两个冠军上(同 W01 的 `OVERLAY_PLAN.md`),test 段成对差。
  - valid 段的同样读数:valid 参与了挑选,只描述,不判。
- **事先的预期:** test 段只有 0.67 年,两个都含冠军全部内容的合成,差值大概率在 ±2 个点以内、t < 1。真正可信的增益要 ≥ 3 个点才可能显著。

## 8. 偏差,必须一起读

- test 段只有 170 个交易日,检验力低。
- valid(2023-08 ~ 2025-12)以前当测试段被读过很多次,两个库和冠军的挑选也部分见过它。所以 valid 上的增益不能当证据,只有 test 能。
- 挖掘库的挖掘区间已核对(2026-11-09,`imports/old_server/AlphaCube/mining_runs/*/meta.json`,有记录的 22 个运行):

  - 到 2025-12-31 的那 6 个见过 valid 段,这是 valid 只作描述的又一个理由。
- 尺子 B 未经 C0X 验证;冠军权重拟合在 train 上,在 train 段对冠军取残差略偏乐观。
