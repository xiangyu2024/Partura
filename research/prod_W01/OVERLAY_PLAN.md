# W01 的合成信号叠加到现成冠军上:做什么、怎么判(2026-11-08 01:10 EST,写在任何叠加信号建出来之前)

用户 2026-11-08 的指示:做「便宜的」那一种。即冠军信号加上 W01 的两层合成信号,权重只在样本内定,和冠军本身同一天相减比。

**为什么值得测**

- W01 是从零挖的,并把冠军的主力(成交额一族,代表 `cross_mean(day_std(Amt), 30)`)当作已知因素剔除;和它 |ρ| ≥ 0.5 的 head 不收。所以它单独比不过冠军,该问的是能不能**加在冠军上**。
- `research/two_level` 里把 Partura 第四轮产出并进冠军池没有变好。但那一批大多是冠军那几族的变体,这一批是按与已知族不相关挖的。

## 对象

| 记号 | 是什么 |
|---|---|
| H / X | 手写库冠军 / 挖掘冠军,延到 2026-09-16 的信号(新服务器 `runs/prod_W01/two_level/champions/`,复现已核对) |
| W | `TWO_LEVEL_PLAN.md` 主判据的 C_WP_ng(W01 的 285 个 P head,两层合成,不设小族门槛) |
| O_H / O_X | 叠加信号:H ⊕ W、X ⊕ W |

## 怎么叠加(照两层合成的族间层)

1. 每个信号逐日 z 分数(`alphacube.metrics.zscore_rows`),方向按样本内 IC 对齐。
2. 把冠军和 W 当作两个「族因子」,用 AlphaCube 族间层的同一个函数定权重:`combine_two_level.fit_weights(..., "lstsq")`。
   只在样本内(前 1359 天,到 2023-08-07)拟合,标签是剔除开盘封涨停的 `open_vwap15`。
3. 用 `combine_two_level.blend` 合成:某一格只有一方有值时,只用那一方。

样本内的事实也一起报,只作描述:W 与 H、X 的逐日秩相关均值,以及拟合出的两个权重。

## 尺子与判读(事先写下;同 `TWO_LEVEL_PLAN.md`)

**尺子**

- 用 `partura.books.books`:全市场十分位,扣单边 15 bp。
- 纯多头净超额 = 前 10% 等权的净收益,减去当天有信号、有标签的股票的等权收益。
- 方向、半衰期只用样本内定。
- 分段:测试段 2023-08-08 ~ 2025-12-31,前推段 2026-01-05 ~ 2026-09-16,合并段 = 两者。

**主判据:O_H − H、O_X − X 两对**

看纯多头逐日净超额,同一天相减,合并段的 t:

| 合并段的 t / 前推段 | 判读 |
|---|---|
| t ≥ 2 | 加上 W01 让这个冠军变好了 |
| 前推段为正,且 t ≥ 1 | 方向一致,证据不够 |
| 前推段为负 | 没有延续 |
| 其余 | 证据弱 |

- 两对分别判。两对都成立才说「W01 能给现成冠军加分」;只有一对成立时,如实写哪一对。
- 多空的成对差同样报,只作描述。

**稳健性(描述)**

- 在冠军自己的半衰期下(H 20、X 10),叠加信号与冠军的成对差;
- 固定权重比 W : 冠军 = 0.25 / 0.5 / 1(z 分数相加)时的成对差。

**事先的预期**

- W 与冠军的秩相关大概在 0.3 ~ 0.6,因为 W01 剔除了成交额一族,但没剔除冠军里别的东西。
- lstsq 给 W 的权重明显小于冠军。
- 成对差大概率在 0 ~ +2 个点、t < 1。若有增益,挖掘冠军上可能更明显:它的前推段比测试段掉得多(夏普 2.10 → 1.49)。

## 偏差

- 测试段不干净(见 `TWO_LEVEL_PLAN.md`)。前推段 0.67 年,功效低。
- 测试段、前推段对 W 是第三次读取,对两个冠军是又一次读取(冠军已读过多次)。
- 叠加的做法是用户在看到两层合成读数之后选的(「便宜的那种」)。但权重怎么定、怎么判,都写在建任何叠加信号之前。
