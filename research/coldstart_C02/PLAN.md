# C02:Partura v2(假设直接测 + 设计初始种群 + GP 局部精修)vs AlphaCube GP(事先约定)

写于 2026-10-27 22:45,在本实验的任何运行之前。提交之后不改;要改就另写一节「修订」,写明改了什么、为什么、当时看过什么。

## 1. 问题

**同样的付费评估次数、同样的随机种子、同样的环境规则下,让 LLM 研究层(Partura v2)直接检验自己的假设、设计初始种群、再让 GP 做局部精修,
能不能比 AlphaCube 的 GP 在没碰过的样本外找到更多有效、互不相关、而且是「新」的信号?**

设计来由:C01(`research/coldstart_C01/`)里 agent 只能通过「按写法匹配的先验 + 邻域」去改 GP 的提议分布,信念传不过去。v2 换接口:
- 假设由 agent 写成一小组带对照的变体,**直接评估**,不经过 GP 的运气;
- agent 设计**初始种群**:一部分随机(过环境禁令与相关度拒绝),一部分是 agent 想测的(大部分是新的低相关 idea,小部分是对以往 idea 的潜在大幅改进);
- GP 只在这个种群附近做局部精修。

## 2. 设计

### 2.1 数据与时段(与 C01 相同)

A 股全市场分钟 store。搜索只看 20180102–20230807(train 至 20211231,valid 20220101 起)。
**测试段 20230808–20251231**,最后每个 head 只读一次(台账 `runs/_c02/ledger.json`);**前推段 20260105–store 末日**,只报不判。

### 2.2 两组都带的环境规则

| 规则 | 设置 |
|---|---|
| 奖励 | `long`(全市场十分位纯多头,扣 15bp,方向与半衰期 0/5/20 在 train 定,score = train 与 valid 较差的) |
| **相关度拒绝** | 候选与已知族(`cross_mean(day_std(Amt), 30)`,sign −1)的实测秩相关 \|ρ\| ≥ 0.5 → 适应度 −∞(打分、记录,但不繁殖)。`PARTURA_RHO_REJECT=0.5` |
| **计算成本禁令** | `ts_spearman`(按股票逐只 Python 循环)与全部 `nt_*`(分钟级跨股票算子,落盘整块立方体)权重 0。`PARTURA_ENV_OPW="ts_spearman=0,nt_*=0"` |
| **准入门槛** | 发现 = score ≥ **0.7**(C01 是 1.0;调低以提高每组可比的发现数) |
| 每种子预算 | 192 次付费评估、种群 48、深度 2–4 |
| 运行保护 | 磁盘守护(数据盘 < 60 GB 停最大落盘)、单任务 180 分钟时限 |

### 2.3 两组

| 组 | 是什么 |
|---|---|
| **A**:AlphaCube GP | 无种子、无指引、均匀采样(`--arms control`),只带 §2.2 的环境规则 |
| **B**:Partura v2 | 同一个 GP、同一环境规则、同一随机种子,外加:直接检验的假设、Partura 设计的初始种群(种子占初代上限 50%,`--seed-share 0.5`)、Partura 的先验(含按字段类型的加权) |

### 2.4 一轮,8 个种子(401–408)

1. **W1 假设**(分级 workflow `workflows/c02_hypotheses.js`):Partura 写 ≤ 8 个假设,每个是一张 thesis 卡加一小组变体(核心写法 + 消融 + 对照),全部变体合计 ≤ 64 个表达式。
2. **直接检验**(`scripts/c02_direct.py`,代码):在 train / valid 上用与搜索相同的奖励和相同的环境规则逐个评估。**每个表达式算 B 组 1 次付费评估。**
3. **W2 设计**(`workflows/c02_design.js`):Partura 读直接检验结果,写 `guidance/C02_r1.yaml`。内容:≤ 2 个 idea,每个的种子就是它设计的初始种群,≤ 24 个,每个种子标 `new` 或 `improve`,`improve` ≤ 1/3;外加先验;并分配种子。
4. **GP 精修**:A 组每个种子 192 次;B 组每个种子 192 − ⌈直接检验数 / 8⌉ 次。两组合计付费评估严格相等。

### 2.5 Partura 能读什么(温启动)

**可以读**:本 PLAN;C01 的样本内材料(`research/coldstart_C01/` 下的 PLAN、digest_r*、beliefs_r*、cards_r*、round*_workflow.json、tokens_r*;`episodes/c01*` 两组的 evidence.json);
C02 自己 B 组的产出;`partura/`、`scripts/` 代码;算子源码。
**不得读**:`research/coldstart_C01/RESULT.md`、`final*.json`、`ledger_c01.json`(含测试段数字);`runs/`;`lab/`;以前研究的结论目录;C02 A 组的任何结果。事后用转录审计。

## 3. 判读(写死)

- **发现**:score ≥ 0.7,且没有被相关度拒绝。B 组的发现包括直接检验里合格的表达式。
- **heads**:每组按 score 从高到低贪心去重,与 C01 相同的量法(train 段每 5 天、按选定方向与半衰期平滑后的日截面秩相关)。要求:
  - 与已知族 \|ρ\| < 0.5;
  - 与本组已收的 head \|ρ\| < 0.7;
  - **与 C01 的全部 head \|ρ\| < 0.7**(只算「新」的;C01 的 head 是两组共同的先验知识)。
- **有效**:测试段年化净超额 > 0 且 t = 夏普 × √年数 ≥ 2.0。
- **主指标**:每组有效 head 个数。判定沿用 C01 §3.3:B − A ≥ 2 且 B ≥ 2 × max(A, 1) 为「Partura v2 有用」;A − B ≥ 2 为「更差」;其余「分不出」。
- **次指标**(只报):风格中性化后有效数;前推段读数;8 对同种子配对;heads 融合书;对 C01 head 的「同族改进」(\|ρ\| ≥ 0.7 但测试段更好)单列;GPU 时间与 token 账;表达式对比;Partura 的直接检验在样本内有多少假设成立。

## 4. 已知局限(写在结果之前)

- 只有一轮;8 个种子。
- B 组温启动(读得到 C01 的样本内材料),A 组没有记忆:被检验的正是「Partura 的记忆与推理」这一整包。
- 测试段与 C01 相同:C01 的判读读过它,设计者(我)看过 C01 的样本外结果。Partura 不得读。新 head 必须与 C01 的 head 不相关,以减轻这层影响,但不能完全消除。
- 幸存者偏差(store 里没有退市股)、A 股纯多头口径,同 C01。
- 字段类型加权只能通过 Partura 的接受规则实现(只在 B 组):AlphaCube 生成器对叶子字段是均匀抽样,算子权重管不到叶子。
