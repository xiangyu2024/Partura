### 目前对本种子 alpha 来源的信念

- 快照只有一个 head:`day_kurt(Ret)`(score +0.97,train +0.97 / valid +1.54,方向 −1,hl=20)。拆解 0 次、共性表空,所以没有任何付费证据,下面全是源码与算术推断。
- 代数事实:Ret 在 0 上有点质量,k/241 分钟活跃时 kurt+3 = (241/k)·c,c 是活跃分钟的形状。随机张量验算:高斯 k=48 → kurt 10.7,全活跃 t(4) → 3.1;乘 (1−zero_ratio) 后为 2.7 与 6.1。所以裸核心的截面排序**主要读的是交易稀疏度**,其次才是尾部形状。
- 我的权重:H1 稀疏度代理 ≈ 0.55,H2 真尾部形状 / 跳跃集中度 ≈ 0.25,H3 彩票 / 封板后效 ≈ 0.20(H1 与 H3 不互斥)。
- 多头腿(低峰度)= 连续成交、价格连续被发现的股票;这本身可能就是「流动性的另一种写法」,只是 5 个控制里没有「有多少分钟真的在动」这一项。
- 写种子时记下的工程事实:LimitWidth / BoardCode / 日度 day_zero_ratio 不能当 `cs_bucket_*` 的分桶变量(并列多,`_pct_rank` 用列序拆并列 → 列序斜坡,陷阱 2);比例类日度量要 20 日平均才过 distinct 门槛;`day_kurt` 对日内仿射变换不变,`day_kurt(in_demean(Ret))` 等与核心逐点相同,不写。

## 第 3 轮

### 目前对本种子 alpha 来源的信念

- **库里 17 个 head,独立机制大约只有四条**:σ 的凸函数(6 个,陷阱 1/3,已付费证实:DW 诚实版 −2.02 / +0.29;偶版比奇版高 +0.47)、交易密度 / 零成交分钟(6 个,含 day_kurt 一族和 `cs_last_low40 + pow_2_5` 那一族;后者还用负底数 → NaN 做了一道隐性样本筛选)、成交时点(3 个:水平 2、量价时点先后 1)、F 家族 `ts_reg_fvalue(day_std(Amt), day_centroid(Amt), ·)`(2 个)。head 数 ÷ 机制数 ≈ 4,这是 C 组方法本身最该报的一个数。
- **F 家族是本库最可能「是真东西」的一条,但还没定性。** 支持:裸核心 +1.51,train 1.53 / valid 1.51 两段几乎相等(σ 通道 head 的 valid/train 是 1.9–5.2);三个单调改写分数差 < 0.07,凸度不是来源;Amt→Volume、窗口 10/20/40 都稳;尺度无关,与已知族只有 −0.23。反对:F 是 R²,会被重心的测量噪声衰减,解剖员的合成面板说明它*能*纯靠精度排出股票(秩相关 −0.80)。合成面板只说明可能,不说明大小,所以我的权重是 **精度 0.5 / 真耦合 0.5**(解剖员 0.55 / 0.45)。
- **时点水平是真的,但平滑以后一半在已知族里**(rho_known 0.50 / 0.56);**量价时点先后**有一只脚在峰度族里(残差 0.60–0.62)。
- **day_kurt 与 DW 已结案**,不再花 GP 位。
- **三轮下来学到的流程事实**:GP 会拆掉归一化去拿 σ 的凸性(r2b 的 7 个 head 没有一个保留 RSJ 分母);E 位真正的产出机制是「种子决定 GP 在哪片邻域里长」,两轮 E 的 6 个 head 只有 1 个是我们写下的机制;审计员对算子语义的预判比我准。
- **本轮的选择和理由**:
  - E = F 核心,外围只做「把测量精度固定住」(精度代理十分位内排序 / 秩残差、用价格移动重心做安慰剂差分、找回被 F 扔掉的符号)。Gassen, Ashbaugh-Skaife & Veenman (2020) 在同步性 R² 上给的正是这个处方。这是最强的家族,一个 E 位就能把它判死或扶正。
  - N = 隔夜 / 日内拆分。17 个 head 没有一个跨日比价;「同样的总收益里竞价占多少」在构造上落在 20 日反转控制的零空间里,不靠陷阱也躲得过中性化;普通 GP 很难自己拼出 `day_first(Open) / cross_delay(day_last(Close), 1)`,这是 C 组相对对照组的边际。
  - 没选:量价时点先后(核心 ②,留作 F 核心被表否掉时的替补);day_kurt 第 2 个 E 位(已结案);时点第二矩 N-乙(和 F、已知族撞车)。
  - R 里**没有**放纯 σ³(`pow_3(cross_mean(day_std(Ret), 20))`):若它替换了 head,等于把陷阱 1 原样放进库里,而且会拖累整组的合理度分。定位给的两条「自动更好」的拆解变体(σ³ 那两个 head 的换窗 / 去 cross_sum)也没交,它们只会让陷阱 head 的样本内分数更高、valid/train 更极端。
