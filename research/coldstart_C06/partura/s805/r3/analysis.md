### 1.3 来源二(本轮新增,证据最硬):开盘集合竞价成交的慢速增长

head +1.13:`cs_bucket_rank(cross_mean(day_first(Amt), 241), cross_mean(cross_mean(day_first(Amt), 241), 30))`,sign **+1**,hl 20,train 1.1323 / valid 2.4838。

**它是什么(代码事实):**
- `in_half` 的注释(`operators/dt_in.py`):241 列的立方体里**第 0 列是 09:30 的开盘集合竞价**,1–120 与 121–240 是两个连续竞价时段。
- `day_first(x)` = `first_valid_last`(`operators/common.py:461-475`)= 当日第一个**非 NaN** 分钟的值。所以 `day_first(Amt)` ≈ **开盘集合竞价的成交额**(若该股当日第 0 格为 NaN,则退化成第一个有值的分钟)。
- `cross_mean(x, d)` = `rolling_reduce(x, d, nanmean_last)`,而 `rolling_windows` 是**左侧 NaN 填充**、`nanmean` 忽略 NaN(`common.py`)—— **没有 min_periods**。
- 于是 x = 241 日均值,key = 该均值的 30 日均值 ≈ 同一条均值线滞后约 15 天。`cs_bucket_rank(x, key)` = 在「同一慢速水平」的十分位里按当前值排序 ⇒ **这个 head 测的是「年度均开盘竞价成交额」最近约 15 天的增长**。sign +1 = 做多成交在增长的股票。

**四类证据:**

| 证据 | 数字 | 读法 |
|---|---|---|
| 充分性 | `cross_mean(day_first(Amt), 241)` 单独 **+0.1172**(`rho_known` **−0.7881**);`cross_mean(cross_mean(day_first(Amt), 241), 30)` 单独 **−0.2439**(`rho_known` −0.7485);`day_first(Amt)` 单独 **−1.2917**(`rho_known` +0.7346) | **两个层面单独都不是因子,而且三个都是流动性 / 已知族的代理(\|ρ\| 0.73–0.79,按 §1 全部不合格)。信号完全不在水平里。** |
| 必要性 | `cs_bucket_rank(cross_mean(day_first(Amt), 241), cross_mean(day_first(Amt), 241))`(自己对自己分桶)−0.2781,必要性 **+1.41**;`cs_bucket_rank(day_first(Amt), cross_mean(cross_mean(day_first(Amt), 241), 30))` −0.7458,必要性 **+1.88**;`cs_bucket_rank(cross_mean(day_first(Amt), 241), cross_mean(day_first(Amt), 30))` −0.9025,必要性 **+2.03** | 三个方向全是大数字。**这是全库唯一一个「三处都必要」的结构** —— 不是某个叶子的改写,是一个真的两项比较 |
| 敏感性·字段 | `Amt → Volume` **+1.3163**(train 1.3163 / valid 2.1036),`rho_known` −0.2192,**与原 head 的 ρ 只有 0.3272** | **更好,而且是另一本书**(见下) |
| 敏感性·窗口 | 241→120:score 0.8361(train **1.0900** / valid 0.8361);241→482:score 0.3953(train **1.1066** / valid 0.3953) | **train 在 1.09 / 1.13 / 1.11 三点上几乎不动,掉的全是 valid(2.48 → 0.84 → 0.40)。窗口 241 是在 valid 上被选出来的** |

**字段这一条值得单独说,因为它给出本轮唯一确定的库改善。**
`daily.py:24-26` 的注释是代码事实:**生产库里价格字段是后复权的,而 `Amt` 与 `Volume` 是原始值**(注释原话是不要用 `Amt/Volume` 当价格,因为两者不在同一个空间)。于是 `day_first(Amt)` = `day_first(Volume)` × **名义**开盘价。两个 241 日均值相比,Amt 版 = Volume 版 + **名义价格的慢速趋势**(一条长周期动量)。
实测:Volume 版 **1.3163** > Amt 版 1.1323,而两者 ρ 只有 **0.3272** —— 价格趋势那一截不但没帮忙,还把书换掉了一大半。**干净的那一维是「开盘竞价成交股数的慢速增长」。**
按规则 §2:score 1.3163 ≥ 1.1323 + 0.1 ✓、`|rho_known|` 0.2192 < 0.5 ✓、与原 head ρ 0.3272 < 0.5 ⇒ **作为新 head 收录**(前提:与库里 11 个 head 的 |ρ| 全部 < 0.7,相关度表会核)。

**没排除的替代解释,按担心程度排:**
1. **partial window 造成的 IPO 衰减。** 没有 min_periods,上市不足 241 天的股票用「有多少天算多少天」的均值,x 与 key 的差在上市第一年里有一个机械分量(IPO 后成交逐月衰减 ⇒ x < key ⇒ 排名低 ⇒ sign +1 下被排除在多头腿外;反过来,次新股放量期 x > key)。
   **必须测**,而且不要用 `ListAge`(哨兵并列块,§1.2c),用 `cross_valid_count(day_last(Close), 241)` 当条件键,或者直接看窗口 120 版的 train 是否同样稳。
2. **流动性增长 = 已知的「高成交量溢价」。** 5 个控制里没有任何一个是流动性的**变化量**,所以它不是 §4-3 的直接实例;但它和 Gervais-Kaniel-Mingelgrin 的高成交量溢价是同一个机制(见 §5 的 L2)。对创新度是上限,对「样本外还会在」是加分。
3. **开盘竞价是否特殊,完全未测。** `day_first` 只用第 0 格。**同一结构换成 `day_sum`(全天成交)是 1 格 R 就能回答的决定性一测。**
4. valid(2.48)远高于 train(1.13),且窗口是在 valid 上选的。样本外应按 **train 的 ≈1.1** 期待,不按 1.13 的 min,更不按 2.48。

**同族的 +0.63 head**:`cs_bucket_rank(cross_mean(cross_mean(day_first(Amt), 20), 20), cross_mean(cross_mean(cross_mean(day_first(Amt), 20), 20), 30))` —— 同一机制的短尺度版(≈40 日均值 vs 其 30 日均值)。它的存在说明机制在时间尺度上是连续的,不是只在 241 这一点上成立;这是对「窗口被 valid 选出来」这条担心的部分缓解。

### 1.4 来源三(完全未探测,嫌疑具体):日内分钟收益的峰度

head +0.93:`day_kurt(in_slice(Ret, 1, 236))`,sign −1,hl 20,train 0.9301 / valid 1.6058。

**为什么它一个诊断数字都没有(工具原因,不是疏漏)**:`scripts/c05_locate.py:336-365` 生成四类变体 —— sufficiency / knockout 只取「collapsed 且 degenerate 且能当合法根」的子树,而 `in_slice(Ret, 1, 236)` 与 `Ret` 都是分钟层张量,不能单独当因子;`SWAP` 表(`:58`)里**没有 `Ret`**;`in_slice` 的 1 / 236 不是节点的 `window` 属性,所以 window 那两条也生不出来。**四类变体一个都没有 ⇒ 空表。**

**代码事实**:`_kurt`(`common.py:411`)= `mean(d⁴) / mean(d²)² − 3`,`d = x − nanmean(x)`,**除掉了方差,是尺度无关的超额峰度**。所以它**不是** §4-1 的凸变换(`day_durbin_watson` 那个病不在这里)。

**但有一条很具体的嫌疑**:分钟收益里有大量**恰好为 0** 的分钟(无成交、锁板、停牌)。零点质量越大,四阶矩相对二阶矩越大 ⇒ 峰度越高。两处 docstring 直接支持这个读法:
- `day_flat_ratio`(`ops_ext.py:82-95`):「它直接命名『冻结报价』这个状态,而不是去读一个在那里**饱和**的峰度」;
- `day_zero_ratio`(`ops_ext.py:272-285`):「在 Ret 上 = 零点的质量 —— 价格没动的分钟(锁板、停牌、无成交)」。

即:**`day_kurt(in_slice(Ret, 1, 236))` 最可能是「零收益分钟占比」= 流动性 / 冻结报价的非线性改写(§4-3),sign −1 = 做多零分钟少的活跃股。** 这也顺便解释 valid(1.61)远高于 train(0.93):近似静态的个股属性 + 一段行情,正是 r2 §1.5 给 M2 那 4 个 head 的诊断形状。

这条嫌疑能用 1 格 R 测一次(把代理换成被代理的量,与 r2 R 第 1 项同一个逻辑),清单见 §4.2 B 组。**顺便提醒 PI:这个 head 是我们自己 r2 槽 a 的产物,它进了最终库,它的质量就是我们这一组的成绩,不能不测。**

### 1.5 来源四(机制有价值,head 本身不稳):`ts_skew(·, 50)` —— 时间维的分布形状

M 第 3 批给了两个 head,结构完全平行:

**(b) head +0.88 四个方向全掉,按 §1.1 的尺子是「调出来的一个点」:**

|---|---|---|---|

| `Vwap → Close` | 0.7557 | −0.12 | 稳 |

**(c) 真正值钱的是第二个 head 揭示的对照,它直接判了我们 r2 槽 b 的死因。**

**(d) `ts_skew` 这类聚合自带的一条伪信号通道**(写给 PI 当警告,不是反对):`nanskew_last`(`common.py:569-583`)= `m3 / std³`。一个偶发尖峰的日度序列,它的 50 日滚动偏度基本由**窗口里的那一个最大值**决定 ⇒ 实质上是「最近 50 天里有没有出现过一次极端值」,尖峰进窗 / 出窗会造成 50 天的机械回声。这既是机制(注意力 / 资金事件),也是一条需要在种子表里设对照的通道(例如同时放 `ts_quantile_q75` 或极值占比,看是不是只有「最大那一天」在出力)。
