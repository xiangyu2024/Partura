# C01 冷启动对比:AlphaCube 单独 vs AlphaCube + Partura(事先约定)

写于 2026-10-26,在本实验的任何一次运行之前。提交之后不改;要改就另写一节「修订」,写明改了什么、为什么、当时看过哪些结果。

## 1. 问题

**同样的算力、同样的随机起点下,Partura(分级 LLM agent 研究层)写的指引,能不能让 AlphaCube 在没碰过的样本外找到更多有效、可交易、彼此不相关的新信号?** 两臂的因子表达式差在哪里?Partura 每轮要花多少 token?

和 e4–e7 的区别:

1. **冷启动**:Partura 不带任何以前的结论,只看本实验自己产生的证据;
2. **多轮闭环**:Partura 读上一轮自己这一臂的结果 → 写指引 → 下一轮搜索 → 再读,共三轮;
3. **自动编排**:每轮一次固定的分级 workflow(`workflows/c01_round.js`),人在开跑之后不插手;
4. **8 个种子**(E11 的要求),判读规则、样本外段与台账都写在这里;
5. **token 记账**:按角色、按模型、按轮。

## 2. 设计

### 2.1 数据与时段

- A 股全市场分钟 store(`/root/autodl-tmp/qmt_daily_data/fast_factor_compute`,5207 只 × 241 分钟,8 个字段)。
- 搜索与 Partura 只看 **20180102–20230807**:train 20180102–20211231、valid 20220101–20230807(`idea_search.py` 固定)。
- **测试段 20230808–20251231**:本实验的搜索和 agent 都不打开,最后每个 head 只读一次(台账)。主判据在这一段。
- **前推段 20260105–store 末日**:同时读一次,只报不判(约 0.7 年,功效不够)。

### 2.2 搜索器(两臂相同)

AlphaCube GP,经 `scripts/idea_search.py`:每臂每种子付费评估预算 192,种群 48,深度 2–4;奖励 `long`(全市场十分位纯多头,扣 15bp 单边,方向和半衰期只在 train 定,score = train 与 valid 中较差的);半衰期网格 0 / 5 / 20;「发现」= `steer.is_discovery`(score ≥ 1.0)。

### 2.3 两臂

| 臂 | 是什么 |
|---|---|
| **A 对照**(AlphaCube 单独) | 无种子表达式、无指引、均匀采样(`--arms control`) |
| **B 处理**(AlphaCube + Partura) | 同一个 GP、同一奖励、同一预算、**同一随机种子**、同一算子库,外加 Partura 本轮写的指引(`--arms steer`) |

### 2.4 轮次与种子

| 轮 | 种子 | A 臂 | B 臂 |
|---|---|---|---|
| R1 | 101–108 | 对照 | **与 A 共用**(无指引时 steer 与 control 逐抽相同,不重复算) |
| R2 | 201–208 | 对照 | 用 `guidance/C01_r2.yaml`(Partura 读完 R1 后写) |
| R3 | 301–308 | 对照 | 用 `guidance/C01_r3.yaml`(Partura 读完 B 臂的 R1 + R2 后写) |

同一轮两臂种子相同;不同轮换种子,所以三轮累计**每臂付费评估都是 3 × 8 × 192 = 4608 次**,算力严格相等。
跑坏的 run(进程崩溃、OOM)原样同参数重跑一次,重跑记在 RESULT 里;不因为结果不好而重跑。

### 2.5 Partura 能动什么(本实验限定)

- **先验**:ban / weight / rewrite / family 四种规则(`partura.steer` 的模式语法),每条必须写 `why`(一句可证伪的话)和 `evidence`(指向本实验的证据)。
- **idea**:hypothesis + seeds(种子表达式)+ grammar(邻域:day_ops / leaves / memory_ops / windows)。每轮最多 2 个 idea;2 个时 8 个种子平分(种子号小的 4 个给第一个);1 个时用满 8 个种子;0 个时用 `I0_open_search`,只带先验。
- **不能动**:奖励(固定 `long`;对照必须是固定目标的 AlphaCube)、pool(环境常量,见下)、预算、种子、判读规则。
  奖励与评估两类反向指引不在本实验的检验范围内,这是本实验的局限,不是结论。

pool(环境常量,两臂、三轮都一样):`cross_mean(day_std(Amt), 30)`,sign −1 —— 教科书式的成交额离散度(流动性 / 波动)一族,只用来判「是不是已知的东西」。

### 2.6 冷启动隔离

Partura 的 agent **不得读**:`lab/findings.yaml`、`guidance/` 下除 `C00_base.yaml` 与本实验 `C01_*` 以外的文件、`research/`(除本目录)、`episodes/`(除 `c01*`)、`notes/`、`studies/`、`handoff/`、`runs/`、`batches/`、`docs/` 里的研究结论。
**可以读**:本实验 B 臂自己的证据(R1 共用的那 8 次也算 B 臂自己的)、本 PLAN、`partura/` 与 `scripts/` 的代码、算子注册表与内核源码(工具,不是结论)。
**不得看 A 臂 R2 / R3 的结果**(真实部署里没有对照)。
隔离是指令级的;事后用 agent 转录审计越界读取(`scripts/c01_tokens.py --audit`),越界如实写进 RESULT。

### 2.7 Partura 的分级编排(每轮一次 `workflows/c01_round.js`)

| 角色 | 模型 | 做什么 |
|---|---|---|
| 总领 | Opus 5.5 | 读本轮汇总、定研究方向、拍板最终指引、写信念更新 |
| 主研 | Opus 5 | 读证据,提出 thesis 卡与 idea(机制、可证伪预测、失效条件、对手方)和先验 |
| 执行 | Sonnet 5 | 机械分析:发现分族、算子 / 叶子统计、读内核源码解释算子到底在算什么、起草 YAML |
| 检查 | Haiku 5.5 | 校验 YAML:能解析、奖励为 long、pool 未改、种子表达式能被搜索文法解析、没有引用禁读文件 |

每轮 agent 调用次数固定(总领 2 次、主研 1 次、执行 ≤ 3 次、检查 1 次、不合格时修订 ≤ 1 次)。
检查两次仍不合格 → 本轮 B 臂沿用上一轮的指引(R2 则用 `C00_base.yaml`,即退化成对照),如实记录。

## 3. 判读规则(写死)

### 3.1 每臂的 heads

把一臂三轮 × 8 种子的全部发现汇总(R1 两臂共用),按 score 从高到低贪心去重,与 `idea_search.py` 的量法相同(train 段每 5 天取样、按选定方向与半衰期平滑后的日截面秩相关):

- 与已知族、与 pool 的 |ρ| < 0.5;
- 与本臂已收的 head 的 |ρ| < 0.7。

### 3.2 样本外读数(每个 head 只读一次)

按搜索选定的方向和半衰期重建十分位纯多头书,扣 15bp 单边,相对等权全市场的净超额。
**「成立」= 测试段年化净超额 > 0 且 t = 夏普 × √年数 ≥ 2.0。**
同时报:风格中性化后的读数(逐日对 log 成交额(规模 / 流动性代理)、`cross_mean(day_std(Ret), 20)`(波动)、20 日收益(反转)做截面回归,取残差再建书),以及前推段读数。

### 3.3 主指标与判定

**主指标:每臂累计「成立」的 head 个数**(两臂预算相同,个数即单位算力的产出)。

| 判定 | 条件 |
|---|---|
| Partura 有用 | B − A ≥ 2 且 B ≥ 2 × max(A, 1) |
| Partura 更差 | A − B ≥ 2 |
| 分不出 | 其余 |

### 3.4 次指标(只报,不改判定)

1. **样本内效率**:R2 + R3 的 16 个同种子配对里,B 臂 heads 数多于 A 臂的对数,符号检验(平局剔除),单侧 p < 0.05 记「样本内更有效率」。
2. 门槛废品率、通过数、最好分数、前十均分。
3. 每臂 heads 的等权 rank 融合书在测试段 / 前推段的净超额与夏普。
4. 风格中性化后的成立数。
5. **表达式对比**:两臂全部发现与 heads 的算子 / 叶子频率、三张面占比、深度、节点数、因子族;两臂前 10 个 head 并排;B 臂的发现有多少落在 Partura 的 idea 邻域里。
6. **token**:每轮按角色、按模型的 input / cache_write / cache_read / output,每轮墙钟;每臂 GPU 秒;B 臂每 GPU 小时的 token、每个成立 head 的 token。

### 3.5 Partura 的「坏轮次」

任何一轮里 B 臂的 heads 数在 8 对同种子配对中输给 A 臂 ≥ 5 对,就记为一次「指引让搜索变差」,在 RESULT 里单独做诊断:
指引里哪条规则 / 哪个 idea 造成的,机制是什么,下一轮 Partura 自己有没有发现并纠正。

## 4. 已知的局限(写在结果之前)

- **幸存者偏差**:store 的 5207 只全部存续到 store 末日(开跑前查过 `day_status.npy`:没有一只的生命周期提前结束;1973 只在 2018-01-02 之后上市)。也就是说股票池只有现在还在的股票,没有退市股。对偏小盘、低流动性的纯多头书,绝对收益偏高。两臂受影响相同,相对比较仍然成立,但绝对数字要打折扣。
- **测试段**:本实验的搜索和 agent 没碰过,但设计者在以前的研究里读过这一段;前推段干净,但只有约 0.7 年。
- **功效**:8 个种子仍可能分不出;GP 的种子方差本来就很大(同一配置换种子 +0.76 / −0.91)。分不出就记分不出。
- **只检验先验 + idea 两类杠杆**,奖励与评估类指引不在内。
- **A 股、纯多头**:T+1、涨跌停买不进、融券基本不可行,所以选拔口径是纯多头;迁移到其他市场时 label、成本、宇宙都要换。
- **多重检验**:本实验总付费评估约 192 × 8 × 5 = 7680 次(R1 共用),全部记下,RESULT 里给出 deflated Sharpe 的粗略门槛。

### 修订 2(2026-10-27 05:50,R2 跑完之后、任何样本外读数之前)

**发生了什么**:R2 的 B 臂 idea `C2b_turnover_on_the_up_minutes` 把搜索带进了分钟级跨股票截面算子(`nt_cs_normalize`、`nt_cs_scale` 等)。
这类表达式要把整块 (股票, 日, 分钟) 中间量落盘(`Partura/tmp/alphacube_*/bound_*.npy`,每个 6.8 GB)。
`c01r2s207B` 第 1 代就写了 253 GB,把共享数据盘写满后以 SIGBUS 退出(退出码 135);同时在跑的 `c01r2s208B` 搜索已做完,但算 heads 时写不进缓存(退出码 1)。
C2b 的 B 臂单次运行要 1.5–2.9 小时,A 臂是 15–70 分钟。崩掉的临时目录已删除(只删了这一个目录)。

**改了什么**(只改运行环境,两臂同一规则;主判据、heads、阈值、Partura 能动的杠杆都不改):
1. **磁盘守护**(`scripts/server/c01_diskguard.sh`):数据盘可用空间 < 60 GB 时,停掉落盘目录最大的那个任务,并删掉它的落盘目录。被停掉的任务记为失败。
2. **单任务时限 180 分钟**(`c01_queue.sh` 的 `JOB_MINUTES`),从 R2 的重跑起对所有任务生效。超时记为失败。R2 已完成的任务最长 171 分钟,都在时限内。
3. **R2 两个失败的 B 任务按 §2.4 原样同参数重跑一次**(`jobs_r2rerun.tsv`)。失败那次的日志与证据改名保留(`*.fail1`),不覆盖。
   **重跑仍失败(崩溃、磁盘守护或超时)时,该种子 B 臂的发现记为 0**。这把搜索成本的代价算在造成它的那一臂上。
4. **次指标增加计算成本**:每臂的 GPU 墙钟秒数合计,以及每个 head 花了多少 GPU 秒。
5. Partura 在 R3 的摘要里会看到自己 R2 的失败与运行时间,并被告知磁盘与时限约束(这是环境信息,不是结论)。

**当时看过什么**:R2 全部 14 个完成任务日志里的「distinct passers」行(样本内),即 A 臂 8 次合计 15、B 臂已完成的 6 次合计 2。
**没有**任何样本外读数。上面的改动都由磁盘事故引起,不是由这些数字引起;单任务时限更可能对 B 臂不利(B 的运行更慢)。

### 修订 3(2026-10-28 00:20 服务器时间,R3 跑完之后、任何样本外读数之前)

**发生了什么**:A 臂 `c01r3s302A`(对照,无指引)被 180 分钟时限停掉(退出码 124)。日志显示它的**搜索在时限内做完了**
(8341 秒、131 次付费评估、36 个通过者,evidence.json 已写出),超时发生在搜索之后的簿记步骤:在搜索视图上重建 36 个通过者、数这次运行自己的 heads。
这与 R2 的 `c01r2s208B` 相同(搜索做完、簿记失败),而搜索是确定性的:原样重跑会逐抽重复同一次搜索,并在同一步再超时。

**改了什么**:不重跑搜索,用 `scripts/c01_heads_fill.py` 在保存下来的证据上补做那一步,代码与阈值和 `idea_search.py` 相同
(同一视图、同一参照信号、同一 ρ 量法、|ρ| < 0.5 / < 0.7)。补算失败才按修订 2 记为失败。
主判据不受影响:`c01_final.py` 从各次运行的全部候选重新跨运行去重,本来就不用各次运行自己的 heads;补算只影响 §3.4 的同种子配对次指标。

**当时看过什么**:R3 全部 16 个任务的日志(样本内:各次运行的通过数与自己的 heads)。没有任何样本外读数。

**修订 3 补充(同一时间,任何样本外读数之前)**:`c01_final.py` 不再在全区间上重建「按搜索自己的量法就是已知族」的发现
(max(|rho_pool|, |rho_known_traded|) ≥ 0.5;训练段日期、平滑、方向与判读完全相同,这些发现按 §3.1 不可能成为 head)。
原因:这批发现里有 R2 C2b 的分钟级截面表达式,在更长的全区间上每个节点落盘约 10 GB,可能触发磁盘守护、把判读本身停掉。
为了验证这条捷径,从被跳过且不含 nt_* 的发现里均匀取 20 个仍然重建,并报告两种量法的差与「按全区间数字会不会变成 head」的个数。

### 修订 4(2026-10-28,判读试运行期间、任何样本外读数之前;用户决定)

**改了什么**:含 `ts_spearman` 的表达式从**两臂**的发现里一律去掉,不重建、不参加 heads 去重、不读样本外。
共去掉 A 臂 90 个发现(其中非已知族 72 个,占 A 臂非已知族发现 203 个的 35%)、B 臂 1 个(非已知族 0 个)。

**为什么**:`ts_spearman` 按股票逐只做 Python 循环,在 2018–2026 全区间上重建极慢;第一次试运行在其中 9 个上卡了约 5 小时,

**对结论的影响(写在结果之前)**:去掉的几乎全是 A 臂的发现,这条修订**偏向 B 臂(Partura)**。
因此判读时按下面的方式读主判定:若去掉之后 B 臂仍然没有按 §3.3 判为「有用」,结论稳健;
若去掉之后 B 臂按 §3.3 判为「有用」,记为「**无法确定**」,不算 Partura 有用。
被去掉的发现的面板以后可以补算,届时另出一版完整判读。

**当时看过什么**:三轮全部样本内证据(各臂的通过数、heads、|ρ|)。没有任何样本外读数。
