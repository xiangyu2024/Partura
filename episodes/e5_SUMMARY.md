## 每个开关的主效应(其余两个开关的四种组合上「开 − 关」的平均;每百次付费评估)

| 开关 | 按族数(事先约定) | 四种组合里几种是「开 > 关」 | 按事先标准的判读 | 按实测互不相关的发现数 | 几种是「开 > 关」 |
|---|---|---|---|---|---|

事先的标准:「有用」= 至少三种组合「开 > 关」且平均每百次评估多 ≥ 2 族;「没用」= 平均差在 ±1 族以内;其余「不确定」。
按实测互不相关的发现数那两列是**事后**加的(e4 之后才发现族数会被一个结构的变体撑大,见 `e4_SUMMARY.md` 的更正),不套事先的门槛,只看方向和大小。

## 读法

1. **三样都有贡献,大致可加;没有哪一样单独就够。** 实测互不相关的发现,每百次评估:对照 0.7 → 单开一样 0.9 / 1.2 / 1.8 → 开两样 2.6 / 1.9 / 3.1 → 全开 4.1。
2. **事先的预期错了一半。** 我预期邻域是主要来源、先验单独开接近对照。实际上先验的主效应和邻域一样大(按族数还更大),而且四种组合里全部是「开 > 关」。
3. **但先验的好处不是来自「拒绝坏的动作」。** 直接检验(`scripts/prior_check.py`,对照臂没被过滤过的 638 个存活候选):指引会碰到的只有 23%,几乎全是 D7(除法降权)一条,它不区分好坏(发现率 0.7% 对 1.0%);批量统计里「毁掉多头腿」的那几条(根上的 z 分数、滚动标准差、滚动最小)各只碰到 1~2 个候选 —— 碰到的确实很差(−4.1、−1.9、−1.1),但 GP 的随机树里很少长出这些结构。
   先验一臂多出来的发现从哪来:**量到的一个来源**是没过门槛的比例从 30% 降到 21%(少为废品付钱;废品不进存档,所以上面那个检验看不到)。**另一个可能的来源**是等价 / 同族去重逼着搜索往别处走(多样性)—— 这一条没有单独量过,是推测。
4. **种子间的方差很大。** 只开先验:4、4、0;邻域 + 先验:2、3、8。24 个 run 上三个主效应的方向一致,但单看任何一格都不可靠。逐对的符号检验(同组合、同种子,开减关,12 对):先验 9 正 2 负,邻域 7 正 3 负,种子 7 正 1 负 —— 没有一个单独到 5% 的显著水平。
5. **按 GPU 小时算,差别更大也更不稳。** 全开 28 个 / 小时,对照 4.6;但「种子 + 先验」只有 4.2,比对照还低 —— 它的种子 2 那个 run 搜进了 `ts_spearman`(日轴滚动秩相关)一类很慢的算子,150 次评估用了 89 分钟。预算按候选个数算,看不见这种成本。

## 对指引的影响

- 「想法 → 短搜」这套东西里,**种子、邻域、先验要一起用**;单开哪一样都只比对照好一点。
- 动作 / 子结构的先验(用户标了「重要」的那一项):**规则本身是对的(碰到的都差),但它们是从 Partura 自己的批量变体里学来的,AlphaCube 的 GP 很少提出那些结构。**要让先验在 GP 上起更大作用,得从 GP 自己的存档里学它常犯的错。用户的 AlphaCube 有约 22 个 GP 运行的存档(`/root/autodl-tmp/AlphaCube/mining_runs/`),还没用过 —— 下一步。
- 「少为废品付钱」是先验里量到的作用;去重和同族少采样可能也在起作用(未单独量)。这几样都应当保留并进 AlphaCube 本体(WP5 的钩子就是为此)。
- 预算该按时间算,或者给算子一个成本先验(慢的算子少采样);否则一个 run 可以被几个慢算子拖掉大半。
