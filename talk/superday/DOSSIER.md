## 1. 一句话与总表

**一句话**:七次事先约定的同种子、同预算对比里,让 LLM 研究层(Partura)参与因子挖掘,从没有在样本外胜过无 agent 的遗传规划(AlphaCube GP)。

## 2. 共同的系统与评估方法(七次实验都适用,差别见各节)

- **AlphaCube**:无 agent 的遗传规划因子挖掘器。
  - 输入:A 股全市场分钟数据立方体,股票 × 交易日 × 241 根分钟 bar(约 5,200 只;C01 PLAN 写 5,207,C05 起的判读视图是 5,220)。
  - 产出:类型化的表达式树(如 `cross_mean(day_std(Amt), 30)`),每个表达式就是一个日频因子。
- **Partura**:分级 LLM 研究团队。C05 起的角色:
  - 结构解剖员(Opus 5);
  - 文献员(Sonnet 5,只用 2023-08-08 之前的文献);
  - PI(Opus 5.5,决定任务);
  - 检查员(Haiku 5.5);
  - C06 加独立审计员(Opus 5.5)。
- **数据切分**:train 2018-01-02 ~ 2021-12-31;valid 2022-01-04 ~ 2023-08-07;**测试段 2023-08-08 ~ 2025-12-31**(只在判读时读一次,记台账);**前推段 2026-01-01 ~ 2026-09-16**(只报不判)。
- **收益标签**:第 t 日收盘后得到信号,第 t+1 日 09:31–09:45 的 VWAP 买入,第 t+2 日同一窗口卖出;入场窗口全程涨停封死的股票剔除(`AlphaCube-steering/src/alphacube/label.py`)。
- **奖励 / 判读的书**:十分位纯多头、等权、扣 15 bp;方向与半衰期(0 / 5 / 20 日)在 train 上选;score = train 与 valid 净夏普中较差的;**score ≥ 0.5 为发现**。
  - C03 起:信号对控制变量做逐日截面中性化后取残差(C03 四个控制,C04 起加市值共五个)。
  - C07 起:改成先排序再平滑,并做非线性中性化(见 C07)。
- **对比方法**:同样的种子、同样的付费评估次数。A = 无 agent 的 GP,B(C06 叫 C)= 有 Partura。判定规则、样本外段、台账在任何运行之前写进 PLAN 并提交;事后改动一律写成「修订」。
- **诚实约束**:
  - agent 不看测试段;隔离按会话记录审计;
  - 每个实验的判读只读测试段一次;
  - 读过测试段之后形成的解释,都标成推断,不当检验。

## 3. 各实验

### C01:Partura 写指引,改 GP 的提议分布

- **问题**:同样算力、同样随机起点,Partura 写的指引能否让 AlphaCube 在样本外找到更多有效、可交易、互不相关的新信号?
- **设计**:
  - 冷启动(Partura 不带以前的结论);3 轮闭环(读本臂上一轮结果 → 写指引 → 搜索);8 个种子;每臂每种子预算 192、种群 48、深度 2–4;
  - 奖励 `long`,全市场,不做中性化;
  - 每轮一次固定的分级 workflow(`workflows/c01_round.js`)。
- **运行记录**:见 `research/coldstart_C01/PLAN.md` 的修订。其中修订 4:把含 `ts_spearman` 的发现从两臂去掉(A 90 个、B 1 个),这条修订偏向 B 臂。
- **结果**:**Partura 更差**。测试段有效 head A 19 个,B 13 个。去掉 `ts_spearman` 后 B 仍没有赢。
- **教训**(写进了 C02 PLAN §1):agent 只能通过「按写法匹配的先验 + 邻域」影响 GP,信念传不过去。

### C02:Partura v2,直接检验假设、设计初始种群

- **问题**:让 LLM 直接检验自己的假设(带对照的变体)、设计初始种群,再让 GP 局部精修,能否胜过 GP?
- **设计**:
  - 环境规则两组相同:奖励 `long`;与已知族 `cross_mean(day_std(Amt), 30)` 的 |ρ| ≥ 0.5 判不合格;
  - 测试段只读一次。
- **结果**:**Partura 更差**。与 C01 heads 不相关的新有效 head:A 7 个,B 2 个。
- **教训**(写进了 C03 PLAN §1):C01、C02 测试段「有效」的 head,做风格中性化后几乎全部消失(C01 两组 19 → 2、13 → 1;C02 两组 7 → 2、2 → 0)。搜索器和 agent 都在优化一个为风格暴露付钱的奖励。

### C03:风格中性化奖励

- **问题**:奖励只为「去掉流动性、波动、反转与已知族之后剩下的东西」付钱时,Partura 能否找到更多有效、新的信号?
- **设计**:残差书奖励(`long_neutral`);16 个种子;发现门槛降到 0.5。
- **结果**:**分不出**。新的有效 head:A 0 个,B 0 个(A 最好的一个 t = 1.98)。Partura 写的机制直接检验全部不过线。
- **教训**:两组都找不到能留下来的东西,于是 C04 扩展了信息集。

### C04:扩展信息集 + 市值控制 + 只做多头腿

- **问题**:两组都能用新的日频字段(LogFloatCap、LogTotalCap、LogFloatShares、LimitWidth、BoardCode、ListAge),奖励再去掉市值暴露,Partura 设计的假设与初始种群能否让样本外残差书更好?
- **设计**:16 个种子(701–716);主指标改为**逐种子融合残差书的测试段净夏普,16 对单侧 Wilcoxon**(C05 起沿用)。
- **结果**:**分不出**。
  - 中位差 B − A = −0.17,p(B 更差) = 0.11;16 对里 B 高 4、低 10、平 2;均值 A +0.02、B −0.20;有效 head A 2、B 2。
  - Partura 的一条禁令禁掉了 A 组后来留到测试段的那一族(发现数 B 53 对 A 173)。
  - 直接检验 0 / 64 过线。
  - 唯一留下的东西是一个**构造**:日收益按涨跌停幅度缩放。它的 14 个后代里 12 个测试段为正、1 个有效;但方向被 GP 改成了与 Partura 写的相反,前推段均值 0.04。
  - LLM 输出 77.9 万 token。
- **教训**(写进了 C05 PLAN §1):在同一预算里让 agent 指挥 GP,agent 的错误会直接挤掉探索。于是 C05 改成 agent 不碰主搜索、只加东西。

### C05:主 AlphaCube 不受干扰,Partura 派任务

- **问题**:同样的额外算力,交给 Partura 去定位—深挖(B),是否好过交给更多的无 agent 搜索(A)?
- **设计**(`research/coldstart_C05/PLAN.md`):
  - **主 AlphaCube(M)**:每种子 4 批;只按自己的历史禁掉结构相同和高相关的;三组共用。
  - **每轮快照** = M 第 1..k 批 + 本组之前的任务;3 轮;每轮每组 256 次评估。
  - **A**:2 次普通 GP。
  - **B**:定位工具(heads 表、子树共性、拆解)→ 结构解剖员 → 文献员 → PI 写任务 → 检查员。任务类型:
    - **E** 深挖:固定一个好结构,只在外面长;
    - **R** 去烂部件:替换原 head;
    - **N** 新想法:写种子。
  - **B0**:同样的工具与任务类型,由死规则代替 LLM。
  - **判读**:每组的库 = M 的 heads + 本组额外 heads(去重:|ρ| ≥ 0.7 或 ≤ −0.5 丢);逐种子等权融合;**主比较 B 对 A**。
- **运行记录**(PLAN 修订 1–14):
  - GPU 显存与锁通道反复调整;面板计算卡在 CPU 还占着 GPU 锁;
  - 排队超时误杀;802 的内存问题,把它搬到第二台服务器;
  - R 替换不能连锁的 bug;第 3 轮被用量上限打断;
  - 判读前的样本内复现核对:543 个 head 里 496 个复现。不复现的已逐个解释:E 的奖励多控制了核心家族,还有 2 条 M 表达式。
  - 都与结果无关,逐条记录。
- **结果**(`research/coldstart_C05/RESULT.md`):**分不出**。
  - 测试段:中位差 +0.08,p(B 更好) = 0.42,B 高 5 / 8;均值 A 0.44、B 0.44。
  - 前推段(只报):A 0.87、B 0.29,B 低 6 / 8,p(B 更差) = 0.039。
  - **挑选期好看,样本外没了**:valid 上 B 1.52、A 0.94(7 / 8 更高)。
  - **B 加的 head 单独看最弱**:测试段有效 B 3 / 94、A 15 / 101、B0 10 / 56;单个 head 测试段夏普 B 0.32、A 0.80、B0 0.69;样本内强度相同(score 1.01 对 1.04)。
    - E:B 0.31、B0 0.65;N:B 0.19、B0 的普通 GP 0.54。
  - LLM 输出 1,321 万 token,101 次 agent 调用。
- **推断**(读过测试段之后,RESULT §4b):
  1. 古德哈特:Partura 更会优化一个有漏洞的奖励(凸变换会重新造出波动;25 个 E 核心里至少 5 个是市值或波动的换个写法);
  2. 研究者自由度:同样的定位信息,LLM 挑的比死规则差。
- **运行中的观察**(`observations.md`):
  - 奖励的凸变换漏洞;
  - 常数经 `_pct_rank` 变成按列序排的斜坡;
  - 定位工具的两处缺陷。这些都由 Partura 的解剖员在样本内指出。

### C06:加独立审计员

- **问题**:同样额外算力,交给「Partura + 审计员」(C),是否好过 A?
- **设计**(`research/coldstart_C06/PLAN.md`):
  - M、A 复用 C05,B5 = C05 的 B 作参照;
  - 第 1 轮复用 C05 的定位、解剖与文献。
  - **审计员**(Opus 5.5)每份计划开跑前打分:
    - 先看确定性的相关度表:与库中 head 的秩相关、与 5 个控制的相关,只用 train;
    - **创新度** 1–5、**合理度** 1–5;两项都 ≥ 3 且剩 ≥ 4 个种子才通过;
    - 与 head |ρ| ≥ 0.7 或与控制 |ρ| ≥ 0.5 的种子自动划掉;
    - 不通过就退回 PI 重写,至多审 3 次,仍不过改为普通 GP。
  - 三处修正:E 奖励不再加家族控制;R 可收录与原 head 不同的好变体;R 替换链走到末端。
  - agent 读 `rules.md`,不读 PLAN(PLAN 里有 C05 测试段的数)。
- **运行记录**(PLAN 修订 1–4,`partura/audit.md`):
  - 相关度表那一步等待超时;子 agent 看到主会话消息,误跳检查;
  - 第 2、3 轮被用量上限打断,逐种子续跑,没丢任何审计结果;
  - 审计员校准的实现改为调用挖掘奖励(读测试段之前)。
  - 48 个任务位最终全部过审;种子接受 474、划掉 147、重写时去掉 34。
- **结果**(`research/coldstart_C06/RESULT.md`):**分不出**。
  - 测试段:中位差 +0.01,p(C 更好) = 0.42,4 胜 4 负;均值 C 0.52、A 0.44。
  - 前推段:C 0.49、A 0.87(C 低 6 / 8,p 0.13)。
  - **挑选期更好看**:train C 1.95、A 1.44(8 / 8);valid C 1.62、A 0.94。
  - C 加的 head:测试段有效 4 / 86;单个 head 测试段夏普 0.32(A 0.80);E 0.09,N 0.42。
  - **审计员校准**:被挡掉的种子样本内与测试段都更好:测试段 −0.53 对放行的 −0.91;24 对里放行的更好只有 3 对,p(放行的更好) = 0.999。
  - LLM 输出 1,691 万 token,222 次调用(其中审计员 38 次)。
- **推断**:判读用的尺子本身在为「控制变量的非线性重写」付钱,审计员按规则把它们挡掉,在这把尺子下就显得更差。病根在尺子,于是有了 C07。

### C07:修好尺子,LLM 只做验证(运行中)

- **问题**:在修好的尺子下,一个只看 train 的 LLM 验证员筛过的因子库(V_tr),样本外是否好过不筛的库(A)?
- **设计**(`research/coldstart_C07/PLAN.md`,开跑前已提交):
  - **新尺子**(奖励与判读都用):
    - 先排序再平滑:单调 / 凸变换是同一个信号;
    - 非线性中性化:对 5 个控制的排名及其平方、三次方取残差,去掉线性、U 形、S 形暴露。
  - **M 与 A 在新尺子下重跑**,不用 LLM;种子 801–808。
  - **验证员**(Opus 5.5):所有 GP 跑完后,对每个种子的候选库(M 的 heads + A 的 heads)逐个决定留或去。
    - 两个版本:**V_tr** 只看 train,**V_all** 再看 valid;
    - 共 16 次调用,每种子每版本一次;规则在 `research/coldstart_C07/rules.md`。
  - **主比较** V_tr 对 A;次比较 V_all 对 A、V_tr 对 V_all(看 valid 会不会让验证员更差)、A 对 M、被去掉与被留下的 head 的样本外表现。
- **局限**(必须讲):
  - 测试段这是第 7 次读,设计用到了 C05、C06 的判读结果,正面结果要打折扣;
  - 新尺子改变了指标,与 C01–C06 不可直接比较;
  - 真正干净的检验是 2026-09-16 之后的新数据。
- **结果**(`research/coldstart_C07/RESULT.md`):**分不出**。
  - 测试段:V_tr 对 A 中位差 +0.11,p(V 更好) = 0.062,4 胜 1 负、3 对相同;均值 A −0.52、V_tr −0.09。
  - 前推段(只报):5 胜 0 负,p 0.031;均值 A −0.22、V_tr +0.14。
  - 新尺子下候选只有 68 个,所有组的测试段融合书都为负。
  - 验证员只留 9 / 68(V_tr)、13 / 68(V_all)。单个 head 上被去掉的反而更好(测试段 +0.40 对留下的 −0.13);书变好主要来自「少放东西」。
  - V_all 不如 V_tr(方向与「看 valid 更过拟合」一致,对数不够,不能判)。

## 4. 横向结论(可以讲的)

1. **主指标上从没赢过**:C01、C02 更差,C03–C06 分不出,C07 待定。
2. **同一个模式反复出现**:Partura 参与的那一组在挑选期(train / valid)最好看,到测试段持平,到前推段落后。
   - 三组从 valid 到测试段都掉大约 1 个夏普:样本内分数本来就预测不了多少。
   - agent 越会优化它,越容易优化到噪声与漏洞上(古德哈特)。
3. **架构上的底线在 C05 守住了**:主搜索不受 agent 干扰,融合书至少不比 A 差。
4. **LLM 真正有用的地方是诊断**:
   - 奖励漏洞(凸变换、列序斜坡、控制换皮);
   - 定位工具的缺陷;R 连锁 bug;
   - 审计员抓到 PI 把 Vwap 当 bar 收盘价的推导错误。
5. **把关也没用**(C06):LLM 审计员按「机制说得通、不重复、不是控制换皮」来挡,挡掉的反而样本外更好。这指向尺子本身的问题(C07 在检验)。
6. **设计含义**(Topic B「怎么设计 agentic alpha 研究员」):
   - LLM 放在验证 / 诊断一侧,不放在押注一侧;
   - 样本外检验对 agent 完全隔离;
