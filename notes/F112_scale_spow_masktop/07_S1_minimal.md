## 这一阶段问的问题

## 一句话答案

**原式是这 11 行里第二差的。** 五个节点里有三个(横截面截尾、峰度通道、带符号平方)对多头腿不是正贡献,

排在 `s1_plain60`、`s1_noMask`、`s1_plain30`、`s1_x241`、`s1_x60`、`s1_noK` **之后**,只赢 `s1_noSpow`、`s1_w10`、`s1_noP`。

## 四条解读

### 1. 截尾节点在帮倒忙,而且是**结构性**的改进(不是平滑的功劳)

`s1_noMask` 在**五档上全部**高于 `v_base` 同档,而换手几乎一样(hl20 6.8% vs 6.6%)。
两者选到的 `hlL` 都是 20,所以主表里 `+3.7% → +7.1%`、`Lshp +0.66 → +1.05` **本来就是同档比较**。
valid 同向且更大(`+5.3% → +9.3%`、`+0.91 → +1.27`)。rIC、rICtraded 也都升。
⇒ H4 的「帮倒忙」分支**已确立**。机制见 `07x_01_a1_channels.md` 与 H10。

**不能过度解读的地方**:`ρ(s1_noMask, v_base) = +0.78`(交易信号)< 0.8,
按 playbook §6 第 3 条,它**不算提纯,是换了一条因子** —— 推荐时必须这么写。

### 2. 窗口和半衰期是**替代品**,真正的参数是「总有效视野」

`s1_plain60` 是全表唯一在 hl10 见顶(`+7.6%`)、hl20 回落(`+6.0%`)的变体;
其它所有变体到 hl20 还在单调上升。这正是「窗口已经把平均做够了,再叠 EMA 就过头」的形状。
反过来 `s1_w10`(窗口 10)在任何半衰期上都救不回来(hl20 仍 `−3.9%`)。

⇒ 原式的问题不是「30 天窗口 + hl20 不够」,而是**两个一起算才到 50 天左右的有效视野,还是短**。
把窗口拉到 60 以后,最优半衰期自己掉到 10。
⇒ 这也解释了 R0 里那个「`Lnet` 一路升到 hl 网格上限 20 还在升」的现象:不是 hl 网格不够,是窗口太短。

**窗口最优在 60 附近,不是 241**:`s1_x241` train `+4.6%` 但 valid 掉到 `+3.3%`。

### 3. 「提纯」会把它推进已知的 20 日反转里;「拉长窗口」才是离开已知暴露的方向

这是本阶段**最有价值**的一条,它改变了候选排序。三个口径一致:

| | `ctl_mom20` 中性化 R² | 中性化后残差 `Lgross` | 原始面板 ρ(`ctl_mom20`) |
|---|---|---|---|
| `s1_plain30` | — | — | **+0.898** |
| `s1_noK` | 0.116 | **−0.7%**(全没了) | +0.781 |
| `s1_plain60` | 0.158 | **−1.8%**(全没了) | +0.731 |
| `v_base` | 0.091 | +1.8% | +0.489 |
| `s1_x60` | **0.040** | **+2.5%**(剩得最多) | +0.443 |
| `s1_x241` | — | — | +0.269 |

而 `ctl_mom20` 自己当因子就有 `Lnet +5.4%/+8.0%`、`Lshp +0.66/+0.87`(`S0_baseline.json` 的
`diagnostics.controls`)—— 与 `s1_plain30`(`+6.7%/+7.9%`、`+0.83/+0.81`)**在噪声内一模一样**。

⇒ `plain30` 看着漂亮(比原式好、换手只有一半、两个节点),但它**就是 20 日反转**,对用户没有新东西。
⇒ 真正值得往下做的是 **mask 去掉 × 窗口拉长** 这个组合:它既拿到了 mask 的那 3~4pp,
   又是全表里最不像 `ctl_mom20` 的方向。**这个组合 `S1_minimal` 没有测**(R1 的设计是一次只动一个节点),
   所以它是 R2 的头号变体。

### 4. 峰度通道和带符号平方:都不是正贡献,但「mask 去掉之后」还没正交开

- 峰度:`s1_noK` 在五档上都 ≥ `v_base`,换手只有 4.0% vs 6.6%,原始面板 rIC 还高一倍 ⇒ H2 被否定。
- 平方:`ρ = +0.97` 近似保序(H3 成立),但删掉它在四档上都更差一点、换手更高 ⇒ 单独删它没有好处。
- **唯一的反向线索**:mask 去掉以后,带峰度+平方的 `s1_noMask`(valid `+9.3%/+1.27`)
  高于都不带的 `s1_plain30`(`+7.9%/+0.81`),差 `+1.4pp/+0.46`(`Lshp` 的差略超噪声)。
  这有可能是真的(mask 在的时候峰度通道被压住了),也有可能只是 valid 的运气。
  ⇒ R2 用 2×2(`s2_f30`/`s2_k30`/`s2_p30`/`s2_n30`)把这两个节点在「mask 已去掉」的前提下正交开。

## 本阶段的意外

1. **一致性检查完全通过**:`s1_x30` 与 `v_base` 在主表、固定半衰期五档、rIC/rICtraded/cov/dist 上**逐位相同**
   ⇒ `cross_scale(d=30) ≡ ts_scale(d=30)`,上一轮主研担心的「内核族标注不同(`dt/cross/rolling` vs `nd/ts/rolling`)
   可能解析不过」没有发生(`check` 22/22 OK)。**窗口阶梯可以放心用 `cross_scale` 取 60/241。**
2. `s1_noP`(只留峰度)在 hl0 的 `Lnet −52.8%`、换手 **75.9%** —— 预注册里预告的 `ts_scale` 的 `EPS` 分母保护
   被触发的样子(`ΣE` 在 0 附近),按预注册**不用于归因**。
3. 结果卡 §2 关于 `s1_noSpow` 的那句散文与同一张表的数字不符(详见 `05_hypotheses.md` H3),表和 JSON 是对的。

## 诊断配置的两条操作事实(下一个人省时间)

- **`profile:` / `neutralise:` 里写别的阶段的变体 id 会被静默丢掉**,不报错:R1 的配置写了
  `profile: [v_base, s1_noK, s1_x60, s1_plain60]`、`neutralise: [v_base, s1_noK, s1_x60, s1_plain60]`,
  而 `S1_minimal.json` 的 `diagnostics.neutralise` 只有 `[s1_noK, s1_x60, s1_plain60]` —— `v_base` 没有。
  ⇒ **想要某个结构的分位剖面 / 中性化,就得把它作为**本阶段**的变体声明一遍**(表达式相同时面板走缓存,几乎不花钱)。
- `conditional:` **可以**写别的阶段的 id(`v_base|ctl_cap` 等三组在 `S1_minimal.json` 里正常算出来了)。
- **固定半衰期表(`books.sweep`)和分位 IC 不受这个限制,每个变体都免费有。**
