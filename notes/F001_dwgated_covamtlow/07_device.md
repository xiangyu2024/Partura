### 设备一致性(H7 的判决性检查)

AlphaCube 的 HANDOFF §8 记录过两件事:CUDA 上分块不变性不成立;`day_durbin_watson` 判"常数行"
用的是 `E[x²] − E[x]² < 1e−8`,在舍入噪声下会翻 NaN。如果这在生产规模上重要,
同一条表达式的 CPU 面板和 GPU 面板就不会一致。实测(全市场 1940 天 × 5220 只,`scripts/cpu_gpu_check.py`):

| 表达式 | 日截面 rank 相关 | 只有 GPU 有值的格子 | 只有 CPU 有值的格子 | 相对差 p50 / p99 | rank IC GPU / CPU | 扣费夏普 GPU / CPU |
|---|---|---|---|---|---|---|
| 原式 | **1.000000** | 393 | 1419 | 2.1e−07 / 8.8e−07 | +0.0540 / +0.0539 | +1.777 / +1.798 |
| `day_durbin_watson(Open)` | 0.999995 | 3241 | 7270 | 7.4e−08 / 2.6e−07 | +0.0411 / +0.0410 | −2.507 / −2.492 |
| `cross_max(day_sum(Amt), 9)` | 1.000000 | 0 | 0 | 0 / 1.7e−07 | +0.0434 / +0.0434 | +2.476 / +2.476 |

**H7 被证伪**:DW 的 NaN 判据确实在两个设备上给出不同结果,但只涉及 **0.01% 的格子**
(1010 万个里的 1 万个),对 rank IC 与扣费夏普的影响在第三位小数。
不含 DW 的表达式(`cross_max(day_sum(Amt), 9)`)则**逐个格子的缺失模式完全一致**。

一个需要记一笔的细节:原式的相对差**最大值是 1.1e+23** —— 存在个别格子的数值来自灾难性相消,
数值本身没有意义。因为交易的是秩不是值,rank 相关仍是 1.000000;但这也是"这条因子的 Pearson IC
不能当真、只看 rank IC"的又一个理由。
