`FAM30` +12.6% / +22.3%(与 `S0_baseline.json` 的 `known_stdamt_mean30` 逐位一致)、`FAM9` +13.7% / +22.2%(同)。

## 问题

用户做 A 股纯多头,已经有 `cross_mean(day_std(Amt),30)`(测试段多头腿净超额 +13%~+15%、纯多头夏普 1.4~1.9)。
这条因子对那本多头书**有没有增量**?x1 只给了第一眼(加 0.3 份「只留爆炸日」+1.1 个点),缺配对差、标准误、残差多头腿。
事前判据(`05_hypotheses.md` H14):配对差 \|t\| < 2 → 增量在噪声内;
**t ≥ 2 且增量 ≥ +2 个点且 train/valid 同向 → 「排除事件票」这个用法是真的,带进留出段。**

## 三个面板

`BASE` = 原式的 numpy 重构;`REG` = 只留规则日(两侧分位数都不退化);`EVT` = 只留爆炸日(\|gap_d\|>20 的日子留值,其余记 0,再取 20 日 nanmean)。
各自的两本书:`BASE` −4.7%/+0.3%(hl20)、`REG` −0.7%/+3.5%(hl20)、`EVT` −3.5%/−3.3%(hl0,多空 +3.45/+3.39)。

`EVT` R² 0.005/0.009,残差 −14.4% / −14.7%(sign 翻成 +1)。

## 解读

1. **原式本身对家族是负增量,而且是显著的负。** 加 0.3 份原式,配对差 −2.0% / −2.4%(t −2.64 / −2.52);
   加 1 份 −4.4% / −3.3%。规则版 `REG` 一样(−1.8% / −2.4%)。
   两段同号、t 都过 2 —— **「加进去会把家族的多头腿拖坏」这件事是坐实的**,不是噪声。
   机制清楚:它的多头端本身是坏的(Q10 翻转),把它掺进家族的排序就是把坏名字换进前 10%。
2. **残差多头腿是零。** 对家族取残差后 `BASE` −0.3% / −0.0%、`REG` +0.5% / −0.7%。
   R² 只有 0.01~0.02(两者几乎正交,rank 相关 −0.03),所以残差 ≈ 原式自己 —— 而原式自己没有多头腿。
   **正交但没有多头腿 = 对纯多头的人没有价值。**(正交本身不是优点,这是本因子最该记住的一条。)
3. **唯一正向的一块是「事件记忆」,而且它的量级低于事前写死的门槛。**
   `FAM30 + 0.3·EVT` 是九个组合里唯一在 train 与 valid **同时**显著为正的:+1.0% / +0.8%,t +3.27 / +3.03。
   方向、量级两段几乎一样,这不是噪声。
   **但事前判据要的是「t ≥ 2 **且** 增量 ≥ +2 个点」,实测 +1.0% / +0.8% 只有门槛的一半 → 判据没过。**
   我按事前写死的判据执行:**H14 成立(增量在实质性门槛之下),这一块不升级为推荐、也不带进留出段。**
   (这是刻意的纪律选择,不是漏看。理由另见第 5 条;后续怎么追写在 `12_next.md`。)
4. **机制读得通,形状也对。** 家族的多头十分位里 1.94%~6.78% 的格子是近 20 日封过板的票,
   而这类票次日起年化跑输 −35% ~ −56%(x1 的事件研究)。把它们换掉:train +3.5%(t +2.68)、valid +0.6%(t +2.13)。
   `w` 的邻域是一个**驼峰**:w=0.1 太弱(+0.2%)、w=0.3 顶点(+1.0%)、w=1 又回到 0(+0.1%)——
   因为 `EVT` 自己的多头腿是 −3.5%,掺多了反而拖。驼峰是**理论预期的形状**,不是调参痕迹;
   但顶点只有 +1 个点,而两段的量级差 3.5 倍(占比 6.78% vs 1.94%,剔除收益 +3.5% vs +0.6%)——
   **增量的大小取决于那一段里封板票有多密**,这不是一个稳定的参数。
5. **为什么不为这 +1 个点再花一次运行**:(i) 事前判据明确没过(+1.0 < +2);
   (ii) 它现在只有 numpy 口径,`EVT` 还没有引擎表达式,要带进留出段就得先建表达式、再确认它复现 numpy 的 −3.5%/−3.3%,
   这是一次运行 + 一轮;(iii) 它改进的是**家族**,不是这条因子 —— 把它写成结论会把「F109 分辨」讲成「F109 有用」,
   归因就错了;(iv) 留出段只能读一次,5 个候选位要留给能**推翻主结论**的东西。
   → 它写进 `09_diagnosis.md` 的「已确立」(数字和 t 都在),同时写明「低于事前门槛,未推荐、未在留出段上验证」。

## 口径上的两处要注意(接手的人别踩)

- **(a) 那张残差表和引擎的 `diagnostics: neutralise` 不是同一件事**:引擎那张只对已经定好方向半衰期的交易信号中性化、
  只看 fit 段、残差不再平滑;x2 这张是把残差当一条全新因子从头走一遍(重新定方向、重新定半衰期、两段都算)。
  两张表不要互相当一致性检查。`EVT` 残差 −14.4%/−14.7%(sign 翻成 +1)就是这条流水线作用在一张 93% 是 0 的面板上的产物,
  **不可解读**,执行在结果卡里也标了「只报数字,不猜原因」。
- **(b) `EVTFLAG` 用的是 `THR=1e-4` 的近似退化判据**,不是严格浮点 `==0`;执行在结果卡里问过这件事。
  严格 `==0` 会让占比数字变小(x1 实测 `q95==0` 0.72%、`q05==0` 0.79%、\|gap_d\|>20 0.49%)。
  我的答复:**近似口径是对的**,因为 `REG` 的 NaN 条件与 `EVTFLAG` 的旗标条件必须是同一件事,才能让 (b)(c) 两张表自洽;
  而且 1e-4 ≈ 一个 tick,正是「分位数为 0」在浮点里的现实边界。占比的绝对值因此略高,**不影响配对差和 t**。
