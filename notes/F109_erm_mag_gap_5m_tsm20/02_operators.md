读源码(`study.sh src`,12 个算子逐个读过)时记下的、探针表里看不出来的事。凡是能量的都在 x1 里量过一次。

1. **`in_delay(Close, 5)` 不跨日**。内核按「每股票-日一行、241 列分钟」平移,每天的前 5 根是 NaN。所以 5 分钟收益
   `Close / in_delay(Close, 5) − 1` 每天只有 236 个值,开盘第一根不会和昨收比。
2. **`day_quantile(Ret, 0.95)` 是 `torch.nanquantile`(线性插值),但在这里没有插值**。`Ret` 的第一根恰好是 0
   (x1 实测:100% 的股票-日,等于首根收盘 / 首根开盘 − 1,**不含隔夜**),所以 241 根全有值,0.95 分位落在整数位置
   (0.95 × 240 = 228,即第 229 小的那一根)。它是一个顺序统计量:**只要全天上涨的分钟不超过 12 根,`q95` 就恰好是 0**;
   否则至少是一个 tick 的收益。x1 普查:`0 < q95 < 1e-4` 的股票-日占比是 0.0000。
3. **`is_gt` / `is_lt` 返回整型 0/1,NaN 参与比较得 0**。每天前 5 根(r5 为 NaN)既不进计数也不进求和;
   `select_where(mask, r5, 0)` 在 mask 为 0 的地方填 0,所以 `day_sum` 加的只是超阈分钟。
   `create_like(Close, 0)` / `create_like(Close, 1)` 的字面量是整数,生成的是 int64 张量,由 `torch.where` / 减法自动提升成浮点 —— 没有副作用。
4. **四个 `1e-06` 干的是两件不同的事**:
   - 计数分母上的两个(`add(day_sum(mask), 1e-06)`):只在「一次都没超过阈值」的日子起作用,把 0/0 变成 0。
     x1:这样的股票-日上侧 0.43%、下侧 0.61%,就是全天一个价的一字板。
   - 分位数分母上的两个(`add(q95, 1e-06)`、`add(abs_(q05), 1e-06)`):**这是整条因子的开关**。分位数恰为 0 时,
     这一侧的比值 = 超阈均值 / 1e-6,从 O(1) 跳到 10³~10⁵。
5. **阈值和分子不在同一个时间尺度上**。阈值、分母是 **1 分钟**收益的分位数,分子是 **5 分钟**收益超过这个阈值的部分的均值。
   它不是教科书里的 ES/VaR 比(那是同一个分布的尾部均值除以分位数):规则日每侧有约 34~37 根 5 分钟收益超阈(236 根里的 15%,而不是 5%),
   比值的中位数是 1.88 / 1.76(高斯随机游走下约 1.8)。
6. **`ts_mean(·, 20)` 与 `cross_mean(·, 20)` 是同一个内核**(`rolling_reduce` + `nanmean_last`,左侧补 NaN,因果)。
   nanmean 不截尾:窗口里有一个 10⁴ 量级的日子,它就占 Σ\|gap_d\| 的 99.9%(x1)。停牌日 `Ret` 全 NaN → 当日值 NaN,被 nanmean 跳过。
7. `abs_` 只出现在下侧:把下尾的 5 分钟收益和 `q05` 都翻成正的幅度,所以 `dn_ratio` 与 `up_ratio` 同为正数、可以相减。
   它不是空操作(去掉它下侧比值的分子分母都变号,比值不变,但 `add(q05, 1e-06)` 的 ε 方向会错)。
