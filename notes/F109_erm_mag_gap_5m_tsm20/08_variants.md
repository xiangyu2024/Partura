等于在推荐别人的因子,超出本研究范围(`12_next.md` 末尾)。

**作废的 tag:`S1_S2`**(exit 97,没有 JSON)。不要 `wait`、不要 `digest`。
失败原因是**邻居**把容器撑到 37.2 GiB、守卫让路(本进程只 3.9 GiB),不是本因子的问题;

## 2. 哪些变体其实是同一棵树(逐字节相同)

`S_final` 的 5 条**全是旧树换了个 id**(表达式由脚本整行拷贝、写盘后逐字节断言过,`results/R2.md` 第 2 步):

| `S_final` 的 id | ≡ 哪一条 | 交叉核对 |
|---|---|---|
| `f_orig` | `S0_baseline/v_base`(**原式**) | 与 `v_base` 的 rank 相关 **+1.00**;train 数字逐位相同 |
| `f_sig` | `S1_nodes/a_sig` | train −/+2.27% 与 `S1_lvl.json` 逐位相同 |
| `f_sum` | `S1_nodes/a_sum` | 同上 |
| `f_lvl` | `S2_level/b_lvl` | 同上 |
| `f_fam30` | `gates.known_stdamt_mean30` = `cross_mean(day_std(Amt), 30)` | 写盘前脚本断言逐字节相等;train/valid 数字与 `S0_baseline.json`/`S1_lvl.json` 的 `known_stdamt_mean30` 行逐位相同 |

⚠ `study.sh check` 只对前 4 条打印了 "is the same tree as ..." 提示,`f_fam30` 没有 ——
因为检查器比对的是「新变体 vs 配置里其它 **variants**」,而 `f_fam30` 对应的是 `gates` 字典里的条目,不在 `variants` 之列。
**不是没核对过**(见上表最后一行)。

同族关系(与 `v_base` 的 fit 段 rank 相关,|.|≥0.95 算同一因子族):
`a_eps3` +0.75、`a_1m` +0.72、`a_up` +0.72、`a_q5` +0.68、`a_sum` +0.56、`b_skew5` +0.53、`a_sig` +0.50、
`a_evt` +0.42、`b_lvlq` +0.44、`a_dn` +0.15、`b_lvl` +0.12。
→ **没有一条达到 0.95**,所以严格说它们都不是「同一条因子的另一种写法」;
但 `a_sig`/`b_lvl` 与原式只有 0.50 / 0.12,**低于 0.8** ——
按审查的规矩,**它们已经不是原式的提纯版,而是另一条因子了**,这也是本研究不把它们当提纯产物的一个独立理由。

## 3. 总表有两组「train 表现」,别混着读

1. **自选半衰期的两本书**(每条变体各用自己最优的 hlL / hlS):回答「这条写法最好能到多少」。
2. **固定半衰期表(hl 0 / 2 / 5 / 10 / 20)**:回答「**结构**谁更好」。
   **比结构必须用这一组** —— 否则会把平滑(半衰期)的功劳写成结构的。
   例:`a_sig` 自选 hl20 是 +2.3%,但在 hl 0 上是 **−10.4%**;原式在 hl 0 上是 −13.5%。
   两条在 hl 0 都很烂,`a_sig` 的优势只有 3 个点,**不是**自选口径看起来的 7 个点。

## 4. `f_lvl` 的半衰期在两种口径下不一样(唯一一条)

| | train-fit(`books`) | utrain-fit(`books_user`) |
|---|---|---|
| `f_lvl` hlL | **5** | **3** |
| `f_lvl` hlS | 0 | 1 |

其余 4 条候选的 hlL / hlS 在两种口径下完全相同。

而判据 G 那张表是 train-fit(`f_lvl` 用 hlL=5)。**这两张表里的 `f_lvl` 不是同一个口径,不要混着读。**

## 5. ⚠ 多空数字有**两套**,`results/R2.md` 第 3 节那张表的标签是错的

`S_final.json` 里同一条候选有两个多空读数,来自两个不同的半衰期:

| 来源 | 在哪个半衰期上 | 举例:`f_orig` utrain / holdout |
|---|---|---|
| `books_user.splits[*]['ls_sharpe']` | **hl_used = hl_long**(因为 `rank_by: long`,所以是 hlL=20) | +1.784 / +2.261 |
| `books_user.by_rank['ls'].splits[*]` | **hlS**(多空自己的最优,=1) | **+2.766 / +2.276** |

`study.sh digest` 的「与用户表同口径」表打印的是**后者**(hlS 口径),这也是**用户最早那张表的口径**
—— 用户表给的 2.77 对应的就是 `f_orig` 在 hlS=1 上的 +2.766。

**`results/R2.md` 第 3 节的表头写着「hlS(utrain 定)」,但数字抄的是前者(hlL 口径)。**
hlS = hlL 的两条(`f_fam30` hlS=hlL=0)碰巧对得上,其余三条差很多
(`f_orig` 1.784 vs 2.766、`f_sum` 1.654 vs 2.712、`f_sig` 2.134 vs 2.475)。
**权威数字(hlS 口径,引多空一律用这组)**:

| 候选 | hlS | LS utrain | LS holdout | 空头腿毛超额 utrain | 空头腿毛超额 holdout |
|---|---|---|---|---|---|
| `f_orig` | 1 | +2.766 | **+2.276** | +32.71% | **+32.86%** |
| `f_sum` | 0 | +2.712 | +1.974 | +37.09% | +37.27% |
| `f_sig` | 1 | +2.475 | +1.957 | +41.47% | +43.42% |
| `f_fam30` | 0 | +2.334 | +1.942 | +24.73% | +24.93% |
| `f_lvl` | 1 | +1.390 | +0.891 | +24.90% | +22.47% |

(验证方法:`S_final.json` → `results['f_orig']['books_user']['sweep']`,7 个半衰期的第 2 项
`ls_sharpe = 2.7663`、最后一项 `ls_sharpe = 1.7845`、`long_ann = −0.0321`。)

## 6. 其它读表的坑

1. **中性化表只能看毛超额和残差 rIC。** 残差不再平滑,换手从 2% 跳到 13~43%,净超额只是被成本吃掉
   (`digest` 自己印了这句话;`07_neutralise.md` 第 4 条列了不能引用的行)。
2. **`x2_incremental` 的残差表 ≠ 引擎的 `neutralise` 表。** 一个是把残差当新因子重走流水线(两段都算),
   一个是对已平滑的交易信号、只看 fit 段。**不要互相当一致性检查。**
   其中 `EVT` 的残差 −14.4% / −14.7%(sign 翻成 +1)**不可解读**。
3. **留出段没有分位剖面。** `profile` 只在 train/valid 上算,别去 `S_final.json` 里找。
4. **`ic_user` / `ic_holdout` 没有 `rank_ic_traded` 字段**,只有 `splits.train` / `splits.valid` 才有。
   所以「平滑后交易信号的 rank IC」在 utrain / holdout 上**不存在**,不是漏抄。
5. **`by_year` 里 `f_lvl` 2020 / 2025 两年的 `long_share` 是退化值**(−218.68 / −157.48):
   那两年多头腿与空头腿毛超额几乎相互抵消(分母 ≈ 0.02%),比值被放大几百倍。
   **别把这两个数当「份额」用**;`Lnet` / `LS` 本身不受影响。
6. **`cov` / `dist` 门槛**:5 条候选全部 cov ≥ 0.999、dist ≥ 0.999,没有卡线的。
   全研究只有 `a_evt` 没过 dist(**0.0153** < 0.5)—— 它只能当诊断用,不能当候选。
7. **rIC 和赚钱脱钩,这条因子身上到处是例子**:留出段 rIC 最高的是 `f_sig` **+0.0579**(高于家族 +0.0503),
   它的多头腿是 **−2.33%**;`b_lvlq` 的 train/valid rIC 全场最高(0.0485 / 0.0686),多头腿 **−4.1%**。
   **选拔只看多头腿(`rank_by: long`,hlL / Lnet / Lshp),不要被 rIC 和多空夏普带着走。**
