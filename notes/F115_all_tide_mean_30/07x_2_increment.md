## 问题

四件事,脚本 `studies/F115_all_tide_mean_30/increment.py`(tag `x2_increment`)一次做完:
(0) `Study.books`/`Study.signal` 能不能钉住半衰期,回答工单明确要求的环境问题;

## 解读


(第 3 轮主研,Opus 5。完整裁决见 `05_hypotheses.md` 的「R2 裁决」一节;这里只写这四件探针自己的读法。)

### 1. (1) 权重曲线:判据命中「H6 被支持」,但量级要诚实写

两条曲线在 valid 上都严格单调下降、`w=0` 全程最高 → 命中工单「H6 被支持」那一行。
**但不要写成「掺进去有害」**:`w ≤ 0.25` 处的下降量(`Lnet` −0.3 ~ −1.9pp、`Lshp` −0.004 ~ −0.17)
**本身就在噪声带内**(±3pp / ±0.3),单看任何一个 `w` 都说不出显著性。能确立的是**没有可测的正增量**,
依据是三件事叠加:(a) 点估计在 5 个步长上单调向下,(b) 两条互相独立的 `X` 给出同一走向,
(c) 到 `w=0.5` 的 −4.7pp 才超出噪声带。正确的句子是:**「掺进去拿不到增量」,不是「掺进去会亏」。**

train 列不单调(`X=O` 在 `w=.10`、`X=P` 在 `w=.25` 各高出 0.07 / 0.21pp)也要照实说:
那正是噪声的量级,和 valid 的单调下行并不矛盾 —— 反而说明 valid 的下行(到 −22pp)不是噪声。

### 2. (1) `auto` 与 `pin(hl=0)` 全 12 格逐数字相同:这是**好消息**,不是异常

`fit_halflives` 对每个 `blend` 重新 sweep 之后自己也选 `hl=0`,所以权重曲线里**不含「二次平滑」这个
混淆变量**:曲线的升降只来自 `w`。工单担心的「二次平滑代价」不存在,所以这条曲线可以直接当 H6 的
判据用,不需要再做对照。(机械原因:两条腿各自已按自己的 `hlL` 平滑过,K30 本来就是 30 日均值。)

### 3. (2) 残差:落在工单那张表**没有列出**的第三种情形 —— rIC 保住、毛多头腿翻负

6 组(2 个 X × 3 组控制)无一例外:残差 rIC 两段都正(+0.0076 ~ +0.0225),残差 `Lgross` train 全正、
**valid 全部为负**(−2.16% ~ −5.03%)。工单只写了「`Lgross`+rIC 都保住 = 成本效应」和
「两者一起塌 = 已知家族的影子」。实测的第三种情形该这么读:

> **去掉已知家族之后,秩空间还剩一点单调信息,但那点信息不在多头端。**

这和 R1 已确立的「分位剖面顶端不单调(Q10 < Q9)」是同一件事的两种测法 —— 用户只能买 Q10,
所以「rIC 还是正的」对他没有用。**注意不要**按 playbook §1 的常规读法把这里写成「成本效应」:
翻负的是 `Lgross`(毛),不是 `Lnet`(净),成本解释不了。
`rank_corr(resid, K30) = −0.02 ~ −0.03` 说明中性化本身干净,残差确实正交。

### 4. (3) H9 被否定,但它的**镜像**成立 —— 这是本轮最该进报告的一句话

`short_gross` 在两套标签下几乎不动(26.10 → 27.20 / 27.06 → 26.97),`LS` 只掉 0.03 / 0.06
→ **用户原表里 `LS 2.29` 不是「买不进的票」撑出来的**,这个常见陷阱在这条因子上不成立,干净排除。
动的是多头腿:`buyable=True` 把次日开盘涨停锁死的票**整格丢掉**(`panels.py` 里是置 NaN,不是置 0),
而这条因子的多头端里有一批这种票;把它们算回来,毛多头腿掉 1.4pp / 0.6pp,
**valid 的 `long_net` 从 +0.25% 翻成 −0.39%**。
→ 报告里的说法:**这条因子 valid 段的多头腿小到可以被一个标签约定翻号**;+0.2% 与 −0.4% 是同一个零。
(别把这条写成「用户的标签口径有问题」—— `buyable=True` 是用户自己的口径,也是更接近实盘的那一个:
买不进就不买。这里量的是「这个零有多脆」。)

### 5. (4) H7b 的反推被直接数字确认 → 「成本常数 30bp / 单位 `LTO`」这件工具可信

直接打印的 `Lgross` 与 R1 用成本常数反推的值逐档相差 ≤0.3pp。以后 digest 不打印 `Lgross` 的地方
(固定半衰期表)都可以放心反推,**不必为它再花一次服务器运行**。
同时 `Lnet` 的峰值确实在 hl=10(−6.15 / +1.58 / +3.86 / **+5.57** / +4.57%),H7 不是被低估的结果。

### 6. (0b) 工具缺口的处理方式是对的,记一笔给后面的人

`by_year` 只对「本次 run 传的那个 stage 自己的变体」生效,跨阶段 id 静默跳过(`corr_ids` / `corr_with`
不受此限)。执行没有为此多花一次服务器运行,而是用 runner 自己那套 `bk.book_row` 按年切片在脚本里补算,
并先在合成数据上自检 —— **这是正确的取舍**(逐年表是 J1 的先验来源,值得补;但不值得一次运行)。
留出段那一次如果也要逐年表,记得 `by_year` 必须列 `S_final` 自己的变体 id。
