## 解读

(第 2 轮主研写。这个脚本的产出改写了这棵树的机制读法,是 R1 两件事里信息量更大的那一件。)

### 1. 「潮宽」不是一个有信息的量,它是被窗口两端夹出来的近常数

`04_grammar.md` §4 的推断是:平静日潮顶 `D` 贴窗口左端 → `M` 很大;只有中段放量脉冲时 `D` 跑到中间
→ `M` 变小。实测结果是**一半对、一半错**:

- 对的那一半:`D` 确实到处跑(p25 = 12、p50 = 51、p75 = 124),潮顶的位置是个真变量;
- 错的那一半:`I` 几乎总是贴左端(p1/p5/p10 全是 0、p50 = 22)、`F` 几乎总是贴右端
  (p50 = 143、p90/p95/p99 全是 180)。**两个谷几乎总是分得很开**,于是
  `M` 的 p1/p50/p99 = **24 / 95 / 177**,`M ≤ 20` 只占 0.61%、`M ≤ 10` 只占 0.05%。

机制上讲得通:在 10:01–14:31 这个窗口里,A 股成交量是「前段衰减 → 午休见底 → 尾盘回升」,
所以不论潮顶落在哪儿,它左边的最低点总在开头附近、右边的最低点总在午休或窗口末端附近。
**`argmin` 找的是"最低",而日内量能曲线的最低点天然靠两头** —— 这是这棵树最重要的一个机制事实。

### 2. 由此 `÷M` 在秩空间接近恒等变换,H2 和 H3 一起死

`M ≈ 95` 近常数 → `N = L/M ≈ L/95`。实测 `rank_corr(N, L) = +0.9582`、
`rank_corr(O, cross_mean(M,20)) = +0.0096`。所以:

- H2(它是成交量形状因子)**被否定** —— 几何通道与成品因子正交;
- H3(多头端被 `1/M` 的重尾污染)**被否定**,而且**假设的前提本身是错的**:预言的重尾不存在。
  直接检验也是平的(按 `O` 分桶,Q1/Q5/Q10 的 `median(M)` = 94/95/94,全样本 p50 = 95);
- 并且这解释了 `S1_anatomy` 里 `a_no_rate ≈ v_base` 为什么会发生 —— 不是巧合,是结构上必然。

`M = 0 → N = NaN` 的推导被精确证实(那 2 个格子 100% 对上),但 2/3,510,125 没有任何解释力,
在报告里只值一句脚注。

### 3. 随机游走标度(`N ~ σ·M^(−1/2)`)在数据上也不成立

`04_grammar.md` 性质 3 预言 `abs(N)` 与 `M` 应当强负相关,实测 `rank_corr(abs(N), M) = −0.1909`
—— 同号但弱得多。原因同上:`M` 的变化范围太窄(p1→p99 只有 24→177,不到 8 倍),
标度关系没有足够的杠杆显现出来。所以「`N` 的噪声随 `M` 变小而放大」这条读法应当从假设空间里划掉。

### 4. 它在动量轴上,这是全部变量里最大的那个暴露

原始面板 `rank_corr(O, ctl_mom20) = +0.4397`,是 x1 量的 7 对里最大的一项,也与 digest 的
`corr_with` 排序一致(06 §10 (a):`ctl_mom20 +0.44` 居首)。配合 `04_grammar.md` 性质 4
(成品 = `cross_mean(带符号日内收益, 20)`、方向 −1)—— **语法和数据都指向「20 日反转」**。
`ctl_ivol +0.2377` 是第二位,与 `÷M` 带来的波动标度无关(见第 3 条),更可能来自
「日内涨跌幅本身与日内波动同向」这个平凡关系。

### 5. 两套 rank 相关口径的符号相反是定义导致的,不是异常

`sig = sign × EMA(O)` 而 `sign = −1`,所以任何变量与 `sig` 的相关 ≈ −(它与 `EMA(O)` 的相关)。
三对数字(`known_stdamt_mean30` +0.1705 → −0.2596、`ctl_ivol` +0.2377 → −0.2098、
`ctl_mom20` +0.4397 → −0.2223)与 `S1_anatomy` digest 自己打印的两位小数对得上,
这是两条独立路径的交叉验证 → **脚本可信,`st.signal`/`st.rank_corr` 的用法和引擎内部是同一个东西**。
报告里引用相关系数必须注明口径(R0 结果卡把这件事记成「异常」,其实是口径问题)。

### 6. 自检通过的意义

`st.ic(O,'train')['rank_ic'] = +0.0374` 与 `S0_baseline` 的 `rIC tr` 完全一致,
而且字符串自检确认脚本自拼的六条表达式组装回来与配置里的 `expression` 逐字符相同 ——
所以 `D/I/F/M/L/N` 这六张面板**就是**原式内部的那六个中间量,不是近似重建。
这一点让上面所有分布数字都可以直接当成原式的内部结构来引用。
(注意 `st.ic` 返回的 `rank_ic` 是对齐过方向的量级,不是带符号的原始 IC —— `sign = −1` 与
`rank_ic = +0.0374` 同时成立,不矛盾。)
