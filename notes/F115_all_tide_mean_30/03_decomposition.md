# SSA 分解表之外需要说明的

`./scripts/study.sh decompose F115_all_tide_mean_30` 给出的 SSA 分解表(15 个去重后的中间量
`A..O`、节点数 59、深度 11、用到字段 Close/Volume)照抄见 `handoff` 的工具输出,这里不重复整张表,
只写表外需要的四件事:量纲/取值范围、重复子树、累计回看天数、恒等检查。变量名与 `01_expression.md`
一致。

## 1. 每个中间节点的量纲和取值范围

| 节点 | 算子 | 量纲 | 取值范围(由构造/公式推出,不是面板实测) |
|---|---|---|---|
| `A` | `in_slice(Close,31,211)` | 价格(Close 的单位) | 该股票当天第 31~211 根(局部 0..180)的收盘价,> 0 |
| `B` | `in_slice(Volume,31,211)` | 成交量(Volume 的单位) | 同一 181 根窗口的成交量,≥ 0 |
| `C` | `in_local_mean(B,5)` | 同 `B`(成交量) | `B` 的 9 分钟居中平均,≥ 0,比 `B` 更平滑(局部极值被削掉一部分) |
| `D` | `day_argmax(C)` | 无量纲(局部分钟下标) | 整数值(float 存储)∈ `[0,180]`;`C` 整行缺失时为 NaN |
| `E` | `in_slice_to_end(C,D)` | 同 `C` | 下标 ≥`D` 部分同 `C`,其余 NaN |
| `H` | `in_slice_from_start(C,D)` | 同 `C` | 下标 ≤`D` 部分同 `C`,其余 NaN |
| `F` | `day_argmin(E)` | 无量纲(局部分钟下标) | ∈ `[D,180]`(`E` 的有效区间下界是 `D`) |
| `I` | `day_argmin(H)` | 无量纲(局部分钟下标) | ∈ `[0,D]`(`H` 的有效区间上界是 `D`) |
| `G` | `day_locate(A,F)` | 同 `A`(价格) | = `A` 在局部下标 `F` 处的值,即原始第 `31+F` 分钟的 Close |
| `J` | `day_locate(A,I)` | 同 `A`(价格) | = `A` 在局部下标 `I` 处的值,即原始第 `31+I` 分钟的 Close |
| `K` | `sub(G,J)` | 价格差 | `G − J`,可正可负 |
| `L` | `div(K,J)` | 无量纲(涨跌幅) | `(G−J)/J`;量级与日内振幅(`ctl_range`)同阶,理论上无固定上下界 |
| `M` | `sub(F,I)` | 无量纲(分钟数) | `F − I`,**恒 ≥ 0**(证明见下),∈ `[0,180]` |
| `N` | `div(L,M)` | 无量纲("每分钟涨跌幅") | `L/M`;`M=0` 时 `0/0 = NaN`(IEEE754,不是 0 也不是 inf,见下) |
| `O` | `cross_mean(N,20)` | 同 `N` | `N` 的 20 交易日因果滚动均值;因子最终输出 |

**`M = F − I ≥ 0` 是构造保证的,不依赖具体数据**:`I` 取自 `[0,D]` 区间上的 `argmin`,`F` 取自
`[D,180]` 区间上的 `argmin`,所以恒有 `I ≤ D ≤ F`,从而 `M = F − I ≥ 0`。

**`M = 0` 的退化情形**(`F = I`,从而必有 `F = I = D`,因为 `I ≤ D ≤ F`):这时 `G = A[F] = A[D]`、
`J = A[I] = A[D]`,所以 `G = J` 精确成立 → `K = 0` 精确成立 → `L = K/J = 0/J = 0`(只要 `J ≠ 0`,
即收盘价不为零,A 股正常情形下恒成立)→ `N = L/M = 0/0`。按 IEEE754 浮点规则,`0.0/0.0` 结果是
**NaN**,不是 0、也不是 `±inf`——这是从算子源码(`sub`/`div` 都没有除零保护,见 `02_operators.md`
第 8、9 节)机械推出的边界行为,不是对实际发生频率的估计(需要跑数才知道多常见,这里没有跑)。
`M = 0` 要求 `C` 的后半段最小值恰好落在峰值 `D` 本身(或前半段最小值恰好落在 `D` 本身)——只要那
一半区间不是整段都等于全局最大值(即非平坦),这在逻辑上是不可能的:全局最大值不可能同时是某一
半区间的最小值,除非那一半区间是常数。换句话说,`M = 0` 只会在"成交量平滑曲线在峰值所在的那一侧
完全走平"这类退化情形下出现。

**价格尺度和成交量尺度都被消掉了**:`L = (G−J)/J` 是 Close 的比值,价格水平(整体乘一个常数)
不影响 `L`;而 `D`、`F`、`I`(从而 `G`、`J`、`K`、`L`、`M`、`N`)全部只依赖 `C` 的**局部极值出现
在哪个位置**,不依赖 `C`(从而 `Volume`)的绝对量级——把 `Volume` 整体乘任意正的尺度(换算单位、
不同股票成交活跃度不同)不会改变 `D/F/I` 的位置,因而不会改变 `O` 的值。这是从 `day_argmax`/
`day_argmin` 齐次度 k=0(见 `02_operators.md` 第 3、5 节实测)直接推出的机械事实,不是对"因子是否
含成交额信息"的判断——这条因子最终测出来的、与 `ctl_amt`/`known_*amt*` 系列的 rank 相关(见
`06_baseline.md`)另有实测数字,两者要分开看。

## 2. 重复子树

SSA 去重后共 15 个中间量(`A` 到 `O`),按被下游引用的次数:`C`×3(被 `D`、`E`、`H` 各引用一次)、
`A`×2(被两次 `day_locate` 引用)、`D`×2(被 `E`、`H` 引用)、`F`×2(被 `G=day_locate(A,F)`、
`M=sub(F,I)` 引用)、`I`×2(被 `J=day_locate(A,I)`、`M=sub(F,I)` 引用)、`J`×2(被
`K=sub(G,J)`、`L=div(K,J)` 引用)。整棵树围绕 `C`(平滑后的成交量曲线)和它的峰值位置 `D` 反复
复用,`F`/`I`/`G`/`J` 又各自被用两次(一次用于算"潮前/潮后谷之间的价格差",一次用于算"潮前/
潮后谷之间隔了多少分钟")。引擎按表达式内容缓存面板,这些重复引用在实际求值时不会被重复计算
(`docs/study_playbook.md` §2);这里列出的是**结构上**的复用关系,不是计算成本。

## 3. 沿路径累计的回看天数

全树只有一个日轴(D 轴)窗口——最外层 `cross_mean(N, 20)`;其余全部算子在分钟轴(M)或逐元素上
操作,不跨日,回看天数为 0。所以沿路径累计的日轴回看 = **20 天**,与 `decompose` 工具报告的
"日轴最大单窗口 20 天;沿路径累计的真实回看 20 天"一致——这棵树只有一层日轴窗口,"取最大值"
与"路径累加"在这里给出同一个数(两者只有在链式叠多层 `cross_*` 时才会不同,这棵树没有那种结构)。
`configs/F115_all_tide_mean_30.yaml` 里 `warmup: 60 ≥ 20`,足够覆盖。

## 4. 恒等或近似恒等节点检查

树里带窗口参数的算子只有两个:`in_local_mean(·, d=5)`(实际窗宽 `2d−1=9`)和 `cross_mean(·, 20)`。
**没有 `d=1` 或窗宽退化为 1 的情形**,所以没有"窗口为 1 的滚动算子"这类近似恒等节点。
`day_argmax`/`day_argmin`/`day_locate`/`in_slice_to_end`/`in_slice_from_start` 都不是滚动算子
(无窗口参数),它们在同一个长度不变的 181 列上"保留部分列、其余置 NaN"或"抽取一个值",改变的是
形状或只保留一个标量,不是恒等变换。`in_slice(·,31,211)` 本身是一个固定的、与数据无关的裁剪
(字面量参数,不依赖任何可调窗口),不属于"窗口参数退化为 1"意义上的恒等,但也不对数值做任何
变换(裁剪前后被保留部分的数值不变)——这是裸事实,不是说它"没有作用"(它改变了参与后续计算的
列范围)。结论:**这棵树里没有数学上恒等或近似恒等的中间节点**。
