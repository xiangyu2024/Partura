**先说留出段的流程(修订时加的说明)。** 留出段在整个研究里只读了一次(S_final 那一笔,5 个表达式;台账里 holdout 的读取次数是 1)。审查之后的修订**没有再读留出段**:
下面新增的「半衰期按纯多头规则定」那张表,数字来自同一次 final 运行当时就写进 `runs/.../final.json` 的 `books_user.splits_at_hl_long`,不是新的读取;修订的两次补充运行只用 train / valid。
读前定下的推荐(`f_max30`)没有因为留出段的数字改动过。流程上有两处瑕疵,无法撤销,照实写在这里:

1. **关于「平台」的读前判据有两条,互不一致。** 原研究按宽松的那条(三档彼此差超过 5 个点才算失败)裁决;随 `final.json` 固化、能核实是读前写下的那条
   (「如果 15/30/60 在留出段上次序乱掉,平台只是样本内的」)按字面已经触发 —— 最优档从 30 换成了 60。细节在 S_final 的修订段。
2. **读前写下的升华判据没有对齐半衰期。** 「`f_max30` 的多头腿净超额和纯多头夏普都低于 `f_orig` 才算失败」比的是各自按多空规则定半衰期的两行(原式 hl 3、换手 6.1%;`f_max30` hl 0、换手 3.8%),
   它证伪不了「好处只是换手更低」。这是判据定得不好,不是事后换判据;对齐之后的读法在下面第 2 点。

### 结果

**提纯(树内最小结构,3 个算子)**

```
cross_stddev(cross_stddev(day_cov(Amt, Amt), 241), 5)
```

**读留出段之前定下的推荐(2 个算子)**

```
cross_max(day_std(Amt), 30)
```

它不是新因子,也不是「更慢的窗口」的功劳:它等价于 F001 已经蒸馏出的 `cross_max(day_std(Amt), 9)` 加一个 hl≈5 的 EMA
(train / valid 上多头腿净超额 +13.7% / +22.2% 对 +13.6% / +22.2%,两个实际交易的信号 rank 相关 0.95、多头十分位重合 79%~80%)。

### 读法(修订)

1. **相对于用户表里的那一行原式(按多空规则定半衰期),读前定下的 `f_max30` 在测试段多头腿净超额 +12.5% 对 +8.9%(+3.6 个点),纯多头夏普 +1.37 对 +1.04,多空夏普 +2.39 对 +2.24。**
   读之前写下的失败判据没有触发。但这 3.6 个点要拆开:**毛超额只多 1.5 个点(15.74% 对 14.27%),成本少 2.2 个点(3.19 对 5.37)**—— 六成是换手更低。
   多空夏普训练列低 0.23、测试列高 0.15,都在 ±0.3 的噪声里,多空上打平。
2. **半衰期对齐之后,家族成员相对树内提纯版的领先在留出段上消失了。** 第二张表里换手都在 3.1%~3.8% 的三个候选:`f_min3`(hl 10)多空 +2.52、多头腿净超额 +13.5%、纯多头夏普 +1.74;
   `f_max30`(hl 1)+2.29、+13.5%、+1.47;`f_max15`(hl 3)+2.30、+13.3%、+1.41。多头腿毛超额 16.0%~16.4%、净超额 13.3%~13.5%,几乎一样;
   `f_min3` 在多空夏普、多头腿净超额、纯多头夏普三项上都不低于读前推荐的 `f_max30`(无论后者取 hl 0 还是 hl 1)。
   样本内同一口径是家族领先的:训练列 +16.7% 对 +13.4%,决策口径 +14.5% / +22.3% 对 +11.1% / +19.1%(train / valid 同向,修订实验第 1 节)。
   所以**「换成已知家族成员让多头腿更好」只在样本内成立;相对于「树内提纯 + 更慢的 EMA」,升华没有样本外证据。**
   反过来也不能说树内更好:纯多头夏普 1.74 对 1.47 的差在噪声带里,多头腿净超额是相等的。两者并列。
3. **提纯在样本外成立。** 同一个半衰期(hl 3)下,`f_min3` 测试段多空夏普 +2.72(原式 +2.24)、多头腿净超额 +11.5%(+8.9%);删掉 3 日极值和 `fangzheng` 的 mean 项没有丢东西。
   原研究在这里还写过「四个候选在测试段四项上都不低于原式,说明原式只是这个家族里更吵的一个成员」;前半句是事实,后半句要收窄 ——
   被比下去的是 hl 3、换手 6.7% 的那一行原式,原式配更慢的 EMA 在留出段上没有读过。
4. **三个窗口**:多头腿毛超额几乎一样(17.0% / 15.7% / 16.6%),差别全在成本,测试段上最好的是换手最低的 `f_max60`(净超额 +14.7%、纯多头夏普 +1.74),不是读之前选的 `f_max30`。
   「d=30 是平台中央、最优」在样本外没有得到支持,配置里那条「次序乱掉」的判据按字面触发了(S_final 的修订段)。**推荐不因此改动,也不改选 60** —— 用留出段再挑一次窗口,它就成了第二个验证集。

5. **整个家族在测试段都弱了一截**:纯多头夏普从训练列的 2.0~2.5 掉到 1.0~1.7,五个候选无一例外。逐年(`runs/.../final.json` 的 `diagnostics.by_year`,报告表里只印了基线;

### 它(读前推荐的那个)比原式好用在哪里

- **多头腿,相对按多空规则定半衰期的原式**:净超额训练 / 测试 +16.1% / +12.5% 对 +11.8% / +8.9%;纯多头夏普 +2.46 / +1.37 对 +1.96 / +1.04。测试段的差里成本占六成。
  样本内还有一部分来自多头名额的去向(07x longleg 第 2 节、修订实验第 2 节 c):原式把一半多头名额给了成交额没那么低的股票,这一半挣得少 —— 这一点留出段上没有单独检验。
- **结构**:4 个算子 → 2 个;没有周年回声、没有未满窗口放大、没有上市首日为 0;分位剖面单调(原式顶端 Q9 > Q10)。
- **对参数不敏感**:这一族 d=9~60、半衰期 0~10 的组合里,只要多空日换手在 2.3%~5.2%,样本内多头腿净超额都在 12.3%~14.5% / 20.4%~22.4%。
  这同时说明 d=30 没有任何特殊之处。

### 它没有比原式好的地方,以及限制

- **多空夏普打平**(训练 2.80 对 3.03,测试 2.39 对 2.24)。要多空的话 `f_max15`(3.08 / 2.70)或提纯版 `f_min3`(hl 3:3.30 / 2.72)更合适。
- **相对「树内提纯 + hl 10」没有样本外优势**(上面第 2 点)。
- **它是已知暴露,而且就是 F001 已有的那个成员。** 全部控制变量张成它的 R² 是 0.740(原式是 0.500),`ctl_amt` 单独 0.643;中性化后残差 rank IC 0.0116、无成本多空夏普 +2.70。
  因子池里如果已经有 `cross_max(day_std(Amt), 9)`,把那个成员的半衰期从 0 调到 5 就得到了它,不需要加这个因子。
- **多头腿的钱在小市值里**(只留市值大的一半,训练段多头腿净超额 +1.8%),容量有限;见风险一节。
