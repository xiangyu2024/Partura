读四个算子的内核源码(`study.sh src`,服务器上的 AlphaCube)之后,和名字不一样的地方有四处。
前三处都在 `nt_ts_kurt` 身上,而且都直接决定这条因子的**多头端**长什么样。

**1. `nt_ts_kurt(Close, 30)` 的窗口是「当天的 30 分钟」,不是「30 个交易日」。**
`nt_ts_kurt` 是 ND 面内核 `ts_kurt` 挂到 NT 面上的孪生:内核只管沿第 0 轴滚(`rolling_reduce(x, d, nankurt_last, axis=0)`),
而 NT 面的引擎每次递给它的是**某一天**的(分钟 × 股票)切片 —— 所以第 0 轴是分钟轴。注册表里它的计算轴是 `M`、
窗口池是 `[3, 5, 10, 15, 30, 60]`(分钟的量级),分解表里「沿路径累计的真实回看 1 天」说的也是这件事。
任务描述里那句「nt_* 是逐分钟的截面/日轴」对 `nt_cs_*` 成立(每分钟跨股票),对 `nt_ts_*` 不成立:它滚的是日内分钟轴,不跨日。
实测见 x1 §0(与 DT 面同一内核的 `in_stddev_rolling` 对照)。

**2. 每天开头的窗口是残缺的,而且残缺窗口有确定的读数。**
`rolling_windows` 在左侧补 `d−1` 个 NaN,`nankurt_last` 只对有限值算矩、不设最少样本数:
第 0 分钟(1 个点,方差 0)→ NaN;第 1 分钟(2 个点)→ 任意两个不同的数峰度恒为 1,超额峰度 **−2**;
第 2 分钟(3 个点)→ 任意三个数峰度恒为 1.5,超额峰度 **−1.5**。探针 `partial_window_values` 的自检两条都对上了。
折叠之后这意味着:只要 9:30 集合竞价那一根与 9:31 那一根的收盘价不同,当天的 `max|K|` 就**至少是 2**(D ≥ 8)。
在纯高斯随机游走上(探针,3 个 tick 一分钟),有 53% 的「股票-日」全天最大的 \|K\| 就是开盘这个两点窗。

**3. 这个峰度核不是无量纲的:`m4 / (var² + EPS) − 3`,EPS = 1e-9,而且方差 ≤ EPS 时直接给 NaN。**
对收益率序列这无所谓好坏;但这里喂的是**价格水平(元)**。30 分钟窗口里价格只在相邻两个 tick 之间跳的时候,
`var²` 与 EPS 同量级,峰度被压向 −3(探针 `kurt_eps_knee`,服务器实测 EPS = 1e-09,半阻尼点在价差 0.0113 元):

| 窗口里的价格形态 | 无量纲的峰度应该读 | 这个核实际读 |
|---|---|---|
| 两个价位各占一半,相差 1 元 | −2.00 | −2.0000 |
| 两个价位各占一半,相差 0.05 元 | −2.00 | −2.0026 |
| 两个价位各占一半,相差 0.02 元 | −2.00 | −2.0909 |
| 两个价位各占一半,相差 0.01 元(1 tick) | −2.00 | **−2.6154** |
| 29 分钟不动 + 1 分钟偏 1 元 | +25.03 | +25.0345 |
| 29 分钟不动 + 1 分钟偏 0.01 元(1 tick 毛刺) | +25.03 | **−2.7119** |

也就是说:同样是「安静之后跳一下」,跳 1 元读成 +25(立方后 15,690),跳 1 个 tick 读成 −2.71(折叠立方后 19.9)。
对比:`day_kurt` 用的是另一个核(`C._kurt`,普通除法),同样的两点分布在任何尺度下都读 −2(探针自检)。
窗口内价格完全不动(方差为 0,比如封死涨停)则是 NaN,被 `day_max` 跳过。

**4. `pow_2` 是真正的偶函数,`pow_1_5` 只有在它后面才合法。**
`pow_(x, e)` 在 `e ≤ 1` 时是带符号幂,`e > 1` 时是普通的 `x**e`:`pow_2` 把负的超额峰度翻成正的(探针:取负后 = even、保序 = False);
`pow_1_5` 对负数会给 NaN,只因为前面已经平方过才安全。合起来是 `|K|³` —— 对 K 而言是**非单调**的折叠,对 \|K\| 而言是保序的立方。
实验室先验里那条「保序外层变换是空操作」只对立方那一半、并且只在半衰期 0 时成立(见第 4 节)。

`day_max` 没有意外:对 241 根分钟取 `nanmax`,整天都是 NaN 才给 NaN。

另外两个只在本研究里用到的算子,读源码时记下的事:
`in_zscore_rolling(x, d)` 是 DT 面的分钟滚动 z 分数,分母是 `std + 1e-9`(对元为单位的 std 可以忽略,所以它**是**无量纲的),
把 0 和 NaN 都当作无效输入、输出记 0;`cs_regres(Y, X)` 是逐日截面一元回归的残差。

## 补:齐次度 / 输出类型 / 有没有用到未来数据(逐项核对,`decompose` 探针实测)

- **`nt_ts_kurt`**:计算轴 `M`(日内分钟),窗口池 `[3,5,10,15,30,60]`。**齐次度探针读数是 `None`**(不是齐次函数——
  分母带 `+EPS`、核里还减常数 3,`f(c·x) ≠ c^k·f(x)`,这与上面第 3 条「不是无量纲」是同一件事的两种说法)。
  输出是连续值,不是布尔或档位。**没有用到当天之后的数据**:`rolling_windows` 左侧补 NaN、窗口是 `[max(0,m−29), m]`,
  第 m 分钟的读数只用到第 m 分钟及之前的数据;不跨日(当天内 causal,日与日之间本来就不滚动)。
- **`pow_2` / `pow_1_5`**:逐元素(`face shared / family elementwise`),**无计算轴、无窗口**。齐次度探针实测:
  `pow_2` k=2.0,`pow_1_5` k=1.5(与解析式一致)。输出连续值。逐元素变换,不存在"未来数据"的问题。
- **`day_max`**:计算轴 `M`(折叠日内分钟轴 → 1 个值),没有窗口参数(吃的是当天全部 241 根分钟)。齐次度 k=1.0。
  输出连续值(`nanmax`,不是布尔/档位)。**没有用到未来数据**:只折叠**当天**的分钟,不跨股票-日边界;
  当天的面板值要等当天收盘才能定下来,与标签时点"t 日收盘后决策"(`01_expression.md`)一致。
- 四个算子的输出都是连续值,没有一个是布尔或档位(step/bucket)输出。
- `decompose` 里能打的探针四个算子全部有数字读数,不适用的探针都明确标了"不适用",没有探针读数为空的情况。
