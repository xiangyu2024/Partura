# 07 S2_overlay:叠在已知家族上的秩空间非对称叠加(结果,事实部分)

来自工单 `orders/R2.md`。问题:R1 §A3 的 `cs_rank(K1) + 0.25·cs_rank(D30)` 对纯多头相对家族基准 `K1`(`known_stdamt_mean30`)
的 +2.5pp 多头增量,是真的,还是「配置里复现不出来 / 单点权重尖峰(H18)/ 任何弱相关第二信号都行(H17)」三种解释之一。
`K1 = cross_mean(day_std(Amt), 30)`,`D30 = cross_mean(原式, 30)`,原式 = `day_max(pow_1_5(pow_2(nt_ts_kurt(Close, 30))))`。
9 个变体(含 `nt_*` 的 6 个),一次服务器运行,tag `S2_overlay`,exit 0,246.6s,peak anon 5.04 GiB,device cuda。

## 实现记录(事实)

- `mul(cs_rank(...), 0.25)` 这种"`cs_rank` 输出乘一个 Python 浮点常数"的写法,`study.sh check` **直接通过**,
  没有用到工单给的两级退路((i) `create_like` / (ii) 用重复家族项造权重)。9 个变体的权重(0.15/0.25/0.40)都是这样直接写的字面量。
- `g_tail` 用到的算子,工单原文写的是 `cs_quantile_q75`。`study.sh src cs_quantile_q75` 查到的内核(`nd_cs.cs_quantile`)语义是:
  参数 `quantile` 直接就是"标记的那一头占比",`cs_quantile_q75(x)` 等价于 `x >= 当日 25 分位`,标记的是**当天最高的 75%**
  (量级上近似"排除最低的 25%"),不是"x 高于 75 分位"。标记"当天最高 25%"(即 `x >= 当日 75 分位`)的算子其实是 `cs_quantile_q25`
  (`study.sh ops '^cs_quantile'` 确认三个变体 `q25/q50/q75` 都存在,都标 `[boolean_output]`)。`g_tail` 要的语义是"罚 D30 最高的那 25%",
  已经换成 `cs_quantile_q25`,意图未变,只是换了被工单文本误记的算子名。最终表达式:
  `sub(cs_rank(cross_mean(day_std(Amt), 30)), mul(cs_quantile_q25(cross_mean(day_max(pow_1_5(pow_2(nt_ts_kurt(Close, 30)))), 30)), 0.25))`。

## 解读(主研,读完 R2 之后)

**这一阶段回答的那个问题有答案了:叠加的增量是真的,但它比头条数字小,而且归因要改。**

1. **三个安慰剂把 H17 判死,而且是朝着「反向」判死的。** `p_ivol`(+8.8%/+20.7%)和 `p_cap`(+9.6%/+18.3%)
   在**两段都低于**家族线(+12.6%/+22.3%)—— 往家族的书里温和掺一个弱相关信号不是「一样好」,而是**有害**。
   `p_k2`(掺家族自己的第二成员 K2)train 拿到 +1.5pp 但 valid 是 **−0.2pp**。九个变体里只有 D30 这一支两段同号为正。
   所以准确的说法不是「D30 独一无二」,而是「随便掺一个会变差,掺 D30 两段都略好」。`p_cap` 顺带把 H9 的
   残余嫌疑也清掉了:增量不是规模倾斜(掺规模代理反而更差)。
2. **`g_w15/g_w25/g_w40` 的 valid 行是同一个数(+23.55/+23.73/+23.51,极差 0.2pp)。** 这既杀死 H18 的尖峰版本,
   也杀死「0.25 是最优权重」这种写法 —— 权重在 0.15~0.4 之间给的是同一个东西。train 上 0.25 高出邻近约 1pp
   是噪声(同一组权重在 valid 上差 ≤0.2pp)。报告里保留 train 选出的 0.25(规矩:参数只在 fit 段定),
   但措辞必须是「w 在 0.15~0.4 之间都一样」。
3. **`g_tail` 是本阶段最干净的否定结果。** 只罚 D30 最高一档(hl0 +6.2%/+15.4%)比完整排序的 0.25 叠加
   (+15.1%/+23.7%)差了近 9pp/8pp。H14 的「这是个单边别买信号、避开最差那一档就够」这个简化**在家族的书里不成立**,
   和 x3 §B 的 book3(只剔 r≥24.9 只拿到一成增量)指向同一结论。机制上自洽:家族的书本身买的是成交额波动低的
   安静票,里面几乎没有 r≥24.9 的名字可剔,D30 在这本书里提供的是一条**连续的梯度**(过去 30 天积了多少冻结盘口痕迹),
   不是一个尾部警报。
4. **`g_raw`(把日轴记忆留在口径里、不写进表达式)+11.2%/+20.9%,低于 `g_w25` 的 +15.1%/+23.7%,也低于家族线的 valid。**
   这是「`cross_mean(…,30)` 这一层升华为什么必须」的直接证据:整条式子只能有一个半衰期,F108 这一支需要的
   平滑比家族那一支长得多,只有写进表达式才能各取所需。
5. **中性化那一行不要误读。** `all_controls` R² 0.805、残差 Lnet −25.4% 看起来很可怕,但 R² 的 0.805 基本上是
   `ctl_amt`(单独 0.714)贡献的,而 `g_w25` 本来就**主要是**成交额家族(对 `known_stdamt_mean30` 秩相关 −0.972,
   符号来自口径差,等于「几乎同一条线」)。残差净值被成本吃掉是因为残差不再平滑、换手 32.2%;残差的
   rIC +0.0086 和毛超额 +2.1% 还是正的。**这一行的正确用法**:它证明 `g_w25` 不是一条新因子,而是家族的书加一点倾斜
   —— 这和推荐的措辞一致,不构成反驳。
6. **必须和 `v_base` 的秩相关一起读(审查反复抓的那条):`g_w25` 对 `v_base`/`m_mean30` 的秩相关只有 0.05~0.27。**
   所以 `g_w25` **不是 F108 的提纯版**,它是另一条因子(已知家族)加上一点 F108。报告里的推荐只能写成
   「F108 唯一可交易的用途是给已知家族的书做 0.25 权重的修正」,**不能**写成「F108 提纯/升华之后能做到 +15%」。
