### 语义(源码级,`02_operators.md`)
- **`day_close` 是 `day_last` 的别名**(内核 docstring 原文)。喂进去的是 `Ret`(逐分钟收益),
  所以 `day_close(Ret)` = **当天最后一个有效分钟自己那一笔分钟收益**,不是收盘价、不是当日总收益。
  **这是整条链上唯一"名字骗人"的地方**,也是 `q25_closeret` 这个文件名骗人的地方。
- `cross_quantile_q25(x,15)` = `cross_quantile(x,0.25,15)`,交易日轴因果滚动、逐股票独立、`nanquantile` 忽略窗口内 NaN。
  窗口网格 `[3,5,10,15,30,60,241]`。齐次度 1;**取负不是奇函数**(`q25(−x) = −q75(x)`);窗口变长不单调。
- 整条链对 `Ret` 齐次度 = 1 → **带尺度**,没有去尺度步骤。两层直链,无重复子树、无恒等节点、**无门控、无非线性放大**。
- 序列头 14 天是"真实样本数从 1 渐增到 15",**不是**整段 NaN。

## 3. 研究过程与逻辑(做了什么、按什么顺序、为什么这么走)

1. **R0(执行)**:读内核源码、跑 `decompose`、跑 `S0_baseline`,写 `01/02/03/06` 四份事实 notes + `results/R0.md`。没下结论(分工如此)。
2. **R1(主研,本轮)**:读完 R0 的四份 notes 与 R0 结果卡,核对了算子清单(`ops`)与 `day_open` 源码,然后:
   - 写 `04_grammar.md`:把这棵树按"事件→记忆→门控→放大"逐个对位,确认**门控和放大两个角色是空的**
     (无逐元素二元节点、无布尔、齐次度 1)。于是**这棵树唯一可问的实质问题就是"读出的顺序统计量在读什么"**,
     F001/F002 那类"门控是不是真在门控""成对算子同期还是跨期"的问题在这里不适用。
   - **找到一条精确恒等式(本轮最重要的产出)**:令 `loc = q75 + q25`(四分位中点×2,纯位置)、`scl = q75 − q25`(IQR,纯尺度),
     则 `q25 = (loc − scl)/2`,**可交易信号 = −q25 = (scl − loc)/2**。
     → 原式精确等于「尾盘分钟收益 15 日离散度」减「其典型水平」,**权重 1:1,而这个 1:1 是机械挖掘选到 `q25` 时的副产品,不是学出来的**。
     → 于是"这是什么"从解释学问题变成**两个可以分别造出来、分别测的表达式**(`add`/`sub`,已确认两个算子都在注册表里)。
   - 写 `05_hypotheses.md`:15 条,每条带"预测什么 / 哪个实验能杀死它"。
   - 下 `orders/R1.md`。
3. **为什么第一张工单是 S1_shape 而不是"分辨它是不是已知暴露"**:
   `all_controls` R² 只有 0.162(84% 的横截面秩方差没被已知控制变量解释)、最高单控制 R² 0.054、
   rank 相关最高 0.22 —— **它显然不是某个已知暴露换了个写法**,花一次运行去确认这件事信息量很低。
   相反,`ctl_ivol` 中性化**反而把 rIC 接近翻倍**这个读数说明:因子带着一个**不想要的**波动暴露。
   恒等式刚好把这个暴露隔离成 `s1_scl` 一项、把剩下的隔离成 `s1_loc` 一项 ——
   **所以 S1_shape 同时是最锋利的"分辨"实验和最直接的"升华"线索**,一次运行回答两件事。
4. **为什么 `s1_q75` 的 `sign` 是关键比特**:`q25` 选到 `−1` 与"驱动是尺度"和"驱动是位置"两种读法**都相容**,区分不了;
   而 `q75 = (loc+scl)/2` 对尺度的载荷符号翻转 → 引擎自选 `+1` 说明是尺度、`−1` 说明是位置。**不花钱的一个比特。**
5. **源码里和名字不一样的地方**(下一个人最容易重复花时间的):
   - `day_close` = `day_last` 的别名,**不是收盘价**;`day_open` = `day_first` 的别名(本轮另读源码确认)。
   - 因子名里的 "closeret" 会让人以为是"当日收益",**它是单分钟收益**。
   - `cross_quantile_q25` 的探针读数 `effective_memory = 0 天` 是**正脉冲造成的假象**(正脉冲落在窗口上端,不动第 4/5 小的位置),
     **不是**"这个算子没有记忆"。解析见 `04_grammar.md` §3,记为 H14(未坐实)。
   - `ts_*` 与 `cross_*` 对"每股票-日一个值"是同一内核,但日频量**必须用 `cross_*`**(显存)。
6. **本轮对 R0 异常的裁决**:
   - 异常 1(`S0_baseline.json` 顶层 `rank_by = "ls"` 与配置里 `rank_by: long` 不一致)→ **判定:不重跑 S0。**
     理由:这条因子 `hlL == hlS == 20`,两种选法同一个答案,顶层标量**不可能**影响已读到的任何数字;
     且 `books.hl_long`/`books.hl_ls` 两个字段独立存着,digest 直接读它们。省一次运行。
     **但留了一条规矩给后面**:所有跨运行的比较都从 `hlL` 列和固定半衰期表读,不从可能依赖 `rank_by` 的表头列读。
   - 异常 2(`rICtraded` 两列展示为空但 JSON 里有数)→ 展示层问题,不是数据缺失,不处理。
   - 异常 5(`Ret` 的精确定义没有直接文档)→ 记为 H15,**推迟到 R2 的脚本里顺手量**(量 `day_sum(Ret)` 与当日收益的 rank 相关)。

**已排除的候选与原因**(本轮的设计裁决):
- `cross_mean(day_close(Ret), 15)`(非稳健纯位置)—— 从 R1 里**砍掉**,为了把 12 个变体的额度留给恒等式那一对。
  理由:它与 `s1_loc`/`s1_q50` 只差"要不要吃极端日",而同一条轴已经由 `s1_std` vs `s1_scl` 在尺度侧测了。
  若 `s1_loc` 与 `s1_q50` 分化很大,再把它加回来。(R1 的「兜底」条款里它是 `add()` 不合法时的替补。)
- `in_slice(...)` 切日内中段某一分钟 —— 砍掉。它在手写库里、参数含字面量、签名要另读,
  而 `day_sum`/`day_mean`/`day_open` 三条注册表算子已经能回答"位置特不特殊"。

- **"它是不是已知暴露"专门跑一个阶段** —— 砍掉,基线已经答了(`all_controls` R² 0.162、最高单控制 0.054、最高 rank 相关 0.22)。

## 6. 后面的研究思路(按顺序;每步做什么、想回答什么、哪种结果意味着什么)

**R2(下一轮主研):裁决 S1/S2/S3,然后下 R2 工单。** 分支如下 ——

- **若 `s1_loc` 高于原式**(H3 成立)→ 主线变成"提纯成纯位置分量"。R2 工单:
  (a) 在纯位置分量上重做窗口扫描(15/30/60),因为最优窗口可能和原式不同;
  (b) 量它相对已知家族的增量(H12)。
- **若 `s1_scl` 高于原式**(H1 成立,H3 被杀死)→ 麻烦:那它就是一个"尾盘分钟波动"因子,
  和 `known_ivol_max9`/`ctl_ivol` 家族是邻居,**必须**立刻量 H12,而且先验上大概率是"已知家族换了个写法、且更弱"。
- **若两个纯分量都明显弱于原式**(H4 成立)→ 1:1 混比真的在互补。那就去问"混比是不是恰好最优":
  用 `mul` 配字面量系数造 `scl − k·loc`(k = 0.5 / 2),**注意**:常数在这套语言里是"铺满分钟轴的退化值",
