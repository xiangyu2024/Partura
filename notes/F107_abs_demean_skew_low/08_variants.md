# 怎么读变体总表,哪些变体其实是同一个东西

> 主研第 3 轮写(Opus 5,2026-10-04)。
> 全研究 4 个阶段、28 个变体:`S0_baseline` 1 + `S1_parts` 11 + `S2_memory` 11 + `S_final` 5
> (每次运行还会自动带上 `v_base` 去算 rank 相关,不额外花钱)。

## 读表前必须知道的三件事

1. **两套口径不能混。**
   - **决策口径**:方向 / 半衰期在 **train** 上定,`valid` 是没见过的 —— **挑变体只看这套**。
     `S0_baseline` / `S12` 的表、以及 `07_S_final.md` 末尾那张表都是这套。
   - **用户口径**:方向 / 半衰期在 **utrain**(train+valid)上定,对应用户表的「训练」列;
     `holdout`(20230808–20251231)是「测试」列。**整个研究只读过一次**(tag `FINAL`,`07_S_final.md` 的 (A)(B) 表)。
   - 同一个变体在两套口径下可以选到**不同的半衰期**:`f_m20` 决策口径选 hl20、用户口径选 hl10;
     `f_K` 两套都选 hl0。比较数字前先看 `hlL` 这一列。
2. **`Lnet` 是净的、`Lgross` 是毛的。** 用户最早那张表里的 `long: [0.099, 0.105]` 是**毛**超额 ——
   别拿它和原式的净超额 +1.1% 比。两者的差就是成本(原式 train 约 8.2pp、留出段 **9.04pp**)。
3. **每个变体有两个半衰期**(`hlL` 多头口径、`hlS` 多空口径)。比较两个变体时,**先确认它们的 `hlL` 是同一个** ——
   不同就不能把差额说成「结构更好」(playbook §6.1)。digest 下面那张**固定半衰期表**就是为这件事印的,
   但它**只在 train 段上有**(`books["sweep"]` 只在 `fit_split` 上算,final / holdout 模式也不会补)。
   本研究的归因之所以干净,是因为 `v_base` / `m10` / `m20` 在决策口径下**都选到 hl20**,主表的 `Lgross` 本来就同半衰期可比。

## 哪些变体其实是同一个东西

| 看起来是两条 | 实际 | 出处 |
|---|---|---|
| `f_orig`(S_final)与 `v_base`(S0) | **同一棵树**,`expr` 逐字相同,引擎合并求值,数值相同 | `07_S_final.md`;FINAL.json 的 `rank_corr` 里 `f_orig` 对 `v_base` = 1.0000 |
| `m20_absret`(S2)、`g_absidio20`(gates)、`f_m20absret`(S_final) | **三个 id,一条表达式**,逐字符串比较完全相同 | `results/R2.md` (E)3 |
| `cross_delay(x,d)` 与 `ts_delay(x,d)`(d>0) | 逐行等价(都是 `res[d:]=x[:−d]`、其余 NaN、axis=D)。config 里 `ctl_rev1` 用前者、`r_absret` 一族用后者 —— **不是 bug,不要统一** | `study.sh src`;`state.md` §2.6 |
| `m10` / `m20` / `m30` / `m60` | 同一族(等权窗口 + 同一棵折叠树),train/valid 互在噪声带内(+4.6~+5.6% / +6.5~+7.3%) | `07_S2_memory.md` |
| `r_absret` 与 `m20_absret` / `m60_absret` | 同一条日频量,只差外面有没有 20 / 60 日均值 | config |

**`m120` 不算同一族**:ρ(v_base) **0.784 < 0.8**,按 playbook §6.3 它已经是换了一条因子;
而且它的净超额全靠把半衰期选到 hl3(固定 hl20 下只有 +1.0% = 原式水平)。

## 哪些看起来是同一个、其实不是

| | |
|---|---|
| `p_rank` = `cs_rank(原式)`、`p_cube` = `pow_3(原式)` | **保序的外层变换不是 no-op**:现在的口径是**先 EMA 再排序**,`EMA(f(x))` 与 `f(EMA(x))` 的序不同(playbook §3)。实测是真的变体:`p_rank`(压平尾部)空头毛 +32.5% → +19.6%、扣费多空夏普 2.81 → **1.12**,多头毛**反而略升**;`p_cube`(权重压到尾部)多头毛降到 +7.2% / +7.5%、空头毛不动 |
| `p_znorm` = `abs_(cs_normalize(day_skew(Low)))` vs 原式 | `cs_normalize` 比 `cs_demean` 多除一个截面标准差 → 逐日尺度被抹平。书在噪声内(+1.6% / +3.1%)→ **这条因子不靠跨日尺度**,只靠截面位置 |
| `r_kurtlow` = `day_kurt(Low)` vs 原式 | ρ **0.7842** 很高,但 Lnet **−7.3% / −9.4%**(毛 +0.5% / −1.9%)→ **高相关不等于同一本书**。`\|B\|` 对同路径峰度的秩空间 R² 0.567 / 0.601,但**与峰度共享的那部分里没有多头腿** |
| `f_m20` vs `f_m20K` | `f_m20K` 是两个 `cs_rank` 面相加,`dist` **0.812**(其余四条 ~1.00)—— 秩面比连续面离散,是数值性质不是异常 |
| `p_range` vs 原式 | 都是「日内不对称度」,但 `p_range` 有界、没有厚尾:多头毛 +9.5% / +9.2% ≈ 原式,而空头毛掉到 +24.1%、LTO 升到 14.1%、`dist` 0.90 → **厚尾只服务于空头腿** |

## 一句话索引(按它回答了什么问题)

- **哪个节点必需**:`p_signed`(折叠)、`p_nodemean` / `m60_nodemean`(`cs_demean`)、`p_close`(字段)、
  `p_range` / `p_znorm` / `p_rank` / `p_cube`(三阶矩与尾部权重)。
- **它是不是已知东西的另一种写法**:`r_absret` / `m20_absret` / `m60_absret`(日频 `\|特质收益\|`)、
  `r_kurtret` / `r_kurtlow`(峰度)、`r_mktcorr`(分钟同步性,H7)、`f_K`(已知家族)。
- **记忆该怎么写**:`m10`~`m120`(窗口长度)、`md60`(中位数)、`mr60`(先取截面秩)、`mx20`(20 日极值)。
- **对用户到底有没有增量**:`f_m20K`(等权秩相加)—— **这是用户真正的问题,也是本研究唯一一条既决定性、
  又不是边界情形的判决**(留出段比 K 低 6.12pp)。
- **留出段那五条的角色**:`f_orig` 基准 1(原式 + 多头最优半衰期)、`f_m20` 第一推荐、`f_K` 基准 2(已知家族)、
  `f_m20K` 增量检验、`f_m20absret` 反驳检验(H14)。为什么是这五条、为什么 `m60` 没占槽位:`10_distilled.md`。

## 不在变体表里、但报告会引用的东西

- **x1**(`studies/.../x1_anatomy.py`,tag `x1`):numpy 探路,12 条假设一次扫完。
  引用它的数字**必须标注「numpy 探路」** —— 它的 `cross_mean` 面板与引擎不是同一张(H15,边界伪影,book 级 ≤0.6pp)。
- **x2**(`x2_elevate.py`,tag `x2`,§a~§f):引擎 `st.books`,和主表同口径,**不需要加标注**。
  §a 取证 H15、§b 杀 H13、§c 立 H16、§d 峰度残差、§e 对 K 的三个检验(这是结论的来源)、§f 逐年。
- **`gates` 里的量**(`g_absidio20`、`g_kurtlow20`、`known_stdamt_mean30`)**不自动进 `diagnostics.neutralise`** ——
  对它们的中性化是用 x1 §6 / x2 §d§e 的 exec 脚本做的。看报告里的 neutralise 表时别以为它们缺了。
