表达式里出现的 7 个不同算子(`day_mean`、`ts_max`、`sub`、`cs_demean`、`pow_2`、`mul`、`pow_1_5`),内核源码和它们调用的底层函数全部读过(`./scripts/study.sh src day_mean ts_max sub cs_demean pow_2 mul pow_1_5`,并单独查了 `ts_max` 用到的 `nanmax_last`)。每条先给**精确公式**,再给探针实测的齐次度/边界行为,最后标"和名字不一样的地方"。全部 7 个算子的声明都是 `lookahead=False`,且源码上 `rolling_windows` 是左填充(只看过去),**没有用到当天之后的数据**。

### `day_mean(x)` — 折日内分钟轴(M → 1)

```python
day_mean(x) = C._mean(x.float()).unsqueeze(-1)     # C._mean 即 common._mean(x) = x.nanmean(dim=-1)
```
- 轴:`M`(日内分钟),折叠成每股票-日一个值。窗口:无(当天全部有效分钟,这棵树里是 `Ret` 的 241 根分钟收益)。
- 齐次度 k = 1.0(线性)。NaN 行为:`nanmean`,当天只要有一根分钟非 NaN 就输出有限值;当天全 NaN(停牌/无分钟数据)才输出 NaN。探针实测 `finite_frac_with_10pct_missing = 1.0`(10% 随机缺失几乎不可能让全天 241 根都缺),`all_nan_input_gives_all_nan = True`。
- 和名字一致:`day_mean` 确实是日内算术平均,不是别的统计量。**不是**"去极值"或"剔除停牌分钟"之类的稳健均值。

### `ts_max(x, d)` — 交易日轴(D)滚动最大值

```python
rolling_windows(x, d, axis=0):                      # 左填充 NaN,因果窗口,输出多一维窗口维(长度 d)
    pad = full((d-1,) + ..., nan); x_padded = cat([pad, x], axis=0); return x_padded.unfold(axis, d, 1)
nanmax_last(w):                                      # w 的最后一维是窗口维
    filled = where(isnan(w), -inf, w)
    out = filled.max(dim=-1).values
    return where(isnan(w).all(dim=-1), nan, out)
ts_max(x, d) = nanmax_last(rolling_windows(x, d, axis=0))
```
- 轴:`D`(交易日),窗口 `d`(本树里用了 5、30、20、30 四次)。**窗口长度 = d 就是真实回看天数**(含当天,左填充只发生在序列最前面不足 d 天的地方)。
- 齐次度 k = 1.0(对 c>0 成立:`max(c·x) = c·max(x)`)。保序性:不适用(不是一元变换,但对单个输入序列而言窗口变长时输出"单调不减"——探针 `monotone_in_window = non_decreasing`)。
- NaN / 不足窗口行为:窗口内只要有一个非 NaN,就输出该窗口内非 NaN 值的最大值(NaN 当 `-inf` 处理,不参与比较);**窗口内全 NaN 才输出 NaN**。序列最前面的 `d-1` 行用左填充的 NaN 补窗口,所以不会报错,只是**有效窗口变短**(第 1 天的"5 日最大值"其实只用了 1 天)。探针实测 `finite_frac_with_10pct_missing = 0.9948`(d=5 时测的,比 `day_mean` 的 1.0 略低,因为窗口更短、更容易撞上"全缺"的边界情形)。脉冲记忆天数 = d(一个脉冲正好在窗口滑出后的第 d+1 天消失)。
- **和名字不一样的地方**:这个项目里还有一个 `cross_max`,两者**内核完全相同**(同一套"交易日轴滚动最大值"数学,`study_playbook.md` §3 明确写了"`cross_stddev(x,20)` 与 `ts_stddev(x,20)` 是同一个内核、逐位相同"对 `max` 同样适用),区别只是**算力实现**:`cross_*`(DT 面)按股票分块算,`ts_*`(ND 面)一次吃整张面板,显存紧张时更容易求值失败。这条表达式的原始挖掘结果用的是 `ts_max` 不是 `cross_max`——数学上和用 `cross_max` 重写完全等价,只是鲁棒性/显存占用不同(S0_baseline 这次跑了 183.3s、峰值常驻内存 3.02G,没有求值失败)。

### `sub(a, b)` — 逐元素减法

```python
sub(a, b) = a - b     # 若 a/b 一个是 Python 标量、另一个是 Tensor,先用 create_like 把标量铺成同形状的常数张量
```
(`fill_nan_with_zero` 参数这里没被传,走的是默认分支,NaN 正常传播:`a` 或 `b` 任一 NaN,结果 NaN。)
- 轴:无(纯逐元素),无窗口。齐次度 k = 1.0(两个操作数都缩放时)。
- **这棵树里 `sub(B, -5)` 的第二个操作数 `-5` 是裸常量**,`create_like` 把它铺成和 `B` 同形状的全 `-5` 张量,所以 `C = B - (-5) = B + 5`,是"整盘加 5",不是任何数据驱动的量。**对常量操作数而言,`sub` 不是严格齐次的**(`sub(cB,-5) = cB+5 ≠ c(B+5)`,除非 c=1)——下一条 `cs_demean` 正好把这个破坏齐次性的常数项抵消掉,见 `03_decomposition.md`。
- 和名字没有出入(确实是减法),但"减一个负常数"等于"加常数"这一点容易被字面(`sub`、`-5`)带偏,写公式时要留意。

### `cs_demean(x)` — 横截面(S 轴)去均值

```python
_valid(x, mask) = isfinite(x) & (mask if mask is not None else True)
cs_mean(x, mask) = mean_over_stocks( where(_valid(x,mask), x, nan) )   # x.nanmean(dim=-1),按股票轴
cs_demean(x) = x - cs_mean(x)
```
- 轴:`S`(横截面,同一天所有股票),无窗口,不折叠任何轴(输出形状不变)。
- 齐次度 k = 1.0,**严格线性**:对任意当天统一的常数 c₀,`cs_demean(x + c₀) = cs_demean(x)`(c₀ 在 `cs_mean` 里被原样减掉)。这个性质是 `03_decomposition.md` 里"`+5` 被精确抵消"的直接依据。
- NaN 行为:当天横截面均值只用当天"有限值"的股票(`_valid` = `isfinite`),不是除以全部股票数;单只股票当天是 NaN,去均值后该股票仍是 NaN,但**不拉低/不拉高别的股票的均值**(因为被排除在均值计算之外)。
- 没有发现和名字不一样的地方;确认了它是"只在当天、跨股票"操作,不是 `cross_*` 那种跨日操作——这一点在这个项目里容易搞混(`cs_` vs `cross_`),源码上两者轴完全不同(`cs_*` 的 `_valid`/`nanmean(dim=-1)` 是按最后一维即股票轴;`ts_*`/`cross_*` 是按日期轴 `axis=0`)。

### `pow_2(x)` — 平方(逐元素)

```python
pow_(x, e):                          # e = 2.0 这里
    if e <= 1.0:  sign(x) * |x|**e   # 保号分支,这棵树里的两次 pow_2(e=2)都不走这条
    else:         x ** e              # 不保号分支:pow_2 实际走的就是这一支
pow_2(x) = pow_(x, 2.0) = x ** 2.0
```
- 轴:无,逐元素。齐次度 k = 2.0。**不保序**(探针 `rank_preserving = False`,`sign_sensitivity = even`,即 `f(-x) = f(x)`)。
- 这棵树里两次用到 `pow_2`(节点 `F = pow_2(E)`、`J = pow_2(I)`),`E` 和 `I` 都是横截面去均值之后的量、**可正可负**,所以这两次平方都是真的"折叠"(丢掉符号),不是 no-op。实验室先验"保序外层一元变换是 no-op"那条明确不适用于 `pow_2` 作用在"有正有负"的操作数上(这条先验本身也写了这个限定)。
- 边界:输入 NaN → 输出 NaN(`torch.pow` 正常传播);没有发现其它边界异常。

### `mul(x, y)` — 逐元素乘法

```python
mul(x, y) = x * y     # 若一个是标量,先用 create_like 铺成同形状常数张量
```
- 轴:无,逐元素。**通用 `mul` 的齐次度探针读数是 k = 2.0**(两个操作数都缩放时,`mul(cx,cy) = c²·mul(x,y)`)。
- **这棵树里 `mul(G, 5)` 的第二个操作数 `5` 是裸常量,不随 `G` 的尺度缩放**,所以这个节点在树里的实际缩放行为是
  `mul(cG, 5) = 5c·G = c · mul(G,5)`——**对这条树而言这一步是 1 次齐次(等于 `G` 本身的次数),不是通用探针读到的 2 次**。
  读 02 的人如果直接套用"`mul` 齐次度 = 2"会把后面 `03_decomposition.md` 的齐次度链算错,这是本节最容易踩的坑。
- 没有别的和名字不一样的地方;`5` 就是字面放大 5 倍,不是门控、不是另一路信号(这棵树里完全没有"两路数据信号相乘"的结构,和 F001/F101 不同)。

### `pow_1_5(x)` — 1.5 次幂(逐元素,整条表达式最外层的算子)

```python
pow_1_5(x) = pow_(x, 1.5) = x ** 1.5     # e=1.5 > 1.0,同样走 pow_ 的"不保号"分支:torch.pow(x, 1.5)
```
- 轴:无,逐元素。齐次度 k = 1.5。探针读到 `保序 = True`、`取负后 = neither`。
- **一般情况下的坑(不只是这棵树)**:`pow_` 的 docstring 说这是"signed power,对分数次幂保留符号",但代码只在 `e ≤ 1.0` 时才走保号分支;`pow_1_5` 的 `e=1.5 > 1.0`,**实际走的是 `x ** 1.5` 这一支,对负数输入直接是 NaN**(非整数次幂的负底数在实数域无定义,`torch.pow` 按 IEEE 语义返回 NaN)。这和"signed power"这个名字暗示的行为**正好相反**——如果某个候选结构里把 `pow_1_5` 套在一个可能为负的量上,会无声地把所有负值变成 NaN,不会报错。
- **但在这棵树里这个坑不会被触发**:`pow_1_5` 的输入是 `K = ts_max(J, 30)`,而 `J = pow_2(I)` 恒 ≥ 0(平方),`ts_max` 保非负,所以 `K` 恒 ≥ 0(或 NaN),从未真正落入负数分支。对 `x ≥ 0`,两个分支本来就给同一个结果(`sign(x)=1` 或 0,`|x|=x`),所以 `pow_1_5(K)` 在这里等价于一个普通的、良定义的 1.5 次幂。完整推导见 `03_decomposition.md`。

## 这一节汇总:三处"名字说的和实际算的不一样"

1. `sub(ts_max(...), -5)` 字面是减一个负数,实际效果是**加常数 5**,而这个常数在下一步 `cs_demean` 里会被**精确抵消**。
2. `mul(G, 5)` 的通用齐次度是 2(两变量都缩放的意义上),但因为第二个操作数是**裸常量**,这个节点在树里的实际缩放行为只有 1 次(跟 `G` 一样),不是 2 次。
3. `pow_1_5` 的命名/文档暗示它对负数"保号",内核实现对 `e>1` 其实不保号(负数输入给 NaN);这棵树因为前面全是"平方 + 取最大值",送进 `pow_1_5` 的值可以证明恒非负,所以这个坑没有被触发,但如果以后做"替换/简化"实验、让某个子树的符号可能翻转,要重新检查这一点。

另外一处不是"名字问题"、是**工具口径**问题,写在这里避免被误读:`study.sh digest` 打出的 rank 相关表是在 `v_base` **原始面板**(没翻方向、没平滑)上算的;`scripts/overview_for.py` 打出的是**可交易信号**(方向 × 面板,按公布半衰期 hl=1 平滑之后)上算的。这条因子 `sign=-1`,所以同一对变量在两张表里符号大致相反(平滑在 hl=1 时影响很小,数值上也几乎相同,差异通常 ≤0.01):例如 `ctl_cap`,digest 读到 −0.14(原始面板),overview_for.py 读到 +0.15(可交易信号)。两者是同一件事的两种读法,**不是矛盾**,但引用时必须注明是哪一张表、哪种口径,否则就是 `study_playbook.md` §6.8 提到的"数字张冠李戴"。具体数字见 `06_baseline.md`。
