## 想回答的问题

**主问题:这条因子的多头腿(= 用户唯一能交易的那本书)到底是"差"还是"根本没有意义"?如果有救,救它的是哪一个节点?**

S0 的事实:多头腿 train `Lnet +1.6% / Lshp +0.39` → valid `−1.7% / −0.52`(翻符号);
多空两段都稳(`LS +2.59 / +2.39`);`long_share` 15.7% → 4.2%;分位剖面是**悬崖型**不是单调
(valid `Q1 −26.6%`、`Q3 +11.5%` 最高、`Q10` 只有 `+1.5%`);`dist = 0.5847`;两种口径都选到 `hl=1`
且它在 sweep 上是**尖峰不是平台**。

分三组问:

1. **(A 组,H1/H2/H6/H7)多头腿是不是并列噪声?** `dist=0.5847` 说典型一天有 41% 的有值股票与别人同值。
   如果多头十分位大量落在并列组里,它的成员就是按**股票代码顺序**挑的,那条腿的数字没有意义,
   "改结构救多头腿"整条路就不用走了。→ 脚本 `x1_ties`。
2. **(B 组,H3/H2)多头腿有没有救?** H3(零假设)= 它只是个"排除极端股"的尾部筛子,多头端天生没有信息;
   H2 = 外层折叠的中心 `mean_cs(G)` 被右尾拖高、错位了,把中心挪到中位数/秩空间就能救。
   → `c9_rankfold` / `c10_medfold` 对 `v_base`;以及整条消融阶梯的多头腿。
3. **(C 组,H5/H9/H8/H4)哪些节点是多余的?** 代数上我已经推出三条强预测(见下),实验是**审计**:
   预测对不上,说明我对引擎的理解错了,后面所有推导都要重做。

### 看到哪种结果意味着什么

| 结果 | 意味着 |
|---|---|
| `x1` 测出多头十分位并列占比 ≳30% 或切割点落在大并列组内部 | **H1 成立**。多头腿不可用的原因是机械的。研究直接走向"多头腿不可用"的结论,R2 只需补齐分辨与风险证据 |

### (B) 自写脚本 `studies/F113_nested_tsmax_demean/x1_ties_and_longbook.py` —— 1 次服务器运行

目的:A 组问题(H1/H2/H6/H7)—— 现成诊断答不了,必须自己量。
**只用 train 和 valid。`st.slice("holdout")` 会直接报错,不要碰。**

抽样口径:和 `partura/diagnose.py:136` 的 `distinct_fraction` 对齐 —— **每 5 天取 1 天**,
只用当天有值股票数 ≥30 的日子;train 和 valid **分开**报,每个指标报**中位数**(另外报一个 90 分位的,见下)。

需要的面板:
```python
p_base = st.panels({"base": "<v_base 的完整表达式,从 configs 里原样复制>"})["base"]
G      = st.panels({"G": "ts_max(pow_2(ts_max(cs_demean(ts_max(day_mean(Ret), 5)), 30)), 20)"})["G"]
A      = st.panels({"A": "day_mean(Ret)"})["A"]
sig    = st.signal(p_base)        # 实际交易的信号:方向 x 面板,按多头口径半衰期平滑;全长
```
**多头腿 = 当天 `sig` 最高的 10%**(方向已经含在 `sig` 里,不要再自己翻符号);**空头腿 = 最低的 10%**。
每天的名额数 `n_long = round(0.10 * 当天 sig 有值的股票数)`。

六个区块。**任一区块失败就打印一行 `[BLOCK k FAILED] <原因>` 然后继续跑后面的**,不要让一个区块拖垮整个脚本。

**区块 1 — 并列结构(H1,最重要)。** 对每个抽样日:
- `raw` 面板(`p_base`,不翻方向不平滑)的"不同取值数 / 有值股票数" → **自检**:
  这个数在 train+valid 合起来的中位数必须复现 S0 的 `dist = 0.5847`(±0.02)。
  **对不上就在结果卡里标出来并说明你怀疑哪里不一致**(面板不同?抽样不同?),后面几个区块的读数要打折看。
- 多头腿内部:不同取值数 / `n_long`;处于并列组(同值股票数 ≥2)的名额占比;处于并列组 ≥10 的占比;
  多头腿内最大并列组的大小。
- **切割点并列**:第 `n_long` 名的那个 `sig` 值,当天有多少只股票恰好等于它(`np.isclose` 不要用,
  用精确 `==`,因为这里关心的就是浮点上的完全相同),其中有多少进了多头腿、多少被切掉。
- 同样四项再对**空头腿**算一遍(对照:如果只有多头腿并列严重,就是 `04_grammar.md` §3 预测的那个
  "低 K 退化平台";如果两端都严重,是别的原因)。
- 每一项报 train / valid 的**中位数**和**90 分位**。

**区块 2 — 退化票(H1 的机械来源)。** 用 `A = day_mean(Ret)`:
- 全样本:有值格子里 `A == 0.0`(精确相等)的比例。
- 每个抽样日:多头腿里 `A == 0.0` 的占比;多头腿里"**过去 5 天 `A` 全部精确为 0**"的占比
  (这类票 `B=0` 精确成立,`04_grammar.md` §3 推的"所有这类股票同一天拿到完全相同的因子值");
  同样对空头腿和全市场各算一遍做对照。
- 报 train / valid 中位数。**富集倍数**(多头腿占比 / 全市场占比)写出来。

**区块 3 — 折叠中心在哪(H2)。** 用 `G`:
- 每个抽样日:`nanmean(G)` 在当天 `G` 的有值截面分布里处于**第几分位**(0~1)。报中位数与四分位。
  H2 预测 ≳0.75。
- 每个抽样日:多头腿那批股票当天 `G` 的分位数的**中位数**;空头腿同样。
  (H2 预测多头腿的 G 分位贴着 `nanmean(G)` 的分位,而不是贴着 0.5 或 0。)

**区块 4 — 多头腿的已知暴露成分(分辨;`study_playbook.md` §6.5 要求的口径)。**
对这 10 个控制/已知家族:`ctl_amt, ctl_cap, ctl_turnrate, ctl_ivol, ctl_dvol20, ctl_rev1, ctl_mom20,
known_stdamt_mean30, known_stdamt_max9, known_amt_max9`(都用 `st.control("<名字>")` 取;
`known_*` 在配置的 `gates:` 里,playbook §2 的例子就是这么取的):
- 每个抽样日把该控制变量转成**当天截面分位**(0~1),报**多头腿名额的分位中位数**和**空头腿的**。
  全市场基准是 0.50。**rank 相关接近 0 但多头腿分位是 0.75,就是 §6.5 说的"秩空间线性中性化看不见
  非单调关系"** —— 这是这条因子必须用这个口径量的原因(它有两次 `pow_2` 折叠)。
- 报 train / valid 中位数。

**区块 5 — 与已知家族多头腿的重合率(H7,"有没有增量"的直接证据)。**
对 `known_stdamt_mean30` 和 `known_stdamt_max9`:
- 用 `st.signal(st.control("<名字>"))` 得到它们各自的交易信号(方向与半衰期由工具自己在 fit 段定);

  核对一下对不对得上)。如果 `st.signal` 吃不下控制变量面板,就退而用 `sign=-1` + `hl=0`(不平滑)并**写明你用了什么**。

**区块 6 — 空头腿里有多少是封板票撑的(H6,`study_playbook.md` §6.6)。**
`tgt = st.target()`(可买入版,封板票标签 NaN)、`raw_tgt = st.target(buyable=False)`。

- **多头腿也各算一遍**(预期几乎不受影响 —— playbook §6.6 说这只影响多空口径;

- 如果 `st.books` 有能直接传 target 的参数,用它更省事,并在结果卡里写明你用了哪种做法。

## A. 已核对的算子语义(执行不用再自己推,但也不要盲信名字)

这三个算子是本批次第一次用,我读了服务器上的源码(`study.sh src`),结果如下 —— **c8 / c9 / c10 的设计依赖它们**:

1. **`pow_1_5` 对负数返回 NaN(已确认)。** 内核 `common.pow_` 是:
   `where(e <= 1, sign(x)*|x|^e, x^e)`。`e=1.5 > 1` 走 **`torch.pow(x, 1.5)` 这条不保号的分支**,
   负数输入静默变 NaN。→ 工单里 `c8_nofold_out` **必须同时删掉 `pow_1_5`** 这一条是对的,照原样做。
   反过来说:`c9` / `c10` 的最外层 `pow_1_5` 的输入都来自 `ts_max(pow_2(...))`,恒非负,**安全**。
2. **`cs_median` 是「当天截面中位数广播成全形状」(已确认)。** 内核末尾 `med.unsqueeze(-1).expand_as(x)`,
   且 `count == 0` 的日子返回 NaN。→ `c10` 的 `sub(G, cs_median(G))` 就是去中位数,设计正确。
3. **`cs_rank` 默认 `pct=True`,取值落在 (0,1];并列按「列序 = 股票顺序」打破(重要)。**
   内核用 `argsort(..., stable=True)`,注释自己写了 ties keep index order。
   → **`c9_rankfold` 的 `dist` 会接近 1,但那是假的「修好」**:它把原来的并列**换成了按股票代码顺序排开的、
   逐日稳定的不同取值**,然后这些值继续穿过 `cs_demean → pow_2 → ts_max → pow_1_5`。
   **所以结果卡里报 `c9` 的 `dist` 时,必须紧跟着报下面 B 节的指标**,不要单独写一句「c9 把并列消掉了」。

## B. 必须补的测量:区块 1b —— 多头腿的成员资格是不是按股票代码定的(H11)

**不加服务器运行**:写在已有的 `x1_ties_and_longbook.py` 里,`st.symbols()` 拿股票代码
(API 确认存在:`partura/study_tools.py:127`)。`c9_rankfold` 的面板在 (A) 跑完后已进共享缓存,
所以 `st.panels({...c9 表达式...})` 不额外花钱 —— **(A) 先跑、(B) 后跑,顺序不要换**。

对 `v_base` 和 `c9_rankfold` 各做一遍(每个抽样日,train / valid 分开报中位数):

1. **代码序位置**:多头腿名额的「股票在列轴上的位置分位」(列下标 / 当天有值股票数,0~1)的**中位数**。
   全市场基准 = 0.50。空头腿同样算一遍做对照。
2. **板块构成**:按股票代码前缀分桶 —— `600/601/603/605`(沪主板)、`000/001/002/003`(深主板+中小)、
   `300/301`(创业板)、`688`(科创板)、`8../4..`(北交所)、其他。报**多头腿的板块占比** vs **全市场的板块占比**。
   (代码格式不是纯数字前缀时,按前 3 个字符分桶,并在结果卡里写明你看到的格式。)
3. **切割点上的并列是不是按代码挑的**:区块 1 已经要求数「第 `n_long` 名的值上有多少只股票、几只进了多头腿」。
   在此之上补一项:**进了的那几只的列下标中位数 vs 被切掉的那几只的列下标中位数**。
   如果进的系统性更小(或更大),说明名额确实是代码顺序发的。

**这三项为什么值得做**:H1 说多头腿是并列噪声,而「噪声」有两种完全不同的后果 ——
如果并列是按代码顺序打破的,那么多头腿暴露的是**股票代码**,而 A 股的代码前缀就是**上市板块**(进而是规模、
上市年龄、涨跌幅限制:创业板/科创板 ±20%,主板 ±10%)。这不是会被平均掉的随机噪声,而是一个**逐日稳定、
看起来可交易、但毫无逻辑的暴露**,而且它正好躲过所有现成诊断:秩空间线性中性化和 rank 相关都看不见它
(`study_playbook.md` §6.5 说的就是这件事)。**`c9` 是本工单唯一的「升华候选」,如果它的多头腿好看、
而好看的来源是代码序,那是这一轮最容易骗过人的假阳性** —— 必须当场量掉。
