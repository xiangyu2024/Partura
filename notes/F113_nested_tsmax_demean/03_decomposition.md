下面是分解表之外需要说明的四件事。

---

## 1. 重复子树:没有

12 个中间节点(A..L)"被引用"全部是 1×,工具自己的计数已经说明了这一点。原因是**这棵树完全不分支**:
从根 `L` 往下,每一个节点都只有**一个"数据"子节点**(另一个操作数、如果有的话,是裸常量:`sub` 的 `-5`、
`mul` 的 `5`、`pow_*` 的指数)。一条不分支的链不可能产生共享子树——这和 F101(`A` 被引用 2 次、`C` 被引用 3 次,
因为同一个"放量掩码"同时拿去做了比较、求均值、求标准差)是完全不同的结构。**对这棵树做"提纯"实验时,不存在
"删掉一个被多处引用的节点、同时影响好几个地方"的情况**——这是事实观察,不是关于提纯方向的建议。

## 2. 量纲(齐次度链)与取值范围

把 `Ret` 整体缩放 c 倍(c>0),逐层推齐次度(每个算子的齐次度见 `02_operators.md`;`sub`/`mul` 的"裸常量操作数
不随 c 缩放"这一点已经在上一节标出,下面直接用结论):

| 节点 | 齐次度(对 Ret 的缩放 c) | 可正可负? | 备注 |
|---|---|---|---|
| A | c¹ | 可正可负 | 分钟收益的日内均值 |
| B | c¹ | 可正可负 | `max` 对 c>0 保持 1 次 |
| C | **非严格齐次**(= c¹·B + 5,常数项不随 c 缩放) | 可正可负 | 见下一节,这个"+5"马上被抵消 |
| D | c¹(精确) | 可正可负 | `cs_demean` 把 C 里的常数项精确消掉,见下一节 |
| E | c¹ | 可正可负 | `max` 对 c>0 保持 1 次 |
| F | c² | **恒 ≥ 0** | 平方 |
| G | c² | **恒 ≥ 0** | `max` 不改变非负性 |
| H | c²(常量 5 不改变次数) | **恒 ≥ 0** | 02 节标出的"mul 齐次度坑" |
| I | c² | 可正可负 | 横截面去均值,把 H 的非负性打破 |
| J | c⁴ | **恒 ≥ 0** | 平方 |
| K | c⁴ | **恒 ≥ 0** | `max` 不改变非负性 |
| L(根) | **c⁶** | **恒 ≥ 0(或 NaN)** | `pow_1_5`:(c⁴)^1.5 = c⁶ |

**结论(可从算子公式直接推出,不依赖任何实测数据)**:
- `L` 对原始 `Ret` 的尺度是 **6 次齐次**:把 `Ret` 整体放大 c 倍,`L` 精确放大 c⁶ 倍。
- `L` 恒 **非负**(或 NaN):`J`、`K` 都是"平方之后再取滚动最大值",不可能为负;`K≥0` 再喂给 `pow_1_5`,
  两个分支(保号 / 不保号)在 x≥0 处本来就给同一个结果,所以**不会出现 `02_operators.md` 里说的"负数输入
  给 NaN"的坑**——这条链路结构上保证了 `pow_1_5` 的输入永远落在"两分支一致"的安全区。
- 唯一可正可负的中间节点是 `A、B、C、D、E、I`;唯一恒非负的是 `F、G、H、J、K、L`。**这条因子原始面板上的
  所有数值都 ≥ 0**(在 `study.sh digest` 的"分位超额"等诊断里,区分股票的只是"非负幅度"的大小,不是方向——
  方向是外部加的 `sign=-1`)。这一点和它"没有通过任何 `abs_` 算子"形成对照:树里没有一次显式调用 `abs_`,
  非负性完全是"平方 + 取最大值"叠加出来的副产品。

## 3. 恒等 / 近似恒等节点:`C → D` 这一步

`C = sub(B, -5) = B + 5`(`-5` 是 `create_like` 铺出来的、对全部股票全部日期都一样的常量,见 `02_operators.md`)。
紧接着 `D = cs_demean(C)`。把 `cs_demean` 的定义代入:

```
D = C − mean_s(C) = (B + 5) − mean_s(B + 5) = (B + 5) − (mean_s(B) + 5) = B − mean_s(B) = cs_demean(B)
```

(`mean_s` 是对当天横截面取均值;常数 5 对所有股票相同,挪进 `mean_s` 再提出来正好消掉。)

**结论:`D` 在数学上精确等于 `cs_demean(B)`,与 `sub` 里的常数选了 `-5` 还是别的任何数都无关**——这不是"影响很小
的近似",是代数上的恒等式,可以直接从 `cs_demean` 的线性性质推出,不需要跑数据验证。换句话说,`sub(·, -5)` 这个
节点在**当前位置**(紧跟着 `cs_demean`)对最终输出没有任何贡献;它要么是挖掘搜索过程中留下的"冗余参数"
(常见于自动挖掘:常数在被截面去均值"冲走"之前,看起来像是在调整阈值),要么在别的候选结构里(比如把这一步的
`cs_demean` 换掉)才会重新起作用。**这是本研究目前找到的唯一一处精确恒等**——树里没有任何窗口为 1 的滚动算子
(四个 `ts_max` 的窗口分别是 5、30、20、30,全部 > 1),没有发现其它恒等或近似恒等的节点。

## 4. 累计回看天数:82 天(复核工具的数字,并给出每一步的明细)

逐层倒推"要让根节点 `L` 在第 t 天有效,需要 `Ret` 往前多少个交易日的数据":

```
K(t) 需要 J 在 [t-29, t]            (ts_max 窗口 30 → 29 天前)
J 是逐元素,需要 I 在同样的 [t-29, t]
I 是横截面(同一天),需要 H 在同样的 [t-29, t]
H 是逐元素,需要 G 在同样的 [t-29, t]
G(s) 需要 F 在 [s-19, s] → 对 s ∈ [t-29,t],并集是 F 在 [t-48, t]          (29+19 = 48)
F 是逐元素,需要 E 在同样的 [t-48, t]
E(s) 需要 D 在 [s-29, s] → 对 s ∈ [t-48,t],并集是 D 在 [t-77, t]          (48+29 = 77)
D 是横截面(同一天),需要 C 在同样的 [t-77, t]
C 是逐元素,需要 B 在同样的 [t-77, t]
B(s) 需要 A 在 [s-4, s] → 对 s ∈ [t-77,t],并集是 A 在 [t-81, t]           (77+4 = 81)
A(u) 只需要第 u 天**当天**的分钟数据,不额外占用交易日轴的回看
```

所以 `L(t)` 总共需要 `Ret` 在 `[t-81, t]` 的 82 个交易日(= 81 天历史 + 当天)。核对:四层 `ts_max` 的窗口是
5、30、20、30,累计回看 = Σ(d-1) + 1 = (4+29+19+29) + 1 = 81 + 1 = **82**,和 `decompose` 自己报的数字一致。
**这远大于树里任何单个窗口(最大 30)**——因为四层 `ts_max` 是**串联**的(每一层的输出都是下一层的输入),
不是四个独立的、各自 30 天的并行分支。

**配置里的 `warmup: 60` 不够覆盖这 82 天**,而且 `S0_baseline.json` 的 `view.warmup_rows` 实测是 **0**
(不是 60,也不是别的正数)——`view.first` 正好等于 `train` 的第一天(`20180102`),说明这次 run 实际没有在
`train` 之前额外加载任何预热交易日。最可能的原因是数据源本身从 `20180102` 开始、没有更早的历史可用
(本次没有去核实数据源的起始日期,这是待确认的事,不是已验证的结论)。**影响**:如果确实没有更早历史,
`train` 最开头大约 82 个交易日(约 4 个月)里,`E`/`K` 两层 `ts_max(·,30)` 吃到的窗口会比标称的 30 天短
(左填充的 NaN 被 `nanmax` 跳过,相当于用更短的有效窗口,不会报错也不会变成 NaN,但这几天的"30 日最大值"
统计意义上没那么扎实)。这段时间占 `train`(973 个交易日)的比例不到 9%,`study.sh digest` 的逐年表和分位剖面
**没有看到专门剔除这前 82 天**的说明——这是一个待确认的边界问题,写在这里留给下一步决定要不要专门测一下
(比如把 `train` 的前 82 天单独摘出来看 `Lnet`/`Lshp` 是否和后面明显不同),本研究本身不下结论。
