- **成分漂移(最重要)**:因子里"水平"那一半的 rank IC 从 2019 年的 +0.029 降到 2023 年的 +0.001;带符号的主体 K 在 2023 年已经是负的(x3 §4)。
  train 的多头腿靠水平,valid 的多头腿靠离散。原式和极值版本因为两半都装着所以看起来稳,但如果离散那一半也开始退,没有第三样东西顶上。
- **空头腿拿不到,而且是已知的东西**:多空夏普的大头是"近 15 日封过涨停板的票后面跌"(x1 §7),A 股做不了空;对控制变量中性化后
  空头腿毛超额只剩 +11.0%(原式)/ +2.3%(`u_max60`)。任何按多空夏普给这条因子打的分都高估了它对纯多头的价值。
- **(修订)多头腿也有一大块是已知的东西**:对期限匹配的控制,推荐式 R² 0.45 / 0.46(原报告用九个短期限控制得到 0.19),残差多头腿毛超额 +4.3% / +3.9%、
  rank IC +0.0063 / +0.0038。实际持有的多头十分位里,约四成的毛超额是"避开近 60 日封过板 / 日频波动最高的票"(配置 +6.4% / +5.3%),
  这一块不需要这条因子:一个"近 60 日没有封板日"的过滤器就拿得到。剩下的六成(桶内选股 +8.1% / +8.1% 毛)扣掉成本是 +3% ~ +5%。
  valid 上它在控制变量之外的预测力已经很弱(哪怕只用原来九个控制,残差无成本多空夏普 +0.88)。
- **基准里的水分**:多头腿"超额"是相对"当天有信号有标签的全部票的等权"。这个基准里含着近期封板、复牌、短历史的票,它们年化跑输 15~40 个点。
  只是避开近 60 日的事件票就有 +7.7% / +5.2%(x3 §3);在这个干净池内部,`u_max60` 按实际的 hl=0 多头腿净超额是 **+3.3% / +5.5%**
  (全市场基准下 +11.3% / +10.1%;原报告这里写的 +5.7% / +8.8% 是在池子里另选 hl=10 的数):真正来自排序的,train 上约三成,valid 上约一半。留出段的 +7.4% 没有做过这个换算。
- **估计量特有**:信息只存在于"3 对"这个窗口(S2);5 对就掉一半,10 对归零。它依赖 A 股 1 分钱最小报价单位下分钟收益的离散结构。
  最小报价单位、涨跌停制度(科创板自 2019 年、创业板自 2020 年 8 月起涨跌幅 20%)或分钟数据的清洗方式一变,K 的分布就变。
  原式逐年的多空夏普 2019–2021 是 +5.75 / +3.55 / +2.10,我没有把这段下降和制度变化分开,这是一个没有检验的制度依赖。
- **内核细节依赖**:封板日 K≫0 靠的是相关系数分母里的 `+1e-9` 把"不动"变成恰好 0(探针 `constant_input_value`)。
  别的实现(返回 NaN)下事件日会直接消失 —— 而 r1 说明多头腿有三分之一要靠看得见封板日(去掉封板日后净超额 +11.3% / +10.1% → +6.8% / +6.7%),
  所以这个内核细节不只关系到拿不到的空头腿。`1000·Ret` 重算与原式 Spearman 0.982(x1 §3),目前不敏感,但换数据源要重测。
- **过拟合**:这是 GP 搜出来的式子。记忆窗口的邻域是平的(5~120),聚合器换五种都站得住;但"3 对 + 峰度 + 折在 0"这个组合没有邻域可言
  (峰度换一阶矩是另一个因子,折叠点移 0.3 多头腿就没了)。我把它读成"这个统计量碰巧把两种不正常分到了 0 的两侧",不是先验上该成立的东西。
- **容量**:预测力集中在小市值、高换手的票(条件 IC);valid 上大市值五分位里的多头十分位只剩 +2.7%(x3 §5)。多头腿自己偏低成交额(分位 0.33)。
- **成本敏感**:原式多头腿三分之二的毛超额被 15 bp 吃掉(单边日换手 10.4%)。`u_max60` 把换手降到 3.9%,对成本假设不那么敏感;
  但它的 dist 是 0.98、`u_max120` 是 0.96 —— 极值聚合在长窗口上会产生并列值,再长就要碰门槛。
- **(修订)半衰期口径**:这条因子的结论对"半衰期按什么选"很敏感。用户口径按多空夏普选,在原式上选到 hl=1(留出段多头腿净 −0.7%);按纯多头夏普选是 hl=5(+2.5%)。
  原报告的头条只和前者比,把"换半衰期就拿得到的 3.2 个点"也算成了升华。推荐式自己对这个选法不敏感(+7.4% / +7.0%),30 日版本敏感(+4.9% / +7.6%)。
- **(修订)选择偏差与多重比较**:`f_max60` 是在看了 x2、S3 两轮 train / valid 结果之后选的;train / valid 上它相对"原式 + hl=5"的优势是 +2.8(t 2.3)/ +0.3(t 0.2)。
  留出段上这个优势是 +5.0 个点(原式 hl=5 +2.5%,`f_max60` +7.4%)—— 这个数**就在最初那一次读取的 `final.json` 里**,原报告说"留出段没有可比的行"是错的。
  它的标准误按实测的日序列相关(0.85,train / valid)是 1.9 个点,按 0.6 是 3.0 个点;留出段上的相关没法量。

  从 10 个数里挑一对来比,显著性要再打折。valid 上同一个增量是 0,这条不该被留出段的一个 +5.0 盖过去。
