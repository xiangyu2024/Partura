### 2.6 「延长半衰期」这条路是**由口径约定关死的**(这一轮新查清的)

上一位主研的结论「没有延长半衰期这条免费改进」是对的,但理由要写准,否则下一个人会反复回来问:

1. **半衰期网格 {0,1,2,3,5,10,20} 是全局约定,不是这个因子的配置项。**
   `docs/study_playbook.md` §1 明文写「在 {0,1,2,3,5,10,20} 里选」(和用户的 `pick_single_factors.py` 一致、已复现过用户表 15 行);
   `grep halflives configs/*.yaml` **一个都搜不到** —— 没有任何配置覆盖它,S0 的 JSON 里记的就是这个默认网格。
   → **不要为了这条因子去扩网格**:扩了就和用户表、和别的因子不可比,等于换了选拔口径(§4 硬规矩 1;用户「口径不要改」)。
2. 在这个网格内,`hl_long` = `hl_ls` = **20** = 公布的那一行 → **「原式 + 多头最优半衰期」这条第一基准和原式是同一行**,
   这条因子**没有**「改进全部来自更长半衰期」那种免费收益可拿。
3. 两条腿在 hl 20(网格上界)**都还在改善**(多头腿 −10.6% → −6.9%,多空 +2.29 → +2.82)。
   **这不构成一个候选**,原因是:每翻一倍半衰期,多头腿的负值大致减半(−67 → −32 → −18.5 → −10.6 → −6.9),
   而 hl → ∞ 的极限是「每只股票自己历史上 −X 的均值」,它的**多头端 = 从没封过板的股票 = 中间六档**,
   而中间六档拿到的就是全市场收益(超额 ≈ 0,x1 C)。→ 极限是「≈ 0 的超额再扣掉成本」,**永远翻不成正的 alpha**。
   ⚠️ 这一条是**合理但未坐实**(从 sweep 形状 + 分档归属推的外推论证,没有量过 hl 40/60)。**不要写成已确立**;
   也不要为它单独花服务器运行 —— 即使量出来 hl 60 是 −4%,结论「多头腿为负」不变。

### 2.7 这一轮自己核对过的语义(`study.sh src`,服务器内核)

上一位研究员的 `02_operators.md` 全部对得上,我从源码再确认两条**整棵树都挂在上面**的:

- `day_quantile(x, q)` = `torch.nanquantile(x, q, dim=-1, keepdim=True)` —— **线性插值**。
  → 241 分钟全有值时 q=0.95 的位置 0.95×240 = **228.0**,恰好落在一个顺序统计量上(第 13 大),**不插值**;
  少一个分钟(240 个)位置变成 227.05 → 两个相邻顺序统计量 5%/95% 加权。所以「95% 分位数恰好为 0」的条件是**上涨分钟 ≤ 12 个**。
- `is_gt(x, value)` = `(x > value).int()` —— **严格不等号,输出 int(不是 bool、不是 NaN)**。
  → (a) 与分位数**并列**的分钟不进尾部(分钟收益并列极多,尾部集合可以远少于 12 个甚至空集);
  (b) NaN 比较为假 → 缺失分钟经 `select_where` 变成 0 而不是 NaN → 整棵树对「部分分钟缺失」**没有 NaN 传播**,只有整天缺失才输出 NaN。
  **这就是 cov = 1.00 的原因。**

## 3. 研究过程与逻辑(做了什么、按什么顺序、为什么这么走)

1. **先读源码,不信表达式的字面意思**(`02_operators.md`)。字面上这是「右尾 ES/VaR 减左尾 ES/VaR」,一个无量纲的尾部形状不对称量。
   读完源码发现**两个分母都是「分位数 + 1e-6」**,而 A 股分钟收益里有大量精确的 0 → 这个 `1e-6` 是整棵树的要害。
2. **用探针在服务器内核上量出「有三个取值区间」**(`03_decomposition.md`):上涨分钟 ≥ 13 个 → 常规(读数 1.0~3);
   上涨分钟 **≤ 12 个** → **塌缩**(读数 = 尾内均值 × 10⁶,一个 0.2% 的 tick 就给 2000)。整棵树在四个角上的读数:
   只有上涨稀少 → **+2039**;只有下跌稀少 → **−2039**;两边都稀少且幅度相同 → 0;两边都不稀少 → 0;全天不动 → 0。
3. **推出「截面两端一定是塌缩日」**,并且**塌缩区间里 X 不再无量纲**(齐次度从 0 变成 1)。
   再加上**口径是先 EMA 再排序**:hl 20 的 EMA 里一个 +2000 的塌缩日要 **20×log₂(2000/0.3) ≈ 250 个交易日**才衰减到常规量级以下
   → 实际交易的信号 ≈「过去一年里塌缩日的带符号、按幅度加权的累计」。这是**从公式推出的预期**,必须在真实数据上量 → 这就是 x1。
4. **先定假设表再跑实验**(`05_hypotheses.md` H1~H9),然后 S0 复现基线、x1 在真实数据上一次性解剖(A~G 七块)。
   x1 的设计很省:用 numpy 在本地算了九种构造的两本书(E 表),**不花服务器轮次**,只用来分辨。
5. **第 1 轮第一个主研**:核对全部数字 → 裁决 H1~H9 → 发现唯一还没回答的是「对纯多头用户,它相对已知家族有没有增量」
   → 新提 H10/H11/H12 → 不另起炉灶,工单 R1 就是把上一位写好却没跑过的 `x2_longonly.py` 跑出来。
6. **第 1 轮第二个主研(我)**:执行被额度打断、R1 没有结果卡 → 按规矩**不另开工单**。
   我做的是:(a) 对着 JSON 和内核源码**自己把关键数字和语义验一遍**(§2.1、§2.7);(b) 查清「延长半衰期」为什么关死(§2.6);

### 源码里和名字不一样的地方(下一个人最容易在这里重复花时间)

1. `day_quantile` 的插值与「上涨分钟 ≤ 12 个」这个阈值:见 §2.7。
2. `is_gt` / `is_lt` 严格不等号 + NaN 为假 + 输出 int:见 §2.7(两个后果:尾部可以是空集;没有 NaN 传播 → cov 1.00)。
3. **计数分母上的 `+1e-6` 是纯粹的除零保护**,不改变任何非空情形的值(空集时 0/1e-6 = 0)。
   **分位数分母上的 `+1e-6` 才是要害**:它是**带量纲**的常数(收益单位),比一个 tick 的收益(10⁻³ 量级)小三个数量级 → 分位数为 0 时比值放大 10⁶ 倍。
4. **右侧分母是 `q95 + 1e-6`(没有绝对值)**,左侧是 `|q05| + 1e-6`。q95 理论上可以为负(>229 个分钟在跌),实际极少。
5. **整棵树在服务器上关于 Ret 是精确的奇函数**(探针 `max|tree(r)+tree(−r)|` = 0.0)。
   ⚠️ **本机那份 torch 把 0.95×240 算成比 228 略小**,右尾会多收进分位数本身那一个分钟(13 对 12)。**本机不是事实来源,以服务器为准。**
6. `create_like(x, 0)` 用的是**整数 0 → int64**;`create_like(x, 1e-06)` 是 float32。`torch.where` 类型提升后 float32,数值没问题,只占内存。
7. **这棵树里没有任何日轴算子**:纯粹「当天 241 个分钟 → 一个数」,真实回看 **1 天**。全部时间结构来自口径里的因果 EMA(半衰期)。
8. **`Study.control(name)`**(`partura/study_tools.py:82`)先查配置的 `external_controls`,再查 `{**controls, **gates}` ——
   所以 `gates:` 里的东西(含 `known_*`、`g_max30`、`g_limitup30`)都能用 `st.control()` 直接取。

- ⚠️ 以上三条若要进 final,**必须先上服务器用真口径跑一遍**(x2 是 numpy 书,只能定性)。这就是工单 R2。

### 5.4 已排除的候选与原因

| 构造 | 为什么排除 |
|---|---|
| 只留常规日 / 先排序再 EMA / clip(±3) | 多空夏普转负或接近 0,多头腿比原式**更差**(−12.0%、−12.8%、−10.7%) |
| 只留右侧 R | 多头腿 −4.2% / −4.0%,仍为负;与原式秩相关 0.63(已经算换了因子)却没换来正的多头腿 |
| 只留左侧 L | 多头腿 −8.2% / −3.4%,方向与 R 同向,秩相关只有 0.19 |
| 多头 = \|EMA20(X)\| 最小(折叠) | train +2.4% 但 **valid −6.0%**(夏普 +0.34 / −0.88)→ 典型的 train 过拟 |
| 塌缩 0/1 标记、日线涨停标记(作为**独立**的书) | 多头腿是并列里按**股票代码顺序**取的 10%,没有意义且过不了 dist。只能用来分辨或做叠加(→ H10) |
| 延长半衰期 / 扩半衰期网格 | **这条路由口径约定关死**(§2.6):网格 {0,1,2,3,5,10,20} 是全局约定、不是配置项,扩了就和用户表不可比;而且 hl→∞ 的极限也翻不成正的 alpha |
| 加大 ε(把 1e-6 换成与收益同量级) | 等价于「去掉塌缩日」,已被第一行排除 |
