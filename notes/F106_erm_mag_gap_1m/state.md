1. **半衰期网格 {0,1,2,3,5,10,20} 是全局约定,不是这个因子的配置项。**
   `docs/study_playbook.md` §1 明文写「在 {0,1,2,3,5,10,20} 里选」;`grep halflives configs/*.yaml` **一个都搜不到**。
   → **不要为这条因子扩网格**:扩了就和用户表、和别的因子不可比,等于换了选拔口径。
2. 在这个网格内,`hl_long` = `hl_ls` = **20** = 公布的那一行 → **「原式 + 多头最优半衰期」这条第一基准和原式是同一行。**
3. 两条腿在 hl 20(网格上界)**都还在改善**。**这不构成一个候选**:每翻一倍半衰期负值大致减半,
   而 hl → ∞ 的极限是「每只股票自己历史上 −X 的均值」,它的**多头端 = 从没封过板的股票 = 中间六档**,
   而中间六档拿到的就是全市场收益(超额 ≈ 0)→ 极限是「≈ 0 的超额再扣成本」,**永远翻不成正的 alpha**。
   ⚠️ 这一条是**合理但未坐实**(外推论证,没有量过 hl 40/60)。**不要写成已确立**,也不要为它花服务器运行。

### 2.7 自己核对过的语义(`study.sh src` / `study.sh ops`,服务器内核)

- `day_quantile(x, q)` = `torch.nanquantile(x, q, dim=-1, keepdim=True)` —— **线性插值**。
  → 241 分钟全有值时 q=0.95 的位置 0.95×240 = **228.0**,恰好落在一个顺序统计量上(第 13 大),**不插值**;
  所以「95% 分位数恰好为 0」的条件是**上涨分钟 ≤ 12 个**。
- `is_gt(x, value)` = `(x > value).int()` —— **严格不等号,输出 int**。
  → (a) 与分位数**并列**的分钟不进尾部(尾部集合可以远少于 12 个甚至空集);
  (b) NaN 比较为假 → 缺失分钟经 `select_where` 变成 0 而不是 NaN → 整棵树对「部分分钟缺失」**没有 NaN 传播**。
  **这就是 cov = 1.00 的原因。**
- `cross_max` / `cross_mean` / `cross_sum` / `cross_delay` 的**搜索网格窗口是 [3, 5, 10, 15, 30, 60, 241]** —— **没有 20**。
  但 `cross_delay(day_last(Close), 1)` 在本配置的 `g_limitup30` 里实际跑通过(x2 用 `st.control("g_limitup30")` 成功求值),
  说明带字面量的通用调用不受这个网格限制;**保守起见 R2 用的是 15**。
- `greater` / `less` 带 `[boolean_output, trivial_boolean]` 标记 → 布尔输出。
  `g_limitup30` 的写法(与另一个布尔相乘、或外面乘一个 `create_like(·, 1.0)`)是已验证能跑的转数值办法。
- `cs_rank` 是 **nd/cs/unary axis S**(ND 面)。把 DT 面的日频量喂进去**有可能被引擎拒**(playbook「表达式语言的坑」)——
  R2 工单里已经写好了不用 `cs_rank` 的乘法兜底版。

### 2.9 排除性增量的量化天花板(**这一轮新算的,是整条研究解释力最强的一块**)

R1 的第 2 节给出四个格子的 ΔLnet。它们**可以用一个乘积预测出来**:
叠加收益 ≈(被标记票占已知家族多头十分位的比例)×(被标记票与未标记票的次日超额之差)。

| 格子(标记 = `blown day within 20d`) | share of 多头十分位 | 超额之差 | 乘积(预测) | **实测 ΔLnet** |
|---|---|---|---|---|
| known30 / train | 0.051 | 17.4 −(−22.1) = 39.5 | 2.0 | **+1.59** |
| known30 / valid | 0.022 | 27.7 −(−4.1) = 31.8 | 0.70 | **+0.52** |
| known9 / train | 0.041 | 19.4 −(−27.6) = 47.0 | 1.93 | **+1.60** |
| known9 / valid | 0.016 | 28.0 −(−7.6) = 35.6 | 0.57 | **+0.40** |

四格全部吻合到 **25% 以内**。valid 上两个因子同时变小(share 减半、超额之差从 ~40 收到 ~33)→ 增量掉到三分之一。

**而 share 之所以这么低,是因为已知家族本来就在躲这些票**:

| 标记 | 占全市场(train/valid) | 占 known30 多头十分位 | 占 known9 多头十分位 | 已知家族的相对持有频率 |
|---|---|---|---|---|
| blown day within 20d | 0.080 / 0.067 | 0.051 / 0.022 | 0.041 / 0.016 | **24% ~ 64%** |
| limit-up close within 20d | 0.197 / 0.154 | 0.073 / 0.034 | 0.054 / 0.023 | **15% ~ 37%** |

→ **「低 Amt 日内波动」这个条件已经把近期封板股筛掉了大半。不是 F106 的清单不准,是这张清单对这本书来说是多余的。**

## 3. 研究过程与逻辑(做了什么、按什么顺序、为什么这么走)

1. **先读源码,不信表达式的字面意思**(`02_operators.md`)。字面上这是「右尾 ES/VaR 减左尾 ES/VaR」,一个无量纲的尾部形状不对称量。
   读完源码发现**两个分母都是「分位数 + 1e-6」**,而 A 股分钟收益里有大量精确的 0 → 这个 `1e-6` 是整棵树的要害。
2. **用探针在服务器内核上量出「有三个取值区间」**(`03_decomposition.md`):上涨分钟 ≥ 13 个 → 常规(读数 1.0~3);
   上涨分钟 **≤ 12 个** → **塌缩**(读数 = 尾内均值 × 10⁶)。
3. **推出「截面两端一定是塌缩日」**,并且**塌缩区间里 X 不再无量纲**(齐次度从 0 变成 1)。

### 源码里和名字不一样的地方(下一个人最容易在这里重复花时间)

1. `day_quantile` 的插值与「上涨分钟 ≤ 12 个」这个阈值:见 §2.7。
2. `is_gt` / `is_lt` 严格不等号 + NaN 为假 + 输出 int:见 §2.7(尾部可以是空集;没有 NaN 传播 → cov 1.00)。
3. **计数分母上的 `+1e-6` 是纯粹的除零保护**,不改变任何非空情形的值。
   **分位数分母上的 `+1e-6` 才是要害**:它是**带量纲**的常数,比一个 tick 的收益(10⁻³ 量级)小三个数量级 → 分位数为 0 时放大 10⁶ 倍。
4. **右侧分母是 `q95 + 1e-6`(没有绝对值)**,左侧是 `|q05| + 1e-6`。
5. **整棵树在服务器上关于 Ret 是精确的奇函数**(探针 `max|tree(r)+tree(−r)|` = 0.0)。
   ⚠️ **本机那份 torch 把 0.95×240 算成比 228 略小**,右尾会多收一个分钟。**本机不是事实来源,以服务器为准。**
6. `create_like(x, 0)` 用的是**整数 0 → int64**;`create_like(x, 1e-06)` 是 float32。数值没问题,只占内存。
7. **这棵树里没有任何日轴算子**:纯粹「当天 241 个分钟 → 一个数」,真实回看 **1 天**。全部时间结构来自口径里的因果 EMA。
8. **`Study.control(name)`**(`partura/study_tools.py:82`)先查 `external_controls`,再查 `{**controls, **gates}` ——
   所以 `gates:` 里的东西(含 `known_*`、`g_max30`、`g_limitup30`)都能用 `st.control()` 直接取。
9. **x1 / x2 的书不是「本机 numpy 的书」**:它们通过 `study.sh exec` 在**服务器**上跑,面板由服务器引擎求值,
   书由 `st.books()` 算 —— x2 打出的 F106 基线行(train Lnet −6.9% / Lshp −2.15 / LS +2.82 / short +27.9%)
   与 `S0_baseline.json`(−6.91 / −2.15 / +2.82 / +27.85%)**逐项吻合**。
   所以它们的 Lnet 是可信的真口径数字;它们**缺的**是引擎级的 `cov`/`dist` 门槛和固定半衰期表,
   而不是「只能定性」。(上一版 state.md §8.1 的说法偏保守,这一轮更正。)
